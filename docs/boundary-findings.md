# CPU 研究：负载规律、恢复选点与剪枝

这组研究区分三类证据：百炼请求的事件模拟、用真实搬运与预热续算构造的物理对照、以及 llama-server 真实槽恢复。以 RTX 4060 Laptop、Qwen3.5-4B Q4_K_M、Vulkan 为校准环境。读数分别对应模拟请求的响应时间、物理对照的主机响应时间和真实恢复接口的时间；不能把它们作为同一端到端指标合并。

| 问题 | 目前有可靠证据的结论 |
| --- | --- |
| 预取额度何时释放，原 KV 能否接力？ | 放得下和能复用是两个条件。8,192-token 模拟中，服务开始或结束时释放额度，初始受阻候选均没有接力原活动来源；服务中途释放则有 **12 次**同源接力。典型案例等待 **100 ms** 后接力 **16 MiB**。是否能复用取决于释放时对象仍可用；100 ms 用于隔离机制。[释放与放置配对](evidence/boundary-reservation-placement.csv) · [接力实例](evidence/boundary-reservation-witness.csv) |
| 为什么损失传给其他请求？ | 一个选点改变了搬运、计算和可服务时刻，固定其他选点仍可产生损失。两槽反例中当前请求快 **69 ms**，此前未完成与后续请求累计慢 **569 ms**。看已到达请求能减轻部分退步；同样的已知历史下，是否保留未到达请求仍能改变最佳边界。[首次改选干预](evidence/first-change-losses.csv) · [两槽干预](evidence/boundary-batch-attribution.json) · [未来到达对照](evidence/boundary-queue-counterfactual.jsonl) · [队列目标](evidence/boundary-queue-objective-4k.csv) |
| 小优势能否信任？ | 固定 30 ms 阈值和跨成本复核都留下反例。独立 300 ms 留出组的最好规则中位绝对误差约 **58 ms**。最新真实服务留出里，短边界差的冷恢复缩短了同行响应，却延长了目标与整组完工。[闭环复核](evidence/boundary-robust-18.csv) · [留出验证](evidence/boundary-batch-join-300.csv) · [真实服务对照](gpu-boundary-restore.md#留出结果) |
| 结论可推广到哪里？ | 本机成本的 FIFO 回放跨 4,096／8,192 token 均未显示复杂选点有稳定额外收益；拓扑、释放和暂存对照也未改写结论。两槽下，32 倍 I/O 压力模拟有 **320 次**同快照排序翻转；物理搬运实验的 12 次翻转，用等长等待复现了 **11 次**，说明加入时机本身足以造成翻转。结论不外推至其他硬件、批次宽度和未覆盖的输入。[两槽模拟](evidence/boundary-batch-recovery.csv) · [物理搬运](evidence/boundary-physical-recovery-pairs.csv) · [等时等待](evidence/boundary-physical-wait-pairs.csv) |

在本机已有数据覆盖的配置中，保留静态基线。要把额外推演用于另一类负载，应先用该负载的重复配对验证三个量：队列目标的收益方向、计入决策耗时后的净收益、以及是否恶化尾部延迟。不要把独占时测出的候选差值直接当作并发运行时的收益。要推广到其他设备，应重新测量文件恢复、实际批处理进度与候选配对；现有证据不支持照搬 30 ms 或本机的速率系数。

## 负载分类与在线选点

百炼轨迹提供到达、长度和前缀哈希；候选、放置和预算由实验构造。先沿静态规则取快照，只标注改选能否让**可见请求完成时间之和少 5 ms 以上**；再闭环启用策略，将实测 Python 决策耗时注入模拟，报告窗口均值、P95 和退化。I/O 倍率用于施压，不作为算法输入。

| 两组 4K 窗口，每档 5,388 个竞争快照 | 常规成本 | 8 倍 I/O | 16 倍 I/O | 32 倍 I/O |
| --- | ---: | ---: | ---: | ---: |
| 存在改选机会 | 0 | 1 | 981 | 2,685 |
| 其中可由前方计算覆盖搬运 | 0 | 1 | 883 | 2,583 |

- **独立请求或搬运相对轻：** 串行成本往往够用。常规成本的 18–20 窗仅看队列深度，平均反而慢 0.53 ms。
- **前方计算可覆盖搬运：** 慢路径必须承载候选依赖。8K、仅 SSD 受压且到达间隔缩短时，`next4` 相对静态基线在全 RAM 组约慢 0.02 ms，在全 SSD 组的 16／32 倍压力下平均改善约 663／947 ms。将拆分放置的 SSD 从 16 倍放慢到 32 倍，有 20 对配置收益增加超过 1 ms，28 对下降超过 1 ms。收益并不随压力单调增加。
- **额度受阻、传输积压或可共享对象：** 决策依赖释放时间、剩余搬运和对象是否仍可复用；单增预算不一定让动态策略相对静态更有优势。只在低成本估计与静态排序不同时推演的排序门会漏选；允许近排序仍有代价，例如仅 SSD 16 倍组，相对静态的 P95 改善从完整推演的约 547 ms 降至约 492 ms。

## 实现附节：入口下界筛除

可见队列策略 `next4` 在状态门触发时，只改当前请求的边界，比较前方未完成、当前和其后至多四个已到达请求的完成时刻之和。前方保持已定边界，后方用静态边界。先完整评估静态候选，再按低成本估计排序其他候选；近似分数只控制顺序，**淘汰必须有下界证明**。

设时刻为 $t$，剩余 $m$ 个 FIFO 请求，第 $j$ 个请求在候选 $c$ 下的剩余独占计算为 $w_j(c)$。单槽计算不能互相覆盖，搬运、复制和争用也不能让完成提前，因此剩余完成时刻之和 $J(c)$ 满足：

$$
L(c)=mt+\sum_{j=1}^{m}(m-j+1)w_j(c)\le J(c).
$$

下界超过当前赢家时不创建候选回放；相等时只在原并列规则不会选它时跳过。其余候选完整推演，保留原收益门槛和回退规则。初版在推演中多次检查下界，特定共享串行路径下还可加队首必需搬运界；第二轮 `entry` 只在回放入口检查计算界。预测事件数指候选回放实际推进的事件，并非请求数或毫秒。

| 实验 | 结果 |
| --- | --- |
| 初轮 1,476 个配置 | 精确变体的零开销选点和逐项完成时刻均与完整推演一致。计算加搬运下界少推进 10%–54% 的事件，决策 CPU 降 3%–26%；有的组下界检查反而更贵。 |
| 入口筛除 612 个配置 | 零开销等价。五组决策 CPU 均值少 16%–31%，配对中位数节省 0.31–0.56 ms；其中一组重压条件下，只省记账（6.83 ms／窗）仍快于入口筛除（7.11 ms／窗）。 |
| 注入实际决策耗时 | 五组平均模拟响应与完整推演相差均小于 0.11 ms。受压时的较大响应收益来自选点；剪枝只降低 CPU 决策成本。 |

该下界依赖单槽 FIFO，不直接适用于请求计算可互相覆盖的连续批处理。同一窗口在不同配置中重复，不视为独立请求样本。下一步要用新留出和真实批处理检验在线信号，并区分选点与恢复路径各自的影响；见[双人分工](work-plan.md)。
