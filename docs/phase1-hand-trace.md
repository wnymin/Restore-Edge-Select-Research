# 第一阶段手算轨迹：两个请求争用预取额度

[预算与成本约定](phase1.md) · [轨迹、检查点和预期结果 JSON](../fixtures/phase1-hand-trace.json)

| 请求 | 到达时刻（ms） | 输入 | 候选边界（token） |
| --- | ---: | --- | --- |
| A | 0 | 3,456 个 token ID 10 | 0 |
| B | 1 | 1,152 个 token ID 20 | 0、576、1,152 |
| C | 1 | 1,152 个 token ID 30 | 0、576、1,152 |

A 从头计算，占用计算资源至 30 ms。B、C 同时到达并进入预取窗口，各选一次边界；同到达时间按轨迹顺序，B 排在 C 前。重复 token ID 是输入的紧凑写法，B 和 C 的前缀互不相同。

| B 的边界 | RAM 中的 KV（每块 18 MiB） | SSD 中的循环检查点（每份 49.125 MiB） | 合计 |
| ---: | --- | --- | ---: |
| 0 | 无 | 无 | 0 |
| 576 | `B.kv1`：token 1–576 | `B.state1`：处理完 token 576 | 67.125 MiB |
| 1,152 | `B.kv1`、`B.kv2`：token 1–1,152 | `B.state2`：处理完 token 1,152 | 85.125 MiB |

C 有一组同样形状、标识独立的对象。初始显存中没有可复用缓存。每个非零边界只读取对应的一份循环检查点，包含卷积历史。缺失对象整批预留；传输按 KV 块顺序、最后循环检查点的顺序逐对象提交到同一条串行队列。已传完的对象到交接时才释放预取额度。检查点独占，可原位接管；重算结果不写回。

验收采用假设的 80 GiB 设备、12 GiB 模型及固定开销、256 MiB 执行预算（其中工作区 32 MiB）。最大执行占用来自 A：108 MiB KV + 49.125 MiB 循环状态 + 32 MiB 工作区 = 189.125 MiB。对象按有效载荷计费，无额外对齐开销。

**手算成本**：RAM 每个 KV 块 1 ms，SSD 每个检查点 3 ms，启动延迟取 0。短、长边界分别需 4、5 ms 传输。后缀重算沿用已定公式，取 `a = 8063/1327104 ms/token`、`b = 1/663552 ms/配对`。A 从头算需 30 ms；B、C 从 0、576、1,152 开始分别需 8、4.25、0 ms。逐请求独立成本为 8、8.25、5 ms，因此 B、C 都选长边界。上述参数只用于验收。

| 预取额度 | B / C 边界 | 传输时间线（ms） | A / B / C 完成时刻（ms） |
| ---: | --- | --- | --- |
| 0 MiB | 长 / 长 | B 按需 30–35；C 按需 35–40 | 30 / 35 / 40 |
| 128 MiB | 长 / 长 | B 预取 1–6；C 到队首按需 30–35 | 30 / 30 / 35 |
| 160 MiB | 长 / 长 | B 预取 1–6；C 到队首按需 30–35 | 30 / 30 / 35 |
| 160 MiB | 长 / 短 | B 预取 1–6；C 预取 6–10；两者都在 1 ms 预留 | 30 / 30 / 34.25 |
| 192 MiB | 长 / 长 | B 预取 1–6；C 预取 6–11 | 30 / 30 / 30 |

160 MiB 下，两个长候选合计 170.25 MiB，即使 B 在 6 ms 已传完，C 也不能用 B 占用的额度，直到 30 ms 交接。长短组合只需 152.25 MiB，C 的加载被 A 的计算覆盖，30 ms 开始重算。平均到达至预填充完成时间由 **31.000 ms** 降至 **30.750 ms**。192 MiB 下两个长候选都能预留，B、C 可在 30 ms 依次交接并完成。

JSON 给出四档预算下全部 9 种边界组合、预留时刻、峰值及离线最优。全重算在任一档均于 30、38、46 ms 完成。还可核对 **128 MiB 的短 / 长**：B 于 30 ms 交接并开始重算，C 随即预取；B 于 34.25 ms 完成后，C 接管在途传输，35 ms 完成，无重复加载。
