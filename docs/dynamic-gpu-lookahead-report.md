# 有限暂存容量下的前缀恢复边界选择

本文统一维护研究结论与后续方向。先读第 1–2 节了解结论和模型，第 4–5 节判断结论强度和下一步；第 3、6、7 节及[证据附录](dynamic-gpu-lookahead-appendices.md)供追查推导与复现。[实验索引](experiment-index.md)记录公共输入、实验条件和命令，两处均不另行维护研究计划。

## 1. 核心结论

文中按文件名引用的 CPU 前瞻审计 CSV 见[数据归档与复现说明](experiment-index.md#cpu-前瞻审计数据归档)。

**恢复边界选择的核心，是比较候选造成的未来状态差及其对各请求的影响。** 前缀长度、单次加载成本或目标请求自身收益，都不足以普遍决定整体最优。研究已经从“加几个工程特征能否改善选点”，推进到“哪些状态不可省、哪些共同工作可抵消、需要检查多少临界情景、单次保证如何组合”的算法问题。

| 算法问题 | 当前结论 | 主要依据与范围 |
| --- | --- | --- |
| 何时局部最优等于整体最优？ | 无耦合条件下可以；存在竞争时须比较目标收益与其他请求净代价。容量只有通过改变关键路径才影响排序。 | 第 3.0–3.1 节：条件推导、最小反例及 GPU 机制配对；没有生产发生频率结论。 |
| 哪些信息不能省？ | 对象并集、预留与共享身份、在途占道及对象加载顺序都可能决定排序。相同汇总字节和分层成本仍可要求相反动作。 | 第 3.4、3.12、3.18 节：状态等价条件与信息不足反例；最小充分状态尚未确定。 |
| 能否少算而保持完整前瞻结果？ | 可以用工作量支配、后缀状态等价和临界情景证书；不同子域需要不同证书。 | 第 3.2–3.8、3.14–3.20 节：立即加载的两请求子域每对至多 9 个情景，限定三请求每对至多 31 个情景，特定按需恢复比较至多 $9(m+1)$ 个区域。条件不能交叉套用。 |
| 怎样处理成本和状态误差？ | 对同一情景比较反事实差，保留事件相等面、单侧极限与参数相关性；仅检查四角不具有一般充分性。未来成本误差不能代替活动残余误差。 | 第 3.12–3.14、3.21–3.23 节：精确分区、原执行器核对与反例；真实误差域覆盖尚未建立。 |
| 容量准入能否和时间求值分开？ | 固定计划下，开始或完成释放可以先按对象并集计算准入阶段；定时释放还需判断它是否严格早于运行完成。跨容量显式枚举可能出现指数多种初始模式。 | 第 3.25–3.27 节：掩码构造、共享对象与释放配对；准入阶段不决定就绪时间和候选排序。 |
| 单次安全能否变成多步安全？ | 分别相对旧计划安全，合并仍可失败；相对更新计划认证，或在实际状态上相对同一基线延续价值认证，才有已证明的组合条件。 | 第 3.9–3.12 节：望远镜分解及反例。固定已知批次、参照一致性和状态有效性是关键条件。 |
| 整体改善能否同时保护个体？ | 二者可能冲突。逐请求预算必须显式约束；最坏遗憾最小不自动满足零退化。 | 第 3.7–3.8、3.15 节：多动作预算前沿及后继消费窗口反例；不直接推出 P95、SLO 或吞吐收益。 |

**比较基线。** 已覆盖的常规成本与负载条件下，保留逐请求 `local-cost` 作为默认。手算轨迹在 160 MiB 下，离线联合选点把平均响应从 31.00 ms 降到 30.75 ms；搬运受压时，先用离线最优测量改善空间，再问前瞻能拿到多少。见[策略与离线最优对照](trace-oracle.md)。

**GPU 的作用是验证机制与约束成本假设。** 真实双槽证明同一边界对可随同行状态改变排序；CUDA 对照证明容量、释放与消费窗口可以共同改变整体排序。真实模型暂存对照未出现稳定的容量排序翻转，动态策略在真实连续服务中普遍更快仍无充分证据。本组继续承担与上述算法判断直接相关的 GPU 验证，不把接口改造作为研究贡献。

**证明、数值审计和硬件观测分别报告。** 解析复杂度来自推导，不能由随机样本替代；构造例证明可能性，不能估计普遍频率；减少模拟事件不等于净决策加速；保持固定后继的完整前瞻动作不等于全序列联合最优。第 4 节逐项列明强度，第 5 节给出唯一维护的后续顺序。

## 2. 问题与适用模型

课程原题关注 KV Cache 分级存储与替换。本项目研究其中的恢复决策：已有缓存放置给定时，如何选检查点以缩短响应？没有比较 FIFO、LRU 等淘汰算法；本文的 FIFO 是请求计算顺序。Qwen3.5-4B 的模拟配置中，注意力 KV 为 32 KiB/token，非零恢复边界还需要约 49.125 MiB 的循环及卷积状态。较晚检查点不能直接截成较早检查点，因此省下的 KV 并不必然意味着省下一次完整检查点读取。详见[模型规格与口径](phase1.md)。

给定缓存放置与可精确恢复的检查点，算法选择当前请求的恢复边界。边界同时决定所需对象、暂存占用、加载和后缀续算。比较同一快照下的候选，固定后继边界及执行规则，目标为已见请求响应时间之和。由于到达时刻不因候选而变，比较完成时间之和等价。

主要定理和事件审计采用 Phase 1 子模型：固定 FIFO 计算顺序、单一不可抢占搬运通道、搬运可与计算重叠、计算开始时交接预取额度、无追加持久驻留、无计算与搬运相互减速；被比较的可见请求均已到达。对象可以大小不同、存在共享；不联合优化缓存布点、淘汰、后继选点或请求调度。各命题的附加条件在下文单独说明。

这个模型适合隔离容量、预取与边界之间的因果关系。固定语义下的证明可迁移到满足相同条件的系统；具体数值、证书覆盖率和事件节省比例不能直接迁移。双槽真实服务与设备对照用于验证机制和成本范围，不能替代此模型的假设，也不能直接验证其全部定理。

## 3. 已经回答的问题

以下给出支撑各结论的推导、证据及适用范围。

### 3.0 GPU 调研确认了哪些机制，哪些算法主张仍无证据

双槽指同一服务中的两个请求槽，可并存、恢复各自状态并接受调度；不保证两个计算任务独立并行。恢复、计算与合批的实际重叠由执行器决定。因此双槽适合作为请求间影响的观测环境，不能直接等同于 Phase 1 的独立计算与搬运模型。

| 已有结果 | 对算法的含义 | 结论边界与依据 |
| --- | --- | --- |
| 同机单跑，512→1,536 token 深恢复使目标快 283.55 ms；1,024→1,152 却慢 84.72 ms | 前缀更长不保证恢复更快，应比较暴露的加载成本与省下的续算 | 两个边界配对证明两种方向存在，不能推出通用 token 阈值。[真实恢复](gpu-boundary-restore.md) |
| 真实双槽窄边界对，同行预填充早期与末段的深减浅中位差分别为 −13.03、+62.47 ms | 静态候选成本可能不足，同一候选对的排序依赖运行状态 | 阶段标签尚未证明足以稳定改善在线决策或保护同行。[阶段留出](dynamic-gpu-phase-study.md) |
| CUDA 多对象留出中，紧额度独立对象组目标快约 2 ms，完成时刻和却慢 1.82 ms；共享或放宽额度后翻转消失 | 联合对象并集与其他请求的净代价都必须考虑 | 每工况 12 对，指标为设备完成时刻和；缓冲别名不是新模型语义验证。[联合暂存](dynamic-gpu-joint-staging.md) |

这些结果支持把算法问题收敛为：候选改变哪些未来状态，这些变化通过什么关键路径影响各请求，以及在信息或成本不确定时能认证到什么程度。它们尚不支持“动态策略在真实连续服务中普遍更快”。本组承担 GPU 验证；CPU 推导用于解释实测机制和构造可复核的算法命题，分工仍以[研究计划](work-plan.md)为准。

### 3.1 局部收益和整体收益为何不同

在最早执行时刻 $E$ 不随候选改变时，候选 $b$ 的完成时刻为 $\max(E,R_b)+C_b$。其中 $R_b$ 是包含准入及搬运等待的状态就绪时刻，$C_b$ 是续算时间。深边界优于浅边界当且仅当省下的续算超过额外暴露的恢复等待。该条件解释了为什么较长前缀既可能更快，也可能更慢。

进一步，令目标改选节省的响应时间为 $G$，其他请求增加的响应时间之和为 $D$。整体改善当且仅当 $G>D$。容量、共享与重叠通过改变 $D$ 或 $R_b$ 影响排序。两两对象能够共存，不保证整个依赖并集能够共存；完全不搬运的后继也会继承前序时差。

已有无耦合条件给出了逐请求关键路径贪心最优的情形；相同在线快照、不同未来到达可要求相反动作的构造，则说明未知未来造成的信息缺失不能靠推演已见队列消除。[前期条件与在线下界](dynamic-gpu-selection-bounds.md) · [联合占用与传递反例](dynamic-gpu-lookahead-appendices.md#round-joint-error)

### 3.2 看哪些请求，比固定看几个请求更关键

直接竞争者之外，还必须考虑共同占用和时差传递。固定四个后继可以在夹具中有效，但没有一般安全性。对已经证明两候选共用就绪时间、续算时间和服务顺序，且无其他候选相关状态的 FIFO 后缀，设已完成部分分数差为 $g$、最后一项完成时差为 $d$、剩余项数为 $m$，则：

$$
g+\min(0,md)\le G\le g+\max(0,md).
$$

该区间不跨零即可停止；其充分条件不能省去。在受控留出中，名义停止平均从查看 21.03 项降至 3.12 项，并保持完整名义推演动作。后续 Phase 1 精确截点在 160 组配置、2,898 次截点候选推演中核对了被省常数，保持完整前瞻的选点与完成时刻。

公开新留出的 64 组配置中，只看目标与完整前瞻本身没有改选差异。多看在构造竞争例中有价值，现有公开窗口没有证明这种收益经常出现。加入计时后，短请求中增加前瞻仍可能得不偿失。[停止界](dynamic-gpu-lookahead-appendices.md#round-bounds) · [截点与公开留出](dynamic-gpu-lookahead-appendices.md#round-phase1-score)

### 3.3 工作量界可以安全排除一部分完整推演

对每个候选构造完成时间和区间 $[L_b,U_b]$：下界支付必然的计算与复制，上界再支付可能暴露的搬运及复制。若 $U_a<\min_{b\ne a}L_b$，候选 $a$ 严格支配其余候选；有精确候选分数后，也可排除下界已经更差的候选。严格比较保留平局规则。

**搬运影响的权重必须按最早可能阻塞的位置计算，不能只按对象所属请求计算。** 后继的小对象可提前预取，在不可抢占通道上挡住前序的大对象按需加载。合成反例中，按归属位置计算的朴素上界低于真值约 841.94 ms；考虑最早阻塞位置的窗口上界仍有效。

1,304 组配置、38,768 次候选区间审计没有越界或误选。公开校准／留出减少事件 92.3%／69.3%，随机压力集仅 11.6%／13.0%；全部困难翻转见证仍未决。说明绝对工作量界适合排除明显劣势候选，临界竞争需要更紧的候选差值分析。两种上界的审计计数包含配对核对，不能视为独立样本。[证明、反例与数据](dynamic-gpu-lookahead-appendices.md#round-workload-bounds)

### 3.4 共同工作可抵消的对象，是未来状态相同的轨迹

两候选拥有相同后续请求及边界，并不足以消去共同后缀。在同一交接阶段，还需要未来相关状态在时间平移后一致：下一请求位置、各请求预留的对象身份、未来仍会使用的就绪对象，以及在途对象身份和剩余占道时间。无关就绪对象可以丢弃；无关在途对象的身份可以丢弃，占道时间仍须保留。

满足条件时，后续每项完成时刻都只平移同一个 $\Delta$。已完成部分分数差为 $g_k$，剩余 $n-k$ 项，则精确分数差为：

$$
G=g_k+(n-k)\Delta.
$$

这把剩余问题精确压缩为一个时间差，并允许交接时仍有预留。它是充分条件，尚未证明是必要条件或最小状态表示。

不检查状态、直接传播目标完成时差的错误规则，在见证集 144 次决策中选错 16 次；公开校准与留出却没有暴露该错误。精确状态合并在 1,304 组配置、38,768 次候选推演中保持完整结果，公开留出事件减少 26.7%，两批随机集仅约 2.8%。主回放没有出现带在途搬运的实际后缀复用；该部分目前由证明和状态级对照支撑。[等价命题与审计](dynamic-gpu-lookahead-appendices.md#round-coalescence)

### 3.5 时间扰动只能在事件分支内连续分析

只改变一个在途搬运剩余时间 $r$，在事件先后关系固定的区间内，完成时间和为仿射函数 $S(r)=a+br$；有 $J$ 个未完成请求时，斜率属于 $0,1,\ldots,J$。两候选收益差同样分段仿射，因此可以在各分支检查端点、单点优先级和收益零点。

跨分支却可能跳变。三请求最小反例得到：

$$
S(r)=\begin{cases}
42,&0<r\le6,\\
30+2r,&6<r<10,\\
22+2r,&r\ge10.
\end{cases}
$$

当 $r$ 从左趋近 10，$S(r)$ 趋近 50；恰好等于 10 时，需求优先改变搬运顺序，$S(10)=42$。较慢的预取因此可能改善整体响应。全局单调性及按 $J|\Delta r|$ 控制变化的全局 Lipschitz 假设均不成立，只检查整个参数区间的两端也不安全。

扩展合成集得到 2,571 个快照、24,407 个分段和 56,527 个核对点，发现 25 个受影响快照、122 个相邻分段边界跳变，均为负跳变，最大绝对值 48；这只是观测，不能推出所有跳变必然向下。边界两侧可能分别计数，122 不是不同阈值数。[分段推导与见证](dynamic-gpu-lookahead-appendices.md#round-residual)

### 3.6 请求关系缺失与成本误差，是两种不同的信息不足

漏掉相关后继时，提高搬运精度无法普遍纠正选点；相关请求已看全时，继续展开队列也无法消除耗时不确定性。共用同一个成本倍率的两条反事实应成对分析，分别取独立最坏值会丢失相关性。固定依赖／服务顺序的模型中，共同误差精确界在 ±50% 留出切片认证 266/600 个用例，独立区间为 215/600，但精确界的本机计算更贵，并未取得最高净收益。

GPU 临界留出 56 对中，点估计判对 49 对；经验范围排除零的 16 对均正确。它验证临界耗时值得区分，不把经验范围提升为未来保证。最新跳变反例还说明，早期固定顺序误差分析不能直接推广到顺序会变化的事件模型。[信息价值](dynamic-gpu-lookahead-appendices.md#round-value) · [共同误差与 GPU 留出](dynamic-gpu-lookahead-appendices.md#round-joint-error)

### 3.7 同一不确定情景下直接比较候选，能得到更紧的判断

设共同参数为 $x\in X$，候选完成时间和为 $J_a(x)$。两候选应比较同一 $x$ 下的差值：

$$
D_{ab}=\sup_{x\in X}[J_a(x)-J_b(x)]
\le \sup_{x\in X}J_a(x)-\inf_{x\in X}J_b(x).
$$

右侧允许两条反事实采用不同的最坏情景，会丢失共同误差的抵消。构造两条轨迹事件阈值的共同划分，分别保留开区间、阈值单点和单侧极限，即可精确求左侧。两批合计 622 个交接反事实对中，共同差认证 507 对，精确单臂独立界认证 85 对，工作量界认证 14 对；16,777 个原模拟器核对点一致。这里认证指在整个参数域内确定严格排序，不表示在线收益发生率。

有限动作的最坏遗憾也可由候选对差值组合：

$$
R_a=\sup_{x\in X}\left[J_a(x)-\min_bJ_b(x)\right]
=\max_b D_{ab}.
$$

首次决策扩展保留了运行中计算及活动依赖，每个候选的符号轨迹只构建一次，再复用到多动作比较。在途残余和未来 SSD 倍率分别是一维子域；前者改变已有搬运的剩余时间，后者只改变快照后新发起的 SSD 服务。两项实验不能合称为独立多参数联合认证。[候选差推导](dynamic-gpu-lookahead-appendices.md#round-candidate-difference) · [首次决策审计](dynamic-gpu-lookahead-appendices.md#round-first-decision)

### 3.8 总分稳健、个体安全和平局保真是不同要求

相对默认动作 $f$，定义候选的最坏个体退化为

$$
H_a=\max_j\sup_{x\in X}[C_j(a,x)-C_j(f,x)].
$$

在 $H_a\le\varepsilon$ 的安全集合中最小化 $(R_a,\tau_a)$，其中 $\tau_a$ 为固定平局优先级。最小总分遗憾不保证个体零退化：未来 SSD 倍率的 1,944 次首次决策中，零个体预算改变了 64 次纯稳健动作。相反，参数内存在赢家翻转，也不必使 minimax regret 动作偏离名义最优；该实验仅有 2 次纯稳健动作异于名义选择。稳健性与个体保护不能相互替代。

令激活预算 $h_a=\max(0,H_a)$。安全集合仅在 $\varepsilon=h_a$ 时变化，因此已有 $(h_a,R_a,\tau_a)$ 后，按激活预算排序扫描即可得到完整预算前沿。若要删除候选 $a$ 且保持动作不变，充分条件为存在 $b$ 满足

$$
h_b\le h_a,\qquad (R_b,\tau_b)<_{\mathrm{lex}}(R_a,\tau_a).
$$

仅有 $h_b\le h_a$、$R_b\le R_a$ 的指标支配只保最优值，可能改变平局动作。三动作解析反例已区分这两种保证。预算前沿在本轮 5,832 个已求值候选上核对通过；删除的是指标上的冗余候选，未节省先前的符号求值成本。[完整前沿与平局反例](dynamic-gpu-lookahead-appendices.md#round-ssd-frontier)

### 3.9 单次安全如何组合：参照必须随方案更新

设完整方案依次为 $P^0,P^1,\ldots,P^K$，评价同一请求集合与同一全局情景 $x\in X$。若每步针对**实际上一方案**认证所有请求的差值：

$$
u_{k,j}=\sup_{x\in X}[C_j(P^k,x)-C_j(P^{k-1},x)],
$$

则逐情景望远镜求和得到

$$
C_j(P^K,x)-C_j(P^0,x)
\le\sum_{k=1}^K u_{k,j}.
$$

所以每步零退化可组合；每步容许 $\varepsilon$ 的一般结论是最多 $K\varepsilon$，不能仍称全程 $\varepsilon$。若要全程预算 $B_j$，必须控制每个请求的累计账本。总分上确界应另行认证，逐请求上确界之和一般更松。此命题不依赖具体缓存框架，但要求请求范围、情景语义和参照方案一致。

各次独立改选都对旧方案 $P^0$ 安全，却不能推出其坐标合并安全：它们的占用和时序会共同改变，单次证书评价的后继已不再是最终执行的后继。归档四请求反例中，未来 SSD 倍率 $x=5/4$，三次独立改选均在整个 $[3/4,5/4]$ 内不使任何请求退化；合并后却出现下表。表内为各请求相对基线的完成时间差，负数表示改善。

上述完整策略替换证明可以以前一策略将真正执行的后续行为为参照，但这不是唯一可组合方式。下一节给出更易检查的基线延续价值条件：即使以后继续改选，只要每步相对同一状态一致的基线延续认证，也能形成另一条望远镜链。因此，“评分后缀不同于最终后缀”本身不足以否定安全，关键是是否存在一致的延续价值或已计费的参照变化。

### 3.10 在线组合的另一条路径：同一基线的延续价值

此前把“必须知道先前策略真正的未来改选”写成在线组合的前置条件，范围过窄。固定基线的 rollout 也可保证安全：每次执行当前动作后，评分时假定后续回到同一基线；实际到下一状态后可以再次改选，无需第一次就预测这些改选。

对同一有限请求集合、同一真实全局情景 $x$，令 $h_k$ 为第 $k$ 次决策的实际历史，$\beta$ 为固定、可执行且能从这些历史继续的基线策略。令 $V_j^\beta(h_k,x)$ 为从该历史按基线继续时请求 $j$ 的绝对完成时刻；已经完成的请求使用其实际完成时刻。当前选择 $a_k$，其动作后回基线的值为 $Q_j^\beta(h_k,a_k,x)$。若下一决策发生前按已承诺动作执行，状态中保留全部不可撤销的预取、运行与引用，则

$$
Q_j^\beta(h_k,a_k,x)=V_j^\beta(h_{k+1},x).
$$

若逐步证书保证 $Q_j^\beta(h_k,a_k,x)-V_j^\beta(h_k,x)\le u_{k,j}$，则沿实际历史求和得到

$$
C_j^{\mathrm{rollout}}(x)-V_j^\beta(h_0,x)
\le\sum_k u_{k,j}.
$$

这是逐请求结论，标量总分另可同样证明。它不要求真实策略最后回到基线，而要求每一步的两端都由同一基线的延续价值衔接。有限终止、完整受影响请求集和包含真实情景的证书域是前提；决策开销也须进入状态转移或差值。未知未来到达未受约束时，不能从有限请求集的证书推出全局保证。

参照漂移会多出桥接项。若下一步将基线由 $\beta_k$ 换成 $\beta_{k+1}$，定义

$$
b_{k,j}=V_j^{\beta_{k+1}}(h_{k+1},x)-V_j^{\beta_k}(h_{k+1},x).
$$

最终差值需累加局部动作差和所有 $b_{k,j}$。忽略这个项会把“换成更差参照”误当作安全。两步抽象决策树即可说明：初始基线终值为 1，改选到状态 A 后原基线延续终值为 0，第一步差为 $-1$；到 A 后改用终值 100 的参照，再选终值 99 的动作，第二步仍报差 $-1$，最终却相对初始基线差 $98=-1+100-1$。它是标量决策树反例，不冒充 KV 事件模型见证；保留原基线 0 时，第二步会被拒绝。

受控 KV 模型审计从每个批次的实际交接快照推进：已运行或已准入的请求不可改选，其余队首可选择合法边界，后继按冻结的随机合法基线继续。每次在 $[3/4,5/4]$ 的未来 SSD 倍率域内作全分支认证；已发出的搬运完成时刻保持实际快照值。真实全局倍率分别取 $3/4,7/8,1,9/8,5/4$，只通过已执行后的状态影响下一次决策，不作为额外决策输入。

| 数据 | 批次 | 实际路径 | 认证决策 | 实际改选 | 延续价值衔接核对 | 参数轨迹核对点 | 个体变慢路径 | 总分变差路径 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: | ---: | ---: |
| 7740，零预算 | 1,000 | 5,000 | 8,718 | 4,704 | 15,000 | 78,762 | 0 | 0 |
| 7741，零预算 | 1,000 | 5,000 | 8,576 | 4,500 | 15,000 | 77,542 | 0 | 0 |
| 7740，单步预算 1 ms | 1,000 | 5,000 | 8,718 | 4,725 | 15,000 | 78,762 | 21 | 0 |

所有路径均核对最终逐请求差值等于沿实际历史的基线动作差值和，且不超过符号上界账本。正预算允许个体退化，总分另行非增认证。五个倍率是同一批次的相关参数路径，正预算也是配对切片，不能把 15,000 条路径视为独立负载。全域安全来自分支证书与推导，五点路径执行是状态衔接审计，不是全域证明的替代。

此算法在队首尚未准入时才允许改选，可能让原首次入窗时已承诺的深边界保持不变；它与原首次决策时机不同。已知批次、固定基线、零决策耗时、同一 FIFO 模型均为当前限制。本节未得到原首次入窗策略、一般未知到达、全局最优或低成本性能保证；原时机的一类受保护评分器另见第 3.11 节。

### 3.11 原首次入窗时机：固定后缀可以组合，但默认动作也须一致

上一节只在尚未准入的队首改选。本节保留原模拟器的首次入窗时机、预取与交接过程，仅以个体保护及最坏总分差改变评分。所有请求在零时刻到达，单通道速率恒定为 1，成本已知；未来新 SSD 服务的敏感性域仍为 $[3/4,5/4]$。各切片将 SSD 基础成本分别乘 $1/2,1,2$，这是已知配置变化，不是三条未知误差实现。实际执行位于每个配置的名义倍率 1。局部未来成本域的证书不等于整条策略在未知全局倍率下的全域验证，尤其不能省略已有活动阶段的误差。

该条件下，当前默认动作和后继串行规则均实现同一静态 local-cost 基线。对一次决策，保留已选的前缀边界、实际预留、就绪对象、在途服务和运行中计算；后继按该基线继续。对候选逐请求认证后，只允许满足个体预算且最坏总分差不为正的动作。下一决策即使发生在同一事件时刻，其基线延续也应等于上一动作评价的后缀；若期间有请求完成，补上已经完成的实际前缀再比较。

这构成第 3.10 节的势函数链，说明“评价时固定后缀，实际以后又改选”本身不破坏组合。真正需要保持的是基线在实际历史上的一致性，以及真实耗时属于所认证的情景域。该算法使用最坏总分差，不是原最小名义响应和规则或前文的最小最坏遗憾规则。

### 3.12 固定基线可消除参照项，但活动状态误差仍须单独认证

单位速率不是势函数组合定理的必要条件。对任意已知、正的恒定通道速率，只要基线策略能从每个实际历史一致延续，仍可应用第 3.10 节。当前采用初始静态 local-cost 边界表作为冻结基线：每次评价保留已提交的边界和实际资源状态，当前与后继均对同一张表比较。快照下另算的默认动作可以作为候选，但不能未认证地替换这条基线。该选择保证参照一致，不声称冻结基线本身最优。

即便完全消去参照漂移，评分快照与实际状态不同仍可使保证失效。设同一候选及基线在预测状态上的逐请求差为 $\widehat\delta_{k,j}$，在实际状态上的差为 $\delta_{k,j}$，定义成对模型缺项

$$
e_{k,j}=\delta_{k,j}-\widehat\delta_{k,j}.
$$

若预测状态上的全域证书为 $\widehat\delta_{k,j}\le u_{k,j}$，沿实际历史可得

$$
C_j^{\mathrm{policy}}-C_j^\beta
=\sum_k(\widehat\delta_{k,j}+e_{k,j})
\le\sum_k(u_{k,j}+e_{k,j}).
$$

若基线还变化，则再加第 3.10 节的桥接项。这个恒等式把参照不一致与状态预测误差分开；$e_{k,j}$ 是两个反事实误差之差，不能只用目标某条路径的预测误差代替。审计中的真实缺项为事后量，只能定位失败；若要据此作在线保证，必须事先给出覆盖真实状态的缺项上界，或直接在活动状态与未来成本的联合域内认证。

**两请求反例。** 前序请求从零时刻计算至 30 ms；目标请求可从头重算 8 ms，或预取一个完整 RAM 前缀，加载精确耗时 39 ms、后缀成本为零。额度足以预取，加载与前序计算重叠，FIFO 顺序及基线 $(0,0)$ 固定。只把前序总计算时间高估 25%，评分快照认为其结束于 37.5 ms；未来加载、续算和对象状态均准确。

| 评价 | 基线的目标完成时刻 | 加载前缀的目标完成时刻 | 加载减基线 |
| --- | ---: | ---: | ---: |
| 错误活动状态上的预测 | $37.5+8=45.5$ | $39$ | $-6.5$ |
| 实际执行 | $30+8=38$ | $39$ | $+1$ |

该改选通过预测状态的零个体退化认证，实际却使目标及总分各退化 1 ms。局部证书为 $-13/2$ ms，成对模型缺项为 $15/2$ ms，两者相加精确得到 1 ms。先前请求在两候选中都相同，不能用它的共同时间误差抵消目标关键路径的变化。

这个反例仅有 RAM 加载，未来服务成本无误差。因而对所有新 SSD 服务倍率的认证也无法修正它；把不确定性放在错误的状态维度上，扩大该成本区间仍无济于事。这是模型内的存在性反例，不把 39 ms 当作本机 RAM 搬运实测。

若只知道真实计算残余 $r\in[30,37.5]$，目标差值可解析写为

$$
\delta(r)=\max(r,39)-(r+8)=\max(0,39-r)-8.
$$

其上确界为 $\delta(30)=1>0$，零预算就应拒绝加载；仅在预测点 $r=37.5$ 评价才会误认安全。原模拟器在 $r=30,31,37.5$ 的核对分别得到 $1,0,-6.5$，与解析式一致。该受限例可直接认证，尚未解决一般同时有在途搬运、共享与事件跳变的联合状态域。

此外，总耗时误差比例不能直接用作剩余时间区间。若总计算耗时为 $W$、已执行 $W-r$，总耗时相对误差为 $\eta$，预测残余是

$$
\widehat r=\max(0,r+\eta W).
$$

高估时绝对残余误差为 $\eta W$，相对残余误差为 $\eta W/r$，接近完成时可任意大；低估还可能将预测残余截成零。因而“总成本 ±25%”与“残余 ±25%”是不同假设。跨事件分支已有不连续反例，也不能直接用全局线性敏感度界代替认证。

研究脚本仅将阶段预测倍率传给原执行器的活动阶段剩余估计；候选的所有未来服务仍按准确名义成本求值，并对新 SSD 服务作一维敏感性认证。实际状态只在执行后用完成时刻和原始传输事件重建，供评价与缺项核对，不进入动作选择。这使实验能单独检查活动状态误差，未把它混同于未来成本误差。

### 3.13 二维事件域可以精确认证，但四角是否充分仍待判定

同时改变正在执行请求的正剩余运行时间 $r$，以及所有尚未启动的 SSD 服务的共同倍率 $x$。初始运行结束改为 $t_0+r$，新 SSD 服务耗时改为原估计乘 $x$；初始在途搬运的结束时刻固定，后继计算、RAM、复制估计和通道速率均固定。比较同一状态、同一后继方案中的候选，只改当前目标边界；可见请求均已到达。输入域是正的闭矩形，不含运行残余被截成零后的另一种活动状态，也不声称该矩形已由 GPU 测量覆盖真实误差。

**分支内结构。** 在事件历史固定时，完成时刻是 $a+br+cx$。证明可逐事件归纳：初始时间为仿射式；固定服务时间或 SSD 倍率服务与当前时刻相加仍仿射；下一事件和等时优先级只依赖两个仿射式的比较。每个比较把当前区域分成负、零、正三部分，所以完整有限轨迹可划分为相对开放的凸多边形、线段和单点。对象准入虽然依赖离散状态，但在固定事件分支内对象集合固定，容量判断不再引入新的数值函数。

因此可以将所有候选的事件分区共同细化，得到区域族 $\mathcal P$。令 $d_{a,j,P}(r,x)$ 为候选 $a$ 相对固定基线在区域 $P$ 的逐请求仿射差，$V(P)$ 为区域闭包的顶点。则

$$
H_a=\max_{P\in\mathcal P}\max_j\max_{v\in V(P)}d_{a,j,P}(v),
$$

$$
U_a=\max_{P\in\mathcal P}\max_{v\in V(P)}\sum_jd_{a,j,P}(v),\qquad
R_a=\max_b\sup_{(r,x)}[J_a(r,x)-J_b(r,x)].
$$

最后一式也在同一共同细分上逐区域、逐顶点求值。$H_a$ 用于个体保护，$U_a$ 是响应和的最坏差，$R_a$ 是最坏遗憾，三者用途不同。当前评分在 $H_a\le0$ 的候选中最小化 $R_a$，平局保留基线，再选深边界；不把它称为响应和必然改善的规则。

使用闭包顶点计算的是上确界：若顶点被严格不等式排除，公式代表从该分支趋近的极限，不是该点真实的等时事件序列。边界自身必须另作分支求值，否则会漏掉前面已发现的事件优先级跳变。区域的有理数裁剪同时保留严格半平面与等式面；可行性由闭包顶点重心是否满足所有严格约束判断。该重心位于闭包的相对内部，因此也适用于退化线段和单点。研究实现设置事件及区域数上限，触发时直接失败；这些保护不是复杂度上界，尚未证明低成本可在线运行。

**错误安全反例得到拒绝。** 沿用第 3.12 节输入，令 $r\in[30,37.5]$、$x\in[0.75,1.25]$。RAM 恢复不依赖 $x$；二维认证精确得到深候选 $H=1$ ms，零预算规则保留重算。深候选的最坏遗憾为 1 ms，重算为 6.5 ms，故只做最坏遗憾最小化仍会选深。这个例子同时说明：加入正确状态维度可以修复保护判断，但稳健最优与个体保护仍是独立要求；它本身没有验证两个参数的交互。

### 3.14 四角一般不充分；两请求可用临界情景精确求解

第 3.13 节的一致性并非一般性质。只需两个请求、充分暂存额度、连续且固定顺序的服务，就能构造四角错误认证；不需要共享竞争、长队列或等时跳变。关键变化是**候选的存储层组成不同，使固定 RAM 成本与 SSD 倍率系数发生权衡**。

**两请求子模型。** 在时刻 $t_0$，前序请求正在计算，正残余为 $r$；只有一个已到达的目标请求。没有在途搬运及其他预留，目标各候选的缺失对象都能立即预取，且不能从当前活动计算中额外复用未计费对象。单通道与计算独立、无持久缓存，所有后续执行规则固定。设候选 $b$ 的 RAM 加载总成本为 $\alpha_b$、SSD 加载总成本为 $\beta_bx$，续算及必要复制为 $c_b$，则

$$
T_b(r,x)=t_0+\max(r,\alpha_b+\beta_bx)+c_b.
$$

这里的加载同时从 $t_0$ 开始，所以成本不受另一候选或未来请求影响；本式不适用于多后继竞争。各 $T_b$ 都是连续凸函数，但两个凸函数的差不一定凸，不能由单条轨迹的凸性推出差值在四角取最大。

**原模拟器内的两请求反例。** 保留原夹具的合法检查点：浅／深边界为 576／1,152 token，浅 KV 的 18 MiB 已驻留；浅的约 49.125 MiB 检查点在 SSD，深的新增 18 MiB KV 在 SSD，而深检查点在 RAM。固定路径成本使浅 SSD 检查点耗时 $6x$、深新增 KV 耗时 $(288/131)x$、深 RAM 检查点耗时 $51/4$ ms。浅续算为 $17/2$ ms，深续算为零，从头重算为 16 ms。额度为 256 MiB，所有候选均可立即预取。

取 $r\in[6,13/2]$、$x\in[3/4,5/4]$。除去共同起点，浅与深完成时刻分别为

$$
T_{576}-t_0=\max(r,6x)+\frac{17}{2},\qquad
T_{1152}-t_0=\frac{51}{4}+\frac{288}{131}x,
$$

因为深加载在整个域内均晚于前序结束。深减浅差值为

$$
\delta(r,x)=\frac{17}{4}+\frac{288}{131}x-\max(r,6x).
$$

| 场景 | 深减浅的目标响应差 ms |
| --- | ---: |
| 四角 $(6,3/4)$ | $-53/524$ |
| 四角 $(13/2,3/4)$ | $-315/524$ |
| 四角 $(6,5/4)$、$(13/2,5/4)$ | 均为 $-263/524$ |
| 严格内部 $(25/4,1)$ | $26/131$，约退化 0.198 ms |
| 全域最大值，$(6,1)$ | $235/524$，约退化 0.448 ms |

四角上深候选严格改善目标，前序不变，故个体最坏差 $H$ 为零；其四角最坏遗憾也为零。完整域中 $H=U=R=235/524>0$。原首次入窗的默认基线恰为浅候选；只看四角的受保护评分器选深，全域评分器保留浅。真实名义点位于矩形严格内部：前序从 0 计算到 60 ms，目标在 $t_0=53.75$ ms 到达，故 $r=6.25$、$x=1$。按原事件执行器实际派发，浅／深的完成向量分别为 $(60,137/2)$ 和 $(60,17999/262)$，后者目标及响应和都多 $26/131$ ms。这是模拟器内完整执行，不是 GPU 耗时实测。

这个反例定位了失败源：SSD 倍率同时作用于两条反事实，但两条路径对它的依赖不同。低倍率时深路径的加载仍可接受，高倍率时浅路径的加载也会暴露；最不利比较反而出现在中间倍率、浅加载刚好赶上前序结束的临界位置。即使只改变 $x$、固定 $r=25/4$，两端也安全而内部不安全。因此它还否证了该子模型中“一维未来成本只查两个端点即可”的普遍规则。

**可证明的正面结果一：共同 SSD 系数时，两个对角情景足够。** 若所有需要加载的候选具有相同 SSD 系数 $\beta\ge0$，允许各自 RAM 成本和续算成本不同，令 $z=r-\beta x$，则

$$
T_a-T_b=\max(z,\alpha_a)-\max(z,\alpha_b)+c_a-c_b.
$$

当 $\alpha_a\ge\alpha_b$，该差值随 $z$ 单调不增；反之单调不减。无加载候选的完成时刻为 $t_0+r+c$，减去共同的 $t_0+\beta x$ 后成为 $z+c$，与上述函数的差同样单调。因此所有候选对的最大、最小差值都在 $z$ 的两个端点达到，即 $(r_{\min},x_{\max})$ 与 $(r_{\max},x_{\min})$。同样两个场景就能精确得到全部个体界、总差界、最坏遗憾和保平局的受保护动作。它是两请求模型的充分条件，不能用来证明第 3.13 节多请求随机族普遍只需四角。

**可证明的正面结果二：任意非负系数，只需检查解析临界情景。** 对两个候选，差值仅在两条直线 $r=\alpha_a+\beta_ax$、$r=\alpha_b+\beta_bx$ 上改变仿射分支。将它们与矩形共同划分后，连续差值的最大、最小值只需检查：四角、各直线与矩形边的交点，以及两直线在矩形内的交点。每条直线至多贡献两个边界交点，故每个候选对至多 9 个场景；平行、重合和恰好过角时去重即可。候选间遗憾是这些成对上界的最大值；有 $A$ 个候选时，系数已汇总后的全部精确界可用 $O(A^2)$ 次有理数算术求得，不必展开通用事件树；从对象表构造系数另需遍历各候选依赖。该复杂度是基本算术次数，未计分数位长增长，也不是在线耗时实测。

本反例三候选的共同临界集合只有 6 个点，通用二维求值器得到 3 个事件区域，二者全部界一致。单独原执行器核对临界点及严格内部点，并在原首次决策位置实际执行两种评分器，重现上述退化／保护。另用 1,000 个代数配置交叉核对全线排列与成对临界算法；89 个配置出现四角低估个体界，共同系数及加入无加载候选的配对均通过两个对角情景核对。这些代数配置不是额外的原模型轨迹，更不代表生产发生率。另有 7781 的 64 个合法两请求配置独立改变对象驻留、RAM/SSD 放置、路径启动成本及计算成本：成对临界算法、共同直线排列、通用事件域全部界与动作一致，1,266 个临界向量和 6,846 个事件分支向量均经原执行器核对；两组点有重叠，不作为独立样本数相加。

### 3.15 加一个固定后继仍可解析，但目标就绪线不再覆盖全部临界点

把两请求模型扩展为三个请求：A 正在运行，目标 B 可改边界，后继 C 的边界固定。三者在当前时刻 $t_0$ 均已到达，预取窗口能同时看见 B、C；没有在途搬运、额外预留或延迟释放。B 各候选及 C 的缺失对象分别都能入池；**B、C 缺失对象不共享，也不能额外复用 A 的活动状态**，初始驻留对象可以复用。维持单不可抢占搬运通道、FIFO 计算、计算开始交接预取额度、无运行减速及持久新增驻留。

令 B 候选 $b$ 的加载为 $L_b(x)=\alpha_b+\beta_bx$，续算及必要复制为 $c_b$；C 的加载为 $L(x)=\gamma+\delta x$，续算及复制为 $c_C$。A 的正残余为 $r$。以下各时刻都减去共同起点 $t_0$，定义

$$
S_b=\max(r,L_b),\qquad F_b=S_b+c_b.
$$

若 B、C 的缺失对象并集能同时预留，C 在 B 的加载完成后即占用搬运通道，所以其完成时刻为

$$
G_b^{\mathrm{coexist}}=\max(F_b,L_b+L)+c_C.
$$

若不能共存，C 要等 B 开始运行、交接额度后才能加载，故

$$
G_b^{\mathrm{conflict}}=S_b+\max(c_b,L)+c_C.
$$

容量是否共存是对象字节与放置决定的候选属性，不随 $r,x$ 改变。这两式包括加载为空、续算为零及初始检查点复制等退化情形。它们分别区分了 C 的搬运起点与搬运是否超过 B 的计算窗口；用准入等待直接代替响应损失会丢失这两步。

**精确临界集。** B 的分支由 $r=L_b(x)$ 划分。冲突时再加 $L(x)=c_b$；可共存时还需 $r=L_b(x)+L(x)-c_b$。因此每个候选至多 3 条直线，每个候选对至多 6 条。完成向量 $(r,F_b,G_b)$ 连续、分区仿射，故逐请求差及总差的极值只需检查四角、直线与矩形边的交点、直线之间的交点。每对至多

$$
4+2\cdot6+\binom62=31
$$

个情景；重合、平行、区域外及重复点删除后通常更少。成对求值同时给出各请求上界与总差上界；最坏遗憾仍为所有对手总差上界的最大值。汇总加载系数后，$A$ 个目标候选的全部精确界仍需 $O(A^2)$ 次基本有理数算术，包含对象表预处理时还要计候选依赖扫描，分数位长和在线运行耗时另算。此处不需要通用事件树，也不能推广为任意队列长度的复杂度保证。

**仅沿用目标就绪临界点会漏掉后继窗口。** 128 个随机合法配置中未观察到漏估，但以下独立构造证明它确实会发生。目标仍选 576／1,152，C 固定选 1,152；预算 128 MiB，目标两个非零候选分别都与 C 冲突，单独则都可预取。浅 KV 已驻留，深新增 KV 在 SSD、深检查点在 RAM。参数为

$$
L_{576}=\frac{2227}{908}x,\quad c_{576}=\frac{17}{4},\qquad
L_{1152}=\frac{19}{5}+\frac{204}{227}x,\quad c_{1152}=0,\qquad
L=\frac{17}{4}x,\quad c_C=0.
$$

取 $r\in[1/2,1]$、$x\in[1/2,3/2]$；两条目标加载均晚于 A 完成，目标就绪线不穿过域，所以旧临界集退化为四角。真正缺失的是 $L=c_{576}$，即 $x=1$。深减浅的总响应差为

$$
\Delta J(x)=
\begin{cases}
-\frac9{10}+\frac{1037}{908}x,&x\le1,\\
\frac{67}{20}-\frac{1411}{454}x,&x\ge1.
\end{cases}
$$

旧临界集给出的总差上界为 $-2987/9080$ ms，约改善 0.329 ms，完整上界却为 $1099/4540$ ms，约退化 0.242 ms。深候选的最坏遗憾也从错误的零改为 $1099/4540$ ms。逐请求界中，后继 C 的损失被从 $10197/4540$ ms，约 2.246 ms，低估成 $13339/9080$ ms，约 1.469 ms。

以浅为比较参照、个体预算为 2 ms，旧临界规则允许深且按遗憾选深，精确规则保留浅。从原执行器的当前名义状态出发，实际 $r=3/4,x=1$：深使目标快 $4549/2270$ ms，却使 C 慢 $10197/4540$ ms，响应和退化 $1099/4540$ ms，确实突破 2 ms 预算。零预算下两种规则都排除深，不能将这个例子写成新的零预算失效。该构造的原 local-cost 默认动作是深；浅是明确指定的合法比较基线，后继始终固定，不声称原多步策略拥有或失去了保证。

**共享不是仅改一个容量求和就能加入的因素。** 另一个合法三请求例中，B、C 共享 36 MiB 只读 KV，两个独立检查点不共享。两请求缺失量各 85.125 MiB，毛和 170.25 MiB，但实际并集 134.25 MiB，可共同纳入 160 MiB。原执行器完成向量为 $(6,6,8)$；按毛和错判冲突、再重复支付 C 的全量加载，会预测 $(6,6,11)$。即使用并集改正容量、仍重复支付共享加载，也只得到 $(6,6,10)$。因此准入和剩余搬运工作都必须体现对象共享；本轮投影明确拒绝共享缺失对象，未用不适用公式给出所谓安全证书。

### 3.16 共享只读 KV 可保留临界集，但剩余加载取决于交接机会

第 3.15 节的无共享条件可在明确限制下放宽：B、C 的缺失对象交集只含只读 attention KV，位于 B 的活动 KV 列表中；两者检查点不共享。仍要求双方缺失对象各自可入池，当前无在途搬运及额外预留，预取窗口覆盖二者，无其他未来请求，活动 A 不提供额外复用。初始驻留检查点所需复制仍计入各自固定计算阶段成本。全部条件由研究投影在求值前检查；没有覆盖共享检查点的写时复制和身份变化。

令 $K_b(x)$ 为 B 候选与固定 C 共享、且不在初始驻留中的 KV 加载成本，$L(x)$ 为 C 的全部缺失加载。容量按缺失对象并集判断共存。后继的有效剩余加载为

$$
\widetilde L_b(x)=
\begin{cases}
L(x)-K_b(x),&\text{可共存，或冲突且 }c_b>0,\\
L(x),&\text{冲突且 }c_b=0.
\end{cases}
$$

**为什么分三种情况。** 可共存时，C 在开始阶段已预留共享 KV，B 加载完成后它们仍在就绪集中，C 只搬其余对象。容量冲突且 B 有正运行阶段时，B 交接预取额度后 C 获准入，执行器把 B 的活动 KV 交给 C，因此仍只搬其余对象。冲突且 B 的阶段耗时恰为零时，执行器在该时刻立即完成 B，再处理后继；缺少 C 预留的 KV 已被丢出就绪集合，不能沿用活动交接。$c_b$ 包括模型中被串入运行阶段的复制成本，不能仅凭后缀 token 为零判断是否存在交接机会。

将第 3.15 节的 $L$ 换成候选相关的 $\widetilde L_b$，闭式保持为

$$
G_b=
\begin{cases}
\max(S_b+c_b,L_b+\widetilde L_b)+c_C,&\text{可共存},\\
S_b+\max(c_b,\widetilde L_b)+c_C,&\text{容量冲突}.
\end{cases}
$$

这不是只修正容量求和：并集决定预取起点，活动交接决定实际剩余工作，两项都影响最终响应。由于比较域只改变正运行残余 $r$ 与 SSD 倍率 $x$，而 $c_b$、共存属性和共享对象集合固定，$\widetilde L_b$ 仍是非负仿射加载。每个候选仍至多 3 条临界线，将它用于原成对算法即可；每对至多 31 个情景、汇总系数后 $O(A^2)$ 次基本算术的上界保持。共享图的依赖扫描与交集预处理另计。

这个推导也揭示了另一个边界：若后续把 $c_b$ 当成可跨零的不确定参数，不能直接把上述三种情况接成连续模型。零与正运行阶段的活动交接机会不同，必须单独保留零面；本轮没有证明关于计算成本的全局连续性。若改为物理系统的不同交接语义，则必须重新确定该条件，不能把模拟器的零阶段优先级当作硬件规律。

### 3.17 共享检查点同时改变目标复制与后继重载，仍可预计算

在第 3.16 节的三请求、固定后继和立即预取条件下，再允许 B、C 使用同一合法边界的同一循环检查点。不同边界的检查点不能互相截取；共享必须由依赖对象身份而非字节相等判定。仍不改变原执行器：计算开始时，目标先撤销自己的预留，再判断检查点是否仍由初始驻留或后继预留持有。

令 $Q_b$ 为双方共享、但不在初始驻留中的检查点，$q_b$ 为其复制成本，$c_b^0$ 已包含目标续算和初始驻留检查点复制。若候选与 C 可共存、$Q_b$ 存在且 B 需要继续生成前缀剩余部分，则

$$
c_b=c_b^0+q_b;
$$

其他情况为 $c_b=c_b^0$。后继预留使共享源在 B 交接时仍被保留，所以目标必须建立私有状态副本；若 B 恰为完整前缀边界，则不收取该复制。初始驻留的复制已经计入 $c_b^0$，不能重复支付。容量冲突时 C 尚未预留这份源，B 在位接管，不产生这项额外复制。

令 $K_b(x)$ 为共享缺失 KV 成本，$Q_b(x)$ 为共享缺失检查点加载成本，不存在时取零。C 的剩余加载精确为

$$
\widetilde L_b(x)=
\begin{cases}
L(x)-K_b(x)-Q_b(x),&\text{可共存},\\
L(x)-K_b(x),&\text{冲突且 }c_b>0,\\
L(x),&\text{冲突且 }c_b=0.
\end{cases}
$$

冲突时正运行阶段只交接活动 KV，不交接循环检查点；因此不能把检查点也从后继加载中扣掉。C 真正开始计算时 B 已完成，没有 B 的未来预留持有 C 的源；在本限定模型中，C 除初始驻留复制之外没有新增共享复制。

将修正后的 $c_b$ 与 $\widetilde L_b$ 代入第 3.16 节的闭式，全部复制成本、共存关系及共享集合都在 $r,x$ 域求值前固定。仍是每候选至多 3 条临界线、每对至多 31 个情景。新增状态改变系数，不增加域内事件族；不能因此将“检查点共享不会影响排序”写入结论。尤其是目标的阶段成本不能再由它自己的静态边界表单独决定，必须知道后继是否持有同一源。

### 3.18 不可预取候选使对象搬运顺序成为不可省略的信息

“每个候选都能单独预取”是第 3.14–3.17 节闭式的重要条件。取消它后，后继已提交的不可抢占对象可反向阻塞当前目标的按需加载。相同候选总加载时间、RAM/SSD 分项总时间、对象大小与缺失字节不足以确定选点；需要知道各对象在依赖顺序中的位置，或等价的搬运前缀时间。

**合法三请求配对。** A 从 0 计算到 28.125 ms，B、C 在 25.125 ms 到达，故首次选点时 A 的准确残余为 3 ms。B 只有重算或完整 1,152 边界；C 固定选完整 1,152，C 检查点已驻留。额度 80 MiB，B 的缺失量为 85.125 MiB，不能预取但可到队首按需执行；C 缺失两个各 18 MiB KV，共 36 MiB，可以预取。无共享缺失对象、通道只有一条且不可抢占。

B 重算成本为 7.5 ms，深候选全部从 RAM 加载，固定耗时 $227/48$ ms，后缀为零。C 的两个等大小 KV 一个从 RAM 加载 1 ms，另一个从 SSD 加载 5 ms。配对仅交换两个 KV 的存储层位置，不改变合法依赖顺序、对象大小、每条路径的总字节或总成本。

| C 的搬运顺序 | B 重算时 B／C 完成时刻 | B 深恢复时 B／C 完成时刻 | 深减重算响应和 | 两候选中最佳 |
| --- | --- | --- | ---: | --- |
| RAM 1 ms，再 SSD 5 ms | $10.5,10.5$ | $515/48,515/48$ | $11/24$ ms | 重算 |
| SSD 5 ms，再 RAM 1 ms | $10.5,10.5$ | $467/48,515/48$ | $-13/24$ ms | 深恢复 |

时刻均相对共同到达起点，A 在两条路径均于 3 ms 完成。第一种顺序中，时刻 3 SSD 对象仍在途，B 的按需加载要等到 6；第二种顺序中只需等到 5，B 随后先于 C 的最后一个 RAM 对象加载。深路径下 C 最终均于 $515/48$ 完成，B 的差异却足以翻转总响应排序。原执行器直接执行全部固定计划重现这些向量；一般二维事件求值器另核对残余 $[2.5,3.5]$、SSD 倍率 $[0.75,1.25]$ 的候选域。

因此，任何只接收上述汇总量、忽略对象顺序的确定性两候选规则，面对这两个实例必然输出相同动作，至少错一个；它若在快照中额外保留对象身份、路径顺序或在途残余，就不属于这个受限规则类。此处是汇总状态不足的存在性结论，不是完整观测在线算法的下界，也不证明原有 local-cost 或任意策略必然退化。

这项失败不同于共享去重：即使对象完全独立，聚合成本也会漏掉不可抢占边界。三请求的共享、复制和可预取闭式仍有效于各自条件；不能用本反例否定其条件证明。若要扩大解析证书，应保留后继逐对象的加载前缀 $s_k(x)$，在 $r=s_k(x)$ 等位置区分哪个传输跨越目标消费时刻，再分析剩余搬运与计算；仅增加一个通道总等待变量不足以确定所有反事实。

### 3.19 按需加载与重算的比较可由逐对象前缀线性分区

对第 3.18 节的失败可给出正面证书。限定三个已到达请求：A 计算残余为正，B 仅比较重算与一个不能预取但可以按需执行的深候选，C 固定且其全部缺失对象可以立即预取。当前无在途搬运、额外预留或额外活动复用，B、C 缺失对象互不共享，维持独立单搬运通道、FIFO 计算与交接释放。路径服务对域内每个缺失对象严格为正；复制如由初始驻留触发，计入固定阶段成本。域仍只有 $r$ 与新 SSD 倍率 $x$。

设 C 有 $m$ 个缺失对象，按合法加载顺序的耗时为 $d_i(x)$，定义前缀

$$
s_0=0,\qquad s_k(x)=\sum_{i=1}^k d_i(x),\qquad L_C=s_m.
$$

设 B 深加载总时长为 $L_B(x)$、深运行阶段为 $c_B$，重算为 $c_0$，C 的固定阶段为 $c_C$。B 深路径到队首时，若

$$
s_{k-1}(x)<r\le s_k(x),
$$

C 的第 $k$ 个传输挡住 B，B 要等至 $e=s_k$，C 未完成的加载为 $u=L_C-s_k$。若 $r>s_m$，则 $e=r,u=0$。所有时刻减去当前共同起点，两条路径的完成向量为

$$
\mathbf C_{\mathrm{deep}}=(r,\ e+L_B+c_B,\ e+L_B+\max(c_B,u)+c_C),
$$

$$
\mathbf C_{\mathrm{zero}}=(r,\ r+c_0,\ \max(r+c_0,L_C)+c_C).
$$

前式来自 C 当前对象完成后，通道优先处理队首 B 的完整按需加载，再处理 C 的剩余对象；后式中 B 不搬运，C 按原顺序连续加载。因此对象前缀决定堵塞边界，后续只需剩余加载总量。这里保留的顺序信息恰是第 3.18 节汇总反例所缺失的部分。

**事件相等不能模糊处理。** $r=s_k$ 时，C 的当前传输与 A 同时完成，执行器处理就绪后由队首 B 提交加载，不提前启动 C 下一对象，故该边界属于第 $k$ 类。当 $r$ 从右侧趋近同一边界，C 下一对象已经启动，B 可能再等待完整的下一对象时长。这说明这些前缀面可发生跳变；不能把开分区公式在端点的极限当成该点的实际完成时刻。

**规模上界。** $m+1$ 个前缀区域均由仿射半平面给出。每区只需再比较两项：$c_B$ 与 $u$、$r+c_0$ 与 $L_C$。每次分别保留负、零、正三个符号，因此每区最多 9 个相对开放多边形、线段或单点，总计至多 $9(m+1)$ 个区域。各区只有常数条边界，完成向量及两路径差在区内仿射；在闭包顶点求上确界，同时单独保留等式面，便可精确获得逐请求界、总差和双方最坏遗憾。前缀累计与分区求值为 $O(m)$ 次基本有理数算术，另加 B 依赖扫描；这不是比特复杂度或实际在线耗时保证。

该线性界针对一个深候选与重算，不包含多个深候选共同竞争、共享对象、不可预取 C 或初始在途搬运。不能将 $O(m)$ 外推成一般长队列证书，也不能将这里的分区数与前面“临界点数”不加区别地比较。

**7830 核对。** 64 个合法配置沿用顺序配对的对象结构，随机改变两层启动成本与带宽。该批 C 均只有两个缺失 KV，故验证重点是前缀等式边界及域内事件，不是长对象链的经验扩展性。解析域共 366 个区域、2,052 个原执行器向量核对；通用二维域另核对 6,920 个向量，所有个体界、总差及双方遗憾一致。两类点集重叠，不能解释为独立样本数之和。线性规模结论来自上述推导，未由固定两对象的实验规模替代证明。

### 3.21 两个活动阶段残余需要共同事件域，而不是独立误差叠加

前面二维域的第二个变量是未来 SSD 倍率；现在单独研究另一个域：运行中 A 的残余 $r$ 与在途传输的残余 $h$ 同时变化，所有未来 RAM、SSD、计算及复制成本固定。初始对象身份、预留和就绪集合固定。本轮沿用 C 已预留且首个缺失 KV 正在传输、B 深候选不能预取的可达状态，比较深恢复与重算。两个变量始终为正，不包含已经完成活动阶段的另一个离散状态。

通用符号求值器增加明确的 active-pair 模式：当前运行结束为 $t_0+r$、当前传输结束为 $t_0+h$；未来 SSD 耗时不乘第二个变量。对相同 $(r,h)$ 同时评价两条反事实。第 3.13 节的事件归纳仍成立：每个固定事件分支中的完成时刻是 $a+br+ch$，比较产生仿射半平面，保留相对开放区域、等式线段和单点后，可在各闭包顶点求差值上确界。这里沿用的是通用分区正确性，没有声称每对 31 点或线性前缀求值器已经认证不确定 $h$。

相应的直观前缀成为 $s_1=h$、$s_k=h+\sum_{i=2}^k d_i$。哪些对象跨过目标到队首时刻，由 $r=s_k$ 确定。这些比较将两个活动阶段直接耦合：固定一个残余后求另一个的最坏点，不能未经证明就丢掉内部事件面；两条反事实也不能各自采用不同残余情景来假装精确差值。

### 3.22 由总耗时界与活跃观测构造残余域，保留共同时间相关性

域内求值精确不等于域覆盖实际状态。本节补上一个条件性的集合推导：给定真实有效的总耗时界、准确开始时刻与活动标志，如何得到残余集合。没有新增硬件测量，也没有把经验误差半径当成确定性界。

**误差定义必须先明确。** 若预测总耗时为 $\widehat W>0$，假设误差相对真实总耗时满足 $|\widehat W-W|\le\eta W$，$0\le\eta<1$，则

$$
W\in\left[\frac{\widehat W}{1+\eta},\frac{\widehat W}{1-\eta}\right].
$$

它不同于相对预测值的假设 $|\widehat W-W|\le\eta\widehat W$。例如 $\widehat W=10,\eta=1/4$，前者区间为 $[8,40/3]$，不是 $[7.5,12.5]$。定义不一致会在进入事件认证前就丢失覆盖。

准确开始于 $s$、准确观测时刻为 $t$ 时，先令结束区间为 $[A,B]=[s+W_{\min},s+W_{\max}]$。若在处理完本时刻事件后观察到阶段仍活跃，则残余满足

$$
r\in[A-t,B-t]\cap(0,\infty).
$$

下端可以趋近零但不能包含零。若 $B\le t$，活跃观测与总耗时假设矛盾，集合应为空；不能用 $r=\max(0,\widehat W-(t-s))$ 把矛盾伪装成确定的已完成阶段。若只知“完成通知尚未送达”，不能当成准确活跃标志，须另建通知延迟模型。

**共同观测时间不能拆开。** 设运行结束区间为 $[A,B]$，传输结束区间为 $[C,D]$，同一观测时刻只知 $t\in[\ell,u]$；两个阶段均已开始，时间区间预先与开始时刻约束相交。除此之外，结束区间没有额外耦合。存在同一个 $t$ 的精确正残余域是

$$
\begin{aligned}
r&>0,\quad h>0,\\
A-u&\le r\le B-\ell,\\
C-u&\le h\le D-\ell,\\
A-D&\le r-h\le B-C.
\end{aligned}
$$

证明是时间区间 $[\ell,u]$、$[A-r,B-r]$、$[C-h,D-h]$ 存在共同交集。当且仅当三组一维闭区间两两相交，等价于上述边界；正残余由活跃标志另加。若硬件速率或其他因素还使两个结束时间相关，此域只是外包络，须继续加入那些相关约束。

例：两个结束时刻准确为 10、12，当前时刻在 $[5,7]$。残余只能位于 $(3,5)$ 至 $(5,7)$ 的对角线段，满足 $h-r=2$；分别构造区间却得到矩形 $[3,5]\times[5,7]$，包含不可能的点 $(3,7)$。该矩形对仿射量 $h-r$ 给出 4，精确域仅为 2。这里只证明集合及线性界可收紧，不声称此数值就是某个恢复策略的响应改善。

精确域可能是多边形、线段、单点或空集。其闭包顶点可含零残余，但严格约束排除该点；证书可用它求单侧极限。若真实阶段已完成，必须执行完成事件、更新就绪与队首等离散状态，再比较候选，而不是在旧活动快照中把残余填零。本节没有实现所有“完成／活跃未知”的离散状态并集。

### 3.24 两个固定后继：准入门槛仍允许有限 max-affine 证书

本轮从一个后继增加到两个，但先限定一类可精确求解的容量结构。四个请求 A、B、C、D 都已到达；A 正在计算，正残余为 $r$，B 选择边界，C、D 的边界固定。没有初始在途传输、其他预留或新增持久驻留。缺失对象互不共享，也不复用 A 的活动状态；保持单串行搬运通道、FIFO 计算、计算开始释放预留，以及固定成本／无相互减速。预取窗口覆盖 B、C、D。

对每个 B 候选，B、C、D 的缺失对象集合**任意两组均可共同预留**；三组并集可以放得下，也可以放不下。这个条件排除了后继绕过一个不能准入的 C 等其他容量结构。每条加载总成本分别为 $L_b(x),L_C(x),L_D(x)$，都对未来 SSD 倍率 $x$ 仿射且非负；各请求续算及固定复制成本为 $c_b,c_C,c_D$。初始驻留若存在，先从缺失集合扣除，并计入实际复制成本。

减去共同当前时刻，令

$$
S_b=\max(r,L_b),\qquad
F_b=S_b+c_b,\qquad
F_C=\max(F_b,L_b+L_C)+c_C.
$$

B、C 总能同时准入，通道按 B 再 C 加载，所以 C 的就绪为 $L_b+L_C$。若三组共同可预留，D 的就绪为 $L_b+L_C+L_D$，因而

$$
F_D^{\mathrm{fit}}=\max(F_C,L_b+L_C+L_D)+c_D.
$$

若三组不能共同预留，D 要等 B 开始、释放预留后才可准入；C、D 能共同预留保证此时容量足够。通道还须完成 C，故

$$
R_D^{\mathrm{conflict}}=\max(S_b,L_b+L_C)+L_D,
$$

$$
F_D^{\mathrm{conflict}}=\max(F_C,R_D^{\mathrm{conflict}})+c_D.
$$

这里是**准入时刻与通道可用时刻取最大值**，不能直接加完所有加载成本。零运行阶段可能跳过当次预取，但在本子域中不改变闭式：若 B 在同一时刻直接完成，D 最迟转为可准入；若 C 也零运行，则 D 在同一时刻转为队首按需加载。由于无对象共享，其结果仍是上述就绪时刻。其他容量关系或活动复用需重新分析。

**有限临界集证明。** B 完成是至多两个仿射函数的最大值；C 完成至多三个。冲突时 D 完成可以展开为以下五项的最大值，再加 $c_D$：

$$
\begin{aligned}
r+c_b+c_C,&\quad L_b+c_b+c_C,\\
L_b+L_C+c_C,&\quad r+L_D,\quad L_b+L_C+L_D.
\end{aligned}
$$

其中 $L_b+L_D$ 被 $L_b+L_C+L_D$ 支配，可删去。三组可共存时至多四项。所有完成向量连续、分区仿射。取每项输出内部所有仿射项的两两等值线，单候选最多 $\binom22+\binom32+\binom52=14$ 条，两候选最多 28 条。因此矩形域中的极值只需四角、直线与矩形边的交点及直线之间的交点，每对最多

$$
4+2\cdot28+\binom{28}{2}=438
$$

个情景。该数是易检查的保守上界，含不活跃分支线，不声称最紧。逐请求差、总差与成对遗憾都在共同线排列的顶点取极值；平局仍按明确规则处理。固定四请求下，$K$ 个目标候选汇总加载系数后，全部成对界需 $O(K^2)$ 次基本有理数算术，另计依赖扫描和分数位长。这不证明一般队列也有常数情景界。

**准入不能省略的原执行器见证。** 首个合成夹具中，B 浅候选缺失 67.125 MiB，C、D 各缺失 85.125 MiB，180 MiB 预算允许任意两组，但不能放下三组。成本为 $L_b=4,L_C=L_D=5,c_b=17/4,c_C=c_D=0$，观测参数 $r=19/2,x=1$。正确完成向量为

$$
(A,B,C,D)=(19/2,55/4,55/4,29/2).
$$

错误地按三组均可立即准入计算，得到 $(19/2,55/4,55/4,14)$，少计 D 的 0.5 ms。原执行器在 180 MiB 下重现前者；仅放宽到 280 MiB 后重现后者，A、B、C 的完成时刻保持不变。这证明额外后继的容量准入可产生目标与首后继均未体现的损失；它没有证明本例的最佳边界发生翻转。

### 3.25 失败的中间准入不保证后继也失败：请求准入集合可以有空洞

上一轮的 3.24 子域要求任意两组对象都能共同预留。现在放宽这一点，只考察一个具体但合法的容量次序：请求 B、C、D 都已到达，B 可选择边界，C 固定深边界，D 固定浅边界；缺失对象互不相同。每个预取请求按 FIFO 请求索引尝试整组预留，但一次准入失败不会阻止检查后续请求。活动 A 正在计算，传输队列单一、不可抢占，计算开始时释放该请求的预取额度。

使用原手算对象大小：B 浅、D 浅各需 67.125 MiB，C 深需 85.125 MiB，预取预算 145 MiB。于是

$$
B_{浅}+C_{深}=152.25>145,\qquad
B_{浅}+D_{浅}=134.25\le145,\qquad
C_{深}+D_{浅}=152.25>145.
$$

在同一时刻，B 选 0 时，C 深可以预留，D 因与 C 冲突而未准入；B 选 576 时，C 不能与 B 共存，但较小的 D 可以在 C 失败后继续尝试并获准入。执行器归档确认了相应预留时刻：前者只有 C 在 0 ms 获准入，后者 B 与 D 均在 0 ms 获准入、C 未获准入。故已准入请求集合不是请求索引前缀，压缩成“最远已准入请求”会丢信息。

D 的对象先加载完成，却不能越过 FIFO 计算中的 C 开始执行。B 浅运行结束后，C 在队首按需加载；该按需路径使用单独的执行预算，因而不会把“预取额度不足”误判为候选不可执行。D 的预取驻留则继续影响可用状态。此过程要求分别记录预取预留集合、就绪对象与队首按需依赖；仅有队列位置、预取字节总量或累计已完成工作量都不够。

**原执行器的完成向量**（ms）为：

| B 边界 | A、B、C、D 完成时刻 | 四请求完成时间和 |
| ---: | --- | ---: |
| 0 | $(30,38,38,46.25)$ | $152.25$ |
| 576 | $(30,34.25,39.25,43.5)$ | $147$ |
| 1,152 | $(30,30,35,43.25)$ | $138.25$ |

B=576 使 C 比 B=0 晚 1.25 ms，同时 D 早 2.75 ms。把 C 的失败当作后续请求都不能准入，会错误预测 D 需在队首按需读取；把 D 的预取完成当作 D 可执行，又会漏掉它必须等待 C 的 FIFO 计算。两种错误都来自把不同资源状态压成单一准入前缀，而非恢复边界本身的固定加载公式。

该例还进入二维条件域 $r\in[5,40]$ ms、未来 SSD 倍率 $x\in[3/4,5/4]$。通用精确事件分区将所有候选共同切为 7 个区域，对原执行器核对 129 个候选向量。在此假设域中，B=576 相对 B=0 的总差上界为 $-4$ ms，但最大单请求退化为 $9/4$ ms；B=1,152 的总差上界为 $-41/4$ ms，最大单请求退化上界为 0，最坏遗憾为 0。说明总和改进不能替代个体保护，且准入空洞通过改变后继完成向量进入原有稳健比较。

### 3.26 准入模式本身可以呈指数增长：固定容量与容量参数化必须分开

3.25 的空洞不是偶然的三请求现象。考虑同一固定容量语义下的贪心扫描：所有后继已到达，缺失对象互不相同，每个后继只有“零边界”或一个固定非零候选，候选按请求顺序尝试整组预留。令第 $i$ 个后继的预留大小（按扫描顺序）为

$$
u\cdot 2^{n-1-i}\quad (i=0,\ldots,n-1)
$$

其中 $u$ 为每个 KV token 的字节数，检查点已驻留；容量取 $uk$。前一个大对象被接受后，剩余容量正好继续编码后面的二进制位；被拒绝的对象不改变剩余容量，后续对象仍可独立尝试。因此最终准入掩码恰为 $k$ 的二进制表示，容量从 $0$ 到 $u(2^n-1)$ 可产生全部 $2^n$ 个准入子集。

这给出一个算法复杂度分界：**给定一次固定容量和一组已知候选，准入扫描本身仍可在线性遍历完成；但若要对容量作精确符号参数化，不能假设只有“全都准入／全都冲突”或少量前缀模式。** 最坏情况下，容量轴至少需要区分 $2^n$ 个离散准入模式。每个模式还可能诱发不同的搬运队列前缀和不同的按需加载路径，之后才进入连续时间的事件分区。

**7883 原执行器核对。** 对 $n=1,\ldots,8$ 个后继，取 $u=32768$ 字节枚举容量 $uk$，逐一核对原模拟器的预留时刻和二进制掩码。得到的模式数分别为 $2,4,8,16,32,64,128,256$，均等于 $2^n$；共覆盖 510 个固定容量配置。对象长度与成本为构造值，只验证准入语义，不代表真实负载分布。

该下界不意味着每个实际工作负载都会出现指数模式，也不否定固定容量下的线性扫描。对一次初始扫描还可以得到更细的结构界：若预留大小只有 $d$ 种不同值，按同一大小分组后，每组被接受的请求必为该组在扫描顺序中的前缀，因此准入掩码数至多为

$$
\prod_{t=1}^{d}(n_t+1),
$$

其中 $n_t$ 是第 $t$ 种大小的出现次数；若大小按非递减顺序排列，则所有请求的准入集合本身是前缀，模式数至多 $n+1$。7883 对大小字母表 $\{1,2,4\}$ 的 1–6 请求序列核对了这两个结构性质，并用合法模型载荷重放了 1–8 请求的 $2^n$ 构造。

这个下界约束的是逐一输出准入模式的算法，未排除隐式表示、只检查会改变动作的模式，或在特定输入结构下合并模式。跨容量证书必须正确处理离散切换，但无须默认显式枚举每个掩码。

### 3.27 动态准入：释放、重试与共享预留

3.25 和 3.26 只描述一次初始扫描。实际语义在请求开始计算时释放该请求的预取预留；之前因容量失败的请求仍会在后续事件重新尝试。因此，算法状态不能只保存初始准入掩码，必须保存当前预留、当前就绪对象和下一次可重新检查的请求集合。

构造一个合法四请求快照：B 选浅边界，C 选深边界，D 选浅边界；D 的首个 KV 已在设备中，所以 D 只需预取一个检查点。预算为 145 MiB。B 浅缺失 67.125 MiB，C 深缺失 85.125 MiB，D 缺失 49.125 MiB，于是

$$
B+C>145,\qquad B+D\le145,\qquad C+D\le145.
$$

初始扫描接受 B 和 D，跳过 C。B 在 30 ms 开始计算并释放预留；事件循环重新检查 C，C 在 30–35 ms 预取完成，随后于 35 ms 开始计算。原执行器记录的预留时刻为 $B=0$、$D=0$、$C=30$ ms，搬运事件均为预取而非队首按需加载。

| B 边界 | A、B、C、D 完成时刻（ms） | 预留时刻（B,C,D） |
| ---: | --- | --- |
| 576 | $(30,34.25,35,39.25)$ | $(0,30,0)$ |

这与 3.25 的同容量结构不同：那里 C 一直无法与 D 共存，必须在队首按需读取；这里 C 在动态释放后重新获得预取资格。若把“初始失败”当成永久拒绝，会高估 C 的恢复成本；若把“最终获准入”当成初始状态，又会错误地让 C 与 B 同时占用预算。两种误差都不是连续时间估计误差，而是离散事件状态误差。

**固定容量下可以先计算哪些准入事件？** 设全部请求已到达且预取窗口覆盖全部后继，初始队首可立即运行，无遗留预留；选点、缓存放置及每个请求的整组依赖固定，单通道、续算严格为正，无追加持久驻留及动态减速。准入按待运行预留与运行中保留额度所覆盖的**对象并集**计费。共享对象在最后一个预留者释放后才退出该并集，不能按每个请求的名义大小直接扣减。

| 释放规则 | 何时可能接受新预留 | 所需信息 |
| --- | --- | --- |
| 运行开始时 | 队首开始并释放后，按顺序重试后继 | 固定计划、容量、对象身份和当前预留 |
| 运行完成时 | 前一请求结束，排除新队首后扫描剩余后继 | 同上；新队首的预留由等待转为运行中保留，并不改变计费并集 |
| 开始后固定延迟 | 同完成释放；若运行中的预留严格早于完成释放，再增加一次重试 | 同上，再判断释放延迟是否小于该请求的运行时长；运行时长可包含必要的检查点复制 |

理由是后继集合在队首推进时只会缩小；在扫描之间，搬运完成只改变就绪对象，不退回整组预留的额度。未获准的同一后继在容量和依赖并集都没变时重试仍会失败。完成释放时，新队首已就绪与否可能改变它与扫描的先后，但不改变该次扫描前的计费并集。由此，开始或完成释放的准入阶段可独立于搬运时长推导；该结论不提供搬运顺序、就绪时间或候选排序。

**定时释放的严格边界。** 在同一个 145 MiB 见证中，B 开始于 30 ms，完成于 34.25 ms。延迟 4 ms 时，C 于 34 ms 获得预留，39 ms 完成；延迟恰好 4.25 ms 时，原执行器在扫描前已推进队首，C 走按需加载，于 39.25 ms 完成。延迟 5 ms 时也走按需加载；保持 5 ms 和同样的字节状态，提高重算时长则使释放重新早于 B 完成，C 恢复预取资格。共享检查点也可能因是否要复制而改变运行时长。因此定时释放不能只由字节状态决定；相等面须按独立的事件规则处理。

**已复跑的证据。** [7884](evidence/dynamic-lookahead-dynamic-release-7884.json) 核对 64 个配置的开始释放及重试；[7885](evidence/dynamic-lookahead-release-modes-7885.json) 核对三类释放的 72 组搬运速度配对（含独立依赖与共享 KV／检查点配置），另保留上述定时反例。配对改变 RAM／SSD 搬运带宽；定时见证单独改变运行成本。两轮均为原模拟器核对，没有新增 GPU 测量。未来到达、零时长阶段、分块预留和多通道未由本节证明。

## 5. 后续方向与验收条件

本节维护研究优先顺序；按[R02 双人分工](next-round-plan.md)执行固定容量子域，GPU 观测性验证并行开展。一般化证明、容量不确定和多步误差保证不作为 R02 的完成条件。

### 第一优先：找出更一般竞争结构中的必要状态与临界集

核心问题：两个候选经过不同的准入历史后，什么条件保证后续影响相同，可以停止分别推演？先在固定容量下做：利用第 3.27 节的释放阶段与对象并集，判断哪些预留、就绪对象及在途剩余工作会改变后继；定时释放先用运行时长上下界判先后，区间跨越相等面时保留两种路径并单独检查同刻归属。再研究容量不确定时，重复大小、单调大小和共享依赖能否合并对选点无影响的模式，避免显式枚举第 3.26 节的所有掩码。以第 3.18 节“汇总相同、动作相反”的构造作为必要性检验。

预期成果是可检查的结构条件、有效情景数随请求数／候选数／对象数增长的上界，或否定低维压缩的最小反例。不能直接把通用符号分区的运行代价视为任何算法必需的复杂度。比较“完整对象状态、逐对象前缀、聚合成本”三类信息，明确各自首次失效的位置。仅扩大同一夹具随机样本不作为主要推进。

验收：原执行器逐请求向量一致，事件等式面与单侧极限独立检查，明确平局；区分情景点数、区域数、基本算术次数与比特复杂度。共享检查点、零阶段、准入集合非前缀闭包，以及不能预取但可按需执行的候选，均须声明是否覆盖。

### 第二优先：将条件稳健性推进为可组合的误差保证

核心问题：观测不足时，什么输入假设足以保证个体预算与整体收益？第 3.22 节已有总耗时到残余集合的条件变换，第 3.23 节说明现有 GPU 极值仍不能建立真实覆盖。先把活动标志未知表示为离散状态并集，保留共同时间与反事实参数相关性，再把状态域接入固定基线的延续价值认证。

分别研究确定性有界误差与明确分布假设下的概率覆盖，不混用保证。已有两请求状态误差反例必须被拒绝；多步研究还应核对基线桥接项、累计预算以及不可撤销的已启动动作。未知到达不能隐含纳入已见批次保证，可另研究有界到达或遗憾下界。

本组 GPU 任务限于检验这些假设是否合理、哪些观测能缩小会改变动作的情景域。记录重点是决策前可知量与事后真值之间的关系；不是继续增加无明确命题的性能测点。

### 第三优先：形成分层证书，证明其何时比完整求值更省

串联无外部性条件、工作量支配、状态等价抵消与临界情景求值，研究何时提前停止、何时跨候选复用、何时回退。所有简化先保留完整求值的动作、平局和个体约束，再比较证书构造加剩余求值的总成本。

预期成果是按竞争结构或事件数参数化的复杂度结论，以及能暴露最坏情况的困难构造。已有预算前沿属于求值后的处理，不能直接计为前置剪枝；仅减少模拟事件也不能主张净在线加速。

### 后续扩展：每次放宽一个模型假设

在上述问题收敛后，分别研究第二搬运通道、持久驻留、有界动态到达、共享带宽减速与连续批处理。每次先指出旧证明哪一步失效，再给出修正条件或反例。优先推广“状态差与临界事件”的分析方法，硬件上的具体阈值与收益比例不作直接外推。平均响应、共同完工、尾部和个体保护若改变目标，须重新证明权重与停止条件。

## 7. 算法设计覆盖与状态差分解

本节由原独立覆盖文档合入，统一列出算法接口、证明条件与尚未解决的设计问题。它不是新增实验，也不声称所有问题已经解决。

### 7.1 统一决策对象

在决策时刻 $t$，对当前请求 $i$ 的每个候选边界 $c$，固定候选后继方案，事件模拟器从快照 $s$ 产生一条轨迹。把当前候选的选择记为 $a=(i,c)$，将其余已见请求的固定方案记为 $\pi$。目标函数可以是：

$$
J(s,a;\pi)=\sum_{j\in V(s)} C_j,
$$

其中 $V(s)$ 是本次评价中可见且未完成的请求集合，$C_j$ 是从当前快照起的绝对完成时刻。平均响应、最大等待、P95 或加权目标都应单独定义；本轮已证明的排序证书只针对固定的完成时间和及其严格平局规则。

候选选择应返回三种结果之一：

1. **认证动作**：所有未求值候选都不可能优于它；
2. **认证区间**：若成本或未来信息不足，返回最坏遗憾界，而不是伪造唯一最优动作；
3. **未认证动作**：继续完整求值或按预先声明的保守回退规则选择。

因此，“没有证书”不是“局部最优”，而是算法必须显式处理的第三种状态。

### 7.2 候选生成与可行性

候选集的正确性先于评分。每个非零边界必须同时满足所有注意力 KV、循环状态和必要卷积缓冲的恢复依赖；候选集必须包含从头计算边界 $c=0$。候选生成、对象放置、对象共享和淘汰属于不同决策层，不能用选点实验替代缓存布点实验。

| 算法层 | 已覆盖 | 尚未证明 | 设计要求 |
| --- | --- | --- | --- |
| 候选依赖闭包 | 精确检查点与模型规格 | 近似状态、缺失区间闭包 | 依赖不全时直接判不可行 |
| 对象大小与层级 | RAM/SSD、共享对象、显存内复制 | 多级主机缓存、分片对象 | 以实际对象集合和去重后大小计费 |
| 可行性检查 | 非前缀准入；固定计划下整组预留的开始／完成释放，以及定时释放的严格先后条件 | 分块预留、未知到达、任意准入空洞下的模式合并 | 区分当前预留、就绪与待重试依赖，验证它们何时足以区分选点结果 |
| 候选排序 | 局部、前瞻、区间支配 | 多目标 Pareto 选择 | 平均响应、尾部和个体退化分开报告 |

### 7.3 状态差分解

设候选 $a$、$b$ 从同一快照出发，在两条轨迹完成相同数量请求、下一请求下标同为 $k$ 的交接处比较。两个交接不要求发生在同一绝对时刻。所有待评价请求已到达、后继方案和参数固定，才可去除绝对时间。令已完成部分的完成时间和差为 $g$，交接时刻为 $t_a,t_b$，未来相关状态分别为 $q_a,q_b$。令剩余请求集合为 $\mathcal R_k$、大小为 $m$，规范化未来价值为：

$$
W(q)=\sum_{j\in\mathcal R_k} \widehat C_j(q),
$$

其中 $\widehat C_j$ 是从时间原点为零的状态开始的相对完成时刻。则由时间平移不变性，候选差为

$$
J_a-J_b
=g+m(t_a-t_b)+W(q_a)-W(q_b).
$$

这是一个定义性分解，但有三个算法含义：

- **时间项** $m(t_a-t_b)$ 是状态已经完全等价时唯一剩余的外部性，得到已有的时间平移公式；
- **状态项** $W(q_a)-W(q_b)$ 包含预留、就绪、在途对象、剩余占道、共享身份和未来依赖等全部差异；
- 工作量上下界是在分别估计两个 $W(q)$，状态等价是在证明状态项为零；两者之间的研究目标是直接界定状态项。

若 $q_a=q_b$，已有状态等价定理给出 $J_a-J_b=g+m(t_a-t_b)$。若仅一个在途剩余时间 $r$ 不同，已有分段分析说明 $W(q)$ 在固定事件分支内是仿射，但跨分支可跳变。因此，未来工作应对状态项建立分支化区间，而不是寻找一个全局连续距离。若存在未到达请求或绝对时间变化的速度，须把这些相对时间表加入状态，不能直接套用上述时间平移分解。

比较器 [study_lookahead_candidate_difference.py](../scripts/cpu/lookahead/robustness/study_lookahead_candidate_difference.py) 对同一快照的两条固定计划分别分支，再合并事件阈值；开区间与单点分开表示。它已扩展到 RAM/SSD、预测成本和通道速度，并以原模拟器的逐请求完成时刻核对。审计和适用边界见[候选差共同分段](dynamic-gpu-lookahead-appendices.md#round-candidate-difference)。

进一步的[首次决策研究](dynamic-gpu-lookahead-appendices.md#round-first-decision)已保留运行中计算与活动依赖，复用所有候选的单臂轨迹计算多动作最坏遗憾，并用逐请求退化上确界定义安全集合。两批 608 次首次决策通过向量核对；零退化保护会改变部分纯稳健动作。无在途入口由后续未来 SSD 倍率研究补齐。

[未来 SSD 倍率研究](dynamic-gpu-lookahead-appendices.md#round-ssd-frontier)已补上无在途入口并构建预算前沿；指标支配只能保最优值，计入平局优先级才能保动作。统一报告第 3.9–3.12 节合并了计划级组合、基线延续价值、首次入窗及活动状态误差：固定同一基线已放宽到已知非单位恒定速率；参照漂移与成对状态模型缺项必须分别计费。已有两请求反例证明预测状态安全可能实际退化，未来 SSD 成本域不能覆盖漏掉的活动状态维度。联合状态与成本域已有第 3.13 节子域证据；第 3.21–3.22 节进一步覆盖给定正残余域及观测条件集合。真实误差域覆盖、一般多参数域和低成本复杂度仍未完成。

### 7.4 剪枝与停止规则的层次

以下是待验证的分层结构；各层的成本没有得到统一比较，也不存在证明强度递减的关系。实际顺序应由证书代价与覆盖率决定：

1. **不可行剪枝**：依赖不完整或执行预算不足时删除。仅预取额度不足不代表候选不可执行，须保留队首按需加载路径。
2. **无外部性触发器**：后继不能在当前候选完成前预取、共享或阻塞；此时局部排序安全。已有触发器是充分而非必要条件。
3. **绝对工作量界**：计算候选 $[L_a,U_a]$；若 $U_a<\min_{b\ne a} L_b$，认证 $a$。搬运上界必须按最早可能阻塞位置计权。
4. **共同状态抵消**：推演到 $q_a=q_b$ 的交接处，使用时间平移公式。
5. **状态差分支界**：对少量残余参数划分事件分支，检查区间端点、优先级单点和收益零点。
6. **完整候选求值**：无法认证时，执行原模拟器的完整前瞻。

任何一层都必须保留原有候选平局和 fallback 语义。若证书只证明严格优劣，等值时不得擅自改用更深边界或随机打破平局。

### 7.5 信息、误差与在线动作

算法输入分三类：

- **已知结构**：候选依赖、对象身份、共享关系、预算和当前预留；
- **当前动态状态**：队首、运行计算剩余、在途对象及剩余时间、可见到达请求；
- **不确定量**：未来到达、搬运倍率、计算时间和可能改变事件顺序的延迟。

未来请求不存在于当前状态时，任何在线规则都不能保证对所有未来都正确；相同快照、不同未来的反例已经证明这一点。对不确定成本，应使用同一反事实共享的误差变量，按事件阈值分段；跨零时返回最坏遗憾最小的候选或继续测量。事后完成时间只能用于评价，不能作为在线特征。

### 7.6 目标函数与平局

当前证书优化完成时间和。算法设计必须显式声明：

| 目标 | 可直接复用当前证书？ | 需要补充 |
| --- | --- | --- |
| 完成时间和 | 可以 | 当前模型与严格比较 |
| 平均响应 | 同一请求集、固定到达下等价 | 到达时刻不必相同；减去固定到达和再除以请求数 |
| 最大等待/P95 | 不可以直接换算 | 需要分布或逐请求界 |
| 共同完工时间 | 不可以直接换算 | 目标函数改变，外部性权重改变 |
| 加权请求优先级 | 仅可形式化扩展 | 重新证明权重和停止界 |

“整体改善”不能替代“每个请求改善”。每次实验至少报告目标请求、后继请求、总和、最大退化和认证覆盖率。

### 7.7 实现与复杂度边界

多次改选的认证必须声明参照的完整方案或延续策略、受影响请求范围、共同情景集合，以及各请求累计预算。计划级重新认证可用差值累加；分别相对旧方案认证再合并不能保证安全。固定后缀的单次证书不自动保证会继续改选的在线策略；但在实际状态上对同一基线延续价值逐步认证时，即使后续再次改选也可望远镜组合。更新基线则必须计入参照变化的桥接项。非单位速率的 KV 见证已经出现忽略桥接项会破坏改善账本的情况，但该批次没有最终个体退化；两类失败必须分开报告。即使基线一致，评分快照有误也会产生另一项成对模型缺项；固定基线的两请求反例已有实际 1 ms 退化，不能用未来服务成本区间替代活动状态区间。

实现上的最小安全接口是：输入快照、候选计划、成本估计和证书层级；输出动作、证书类型、未决候选数、最坏遗憾界和回退原因。事件减少只代表模拟工作量减少，必须另计证书构造、状态键、依赖扫描和缓存维护成本。

当前研究不把证书直接嵌入真实服务调度器。先用原模拟器核对完整轨迹，再测“证书计算时间 + 剩余模拟时间”是否小于完整求值。任何改动若改变队列、预取、交接或释放语义，必须视为新模型重新验证。

### 7.8 放宽模型的顺序与失效点

| 放宽项 | 首个可能失效的结论 |
| --- | --- |
| 未到达请求 | 已见后缀停止界和时间平移等价 |
| 第二条独立搬运通道 | 单通道向前阻塞上界与 FIFO 事件顺序 |
| 持久缓存/延迟释放 | 无外部性触发器、交接状态等价 |
| 计算减速或共享带宽 | 固定分支仿射性及工作量权重 |
| 后继也可改选 | 固定后继的工作量界和共同后缀公式 |
| 连续批处理 | FIFO 递推、固定后缀计算和单请求交接状态；固定请求集下响应和与完成和的恒等关系仍成立 |

每次只放宽一个因素，先构造最小反例，再决定是否重新证明。若失效只影响事件顺序，保留状态差分解；若改变目标函数或状态转移，则不能沿用旧证书。

### 7.9 当前验收清单

后续每个新策略或新定理都必须回答：候选集是否完整？可行性是否先判？状态键是否保留对象身份和剩余占道？未来请求是否被误当成已知？成本误差是否保留反事实相关性？事件相等时优先级是否核对？平局和 fallback 是否一致？目标是否仍为完成时间和？证书成本是否计入？对困难见证、公开留出、随机压力和最小反例是否分别复算？

验收应按具体子域判断，不以“覆盖清单全部列出”代替证明。两／三请求临界集、共享 KV 与检查点、特定按需前缀、正残余共同域和观测条件转换已有第 3 节证据；一般多请求、未知活动状态、多步误差域和真实覆盖仍有缺口。当前优先次序只由第 5 节维护。
