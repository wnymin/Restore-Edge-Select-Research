# 动态恢复边界策略：因素评估与优先级

评估日期：2026-11-18。本文按[因素取舍协议](recovery-research-protocol.md)给已有证据排序，不替代[统一研究报告第 5 节](dynamic-gpu-lookahead-report.md#research-next)的后续路线。B1–B3 [已验收](dynamic-cpu-completion.md)；本次复算既有 CPU 干预，不新增 GPU 实测，不修改模拟器或默认策略。

## 评估范围

Qwen3.5-4B、精确检查点、给定放置与候选、固定 FIFO 请求顺序、单计算槽与串行传输、共享 HBM 预取额度、首次入窗只选一次。策略只选边界。主目标是同一请求集到预填充完成的平均模拟响应；单请求代价、P95、决策开销另报。固定请求集和到达时刻下，最小化完成时间之和等价于最小化平均响应，不等价于最小化共同完工时间或尾延迟。

## 因素排序

影响按因素是否改变合法动作、关键路径或候选排序判断。量化代价区分 CPU 快照与 GPU 验证；下表描述要做的工作，不把未计时的开销写成实测。

| 优先级 / 因素 | 决策时输入及量化代价 | 影响、证据和当前取舍 |
| --- | --- | --- |
| **P0：合法依赖和可见请求** | 候选边界（token）、依赖与放置（对象 ID／层级）、已到达顺序与队首（请求 ID／序号）。CPU 可读元数据，候选依赖需遍历。 | 硬约束，不适用遗漏预算。非零候选须有完整 KV、循环和卷积历史；保留重算候选 0。在线只使用决策时已到达的信息。窗口内证书不能当成整条轨迹保证。 |
| **P0：净新增预留、共享身份与释放／重试** | 已计费对象并集、剩余额度及新增字节、持有者和释放事件（B／ID／事件）。CPU 易读，计算量随依赖和引用数增长。 | 高。额度扫描 56/144 组收益异号；共享只在 3/288 组异号，仍会改变去重、移交或检查点复制，不能省掉身份。[统一报告 §3.27](dynamic-gpu-lookahead-report.md)的 145 MiB 见证中，C 初次失败，但 B 开始释放后获准。预取失败不等于恢复不可行；保留重试及队首按需路径。 |
| **P0：就绪、在途身份、搬运次序和同刻规则** | 已就绪／活动依赖、在途对象、搬运顺序和同刻优先级（ID／序号／事件）。CPU 可读；若压缩需检查反事实后续状态。 | 高。在途搬运既可能挡路，也可能是候选需要的对象；在当前语义中不能抢占。[等汇总成本反例](evidence/dynamic-lookahead-transfer-order-7820.json)换对象顺序便使动作翻转。未证等价时保留逐对象顺序和事件分支。精确的剩余时长另见 P1/P2。 |
| **P1 首选：运行计算余量、在途残余与可覆盖搬运** | CPU 快照可得运行和在途残余（ms）；释放至下次消费的窗口由已见队列、缺失对象与必要复制推演。读取当前事件较轻，跟踪多个后继较贵。 | 高。C 到达扫描 13/96 组异号；在 70 MiB 见证中，浅候选早晚都能预取，收益却异号。[CUDA 配对](archive/gpu-studies/dynamic-gpu-joint-staging.md)中，相近的准入等待只有错过消费窗口才翻转整体排序。临界点或后继影响未排除时做完整可见窗口求值，不用“有同行”或“放得下”直接定动作。 |
| **P1 次选：搬运、复制和重算的候选成本差** | 缺失对象路径与字节、启动与检查点复制、后缀计算（B／ms）。CPU 查已校准成本并累加；真实活动期误差见 P2。 | 高但依赖工况。[离线对照](trace-oracle.md#留出回放结果)在已测 1× 和 8× 档无可降空间；受压档出现改善空间，低估成本也会错过改选。倍率不是硬件阈值，常规工况仍用 `local-cost`。 |
| **P2：真实活动残余和有效就绪延迟的不确定性** | 决策前能取活动标志、开始时间或进度；真实残余（ms）只能事后核对。GPU 同步及遥测成本尚未测；CPU 可先注入偏差。 | 疑似高、难量化。独占读盘中位数在 CUDA 留出漏判短窗口翻转；[GPU 归档审计](evidence/dynamic-gpu-interval-audit-7870.json)的 156 条后续读数仅支持释放至就绪延迟的归档覆盖，不是活动残余保证。保留共同时间与反事实相关性；状态未知保留离散分支，区间跨平局或个体预算时不认证。 |
| **P3：粗粒度代理只用于筛查** | 同行待完成标志、提交年龄（ms）、队列长度（请求数）、总积压（B／ms）。比逐对象前瞻便宜，不能判定具体就绪和后继消费。 | 单独排序证据弱。[A3](archive/gpu-studies/dynamic-gpu-a3-live.md)中标志使深恢复从 20/20 降为 10/20，但未测出比固定深恢复更低的响应和，目标响应仍比固定浅驻留慢。先消融重复代理，检查能否低成本识别无竞争场景；不替代 P0/P1。 |
| **禁止或暂缓** | 未到达请求、事后完成时间和离线标签仅作评价；多通道、持久驻留、时变带宽和连续批处理是模型扩展。 | 前者不代表影响低：相同快照、不同未来可有相反离线最优动作。后者没有本阶段遗漏损失保证，不纳入当前评分；扩展时一次只放宽一项。 |

P0 必须保留，但不要求每次全量推演。证明候选后续状态等价后可复用求值；不能以低平均损失豁免执行约束。当前没有因素获批在全适用域内忽略。

## CPU 固定动作配对复算

基于 [864 条干预记录](evidence/dynamic-cpu-interventions-synthetic-864.csv)。每次只变一个实验项；固定其他三个实验项、目标请求、比较边界和原基线边界，并排除不改选。一组内若 `mean_gain_ms` 同时严格为正和负（容差 $10^{-9}$ ms），记作异号。计数是**固定边界改选相对同一边界基线的收益符号变化**，不是全候选最优边界翻转率或生产发生率。

| 变化项 | 异号组 / 合格组 | 解释 |
| --- | ---: | --- |
| 预取额度（0/70/160/192 MiB） | 56/144 | 优先做容量临界测试；扫描跨度不能外推。 |
| C 到达时刻 | 13/96 | 可同时改变可见性和覆盖时间，不能归因给单一代理，更不能在线读取未来到达。 |
| 共享布局 | 3/288 | 确认会翻转；低异号数不证明共享可忽略。 |
| SSD 耗时倍率 | 不适用（0 个合格组） | 此夹具全档分组都发生基线换边界。成本敏感性另看已有估计误差留出，或做固定基线配对。 |

从实验仓库根目录复算：

~~~powershell
$rows = Import-Csv docs/evidence/dynamic-cpu-interventions-synthetic-864.csv
$factors = 'budget_mib','sharing','c_arrival_ms','ssd_scale'
foreach ($factor in $factors) {
    $keys = ($factors | Where-Object { $_ -ne $factor }) + @('target','boundary')
    $fixed = @($rows | Group-Object -Property $keys | Where-Object {
        @($_.Group.baseline_boundary | Sort-Object -Unique).Count -eq 1 -and
        $_.Group[0].baseline_boundary -ne $_.Group[0].boundary
    })
    $flips = @($fixed | Where-Object {
        ($_.Group | Where-Object { [double]$_.mean_gain_ms -gt 1e-9 }) -and
        ($_.Group | Where-Object { [double]$_.mean_gain_ms -lt -1e-9 })
    })
    "$factor $($flips.Count)/$($fixed.Count)"
}
~~~

## 策略取舍与升降级条件

1. **先做固定容量下的 P0＋P1。** 与同快照、同成本、同可见窗口、固定后继选择的完整求值相比，优先验证对象并集、逐对象前缀和释放状态能否在不改动作的前提下缩短推演。无外部性且满足等价条件时用 `local-cost`；受压且优化均值时以 `entry` 作在线对照。尚无计入开销后动态门控稳定优于 `entry` 的证据。
2. **P2 先验证会改变动作的误差。** CPU 分别扰动运行残余和在途残余，再做联合扰动；GPU 配对记录决策前状态和事后事件、另计遥测时间。两候选在共同情景内比较，同刻及其两侧单独核对。无法认证时回退基线；多步只有在实际状态、延续参照和累计预算一致时才可组合，不能累加相对旧计划的单步结论。
3. **P3 先消融，尚不删除。** 同快照先做单次干预，再用冻结窗口、种子和成本做闭环留出。覆盖正常／受压、容量临界、共享／在途交接、近似平局及 `容量 × 余量`、`共享 × 释放`。报告翻转率、平均响应、P95、最大单请求退化及计入采集、证书、剩余推演和回退的净收益。

**损失验收。** 精确简化在声明子域内要求零动作差（含平局）与零模型内逐请求完成差。允许近似时，先用校准数据扫描预算：单步参考完整可见窗口求值，闭环以完整策略为损失参照、`local-cost` 为收益参照；均值损失可按完整策略相对基线的零开销改善取 0%、1%、5% 作探索档，改善非正则只报绝对 ms。个体预算需独立扫描、留出前冻结；这些不是部署门槛。未认证的离线最优报区间。损失超预算、区间跨预算、无净收益或证据不足时，保留因素、缩小范围或回退，不称为“可控忽略”。
