# CPU 协作者成果入口

本轮继续研究固定执行器中的恢复边界选择。已完成动态状态配对、在线门控与留出评价，本次进一步检查选点开销、离线最优区间，以及尚未到达的请求带来的信息限制。全部工作使用 Python、仓库内成本表和公开请求轨迹，无需 GPU。

## 当前可以支持的结论

- **动态状态会改变改选收益。** 同一硬件成本下，容量、共享和到达时机能够改变边界选择的后果。[配对干预与门控](dynamic-cpu.md)记录单次改选对目标及后续请求的影响，留出包含 480 个配置。
- **较少推演仍需配合计时评价。** 动态门控减少了推演，但未稳定超过原有 `entry` 的净响应。[`entry-fast`](dynamic-cpu-entry.md)保持原窗口选点与执行结果，前两遍平衡换序复测分别减少本机选点耗时 13.65% 和 13.33%。整合版本第三遍为 15.78%，注入开销后的平均响应改善 0.0847 ms，最差重复轮次单请求额外等待 22.993 ms。[重复性与兼容性](dynamic-cpu-repeatability.md)同时保留变慢配置与单请求损失。
- **更紧的下界需要付出计算成本。** 新增必要搬运下界通过逐候选审计，但留出仅多排除 16 次推演，净收益为负。目前仍以 `entry-fast` 为实现参照。[搬运下界对照](dynamic-cpu-transfer-bound.md)
- **已确定边界的推演可以进一步简化。** `entry-replay` 在固定序列推演中直接提交已指定边界，并省去单位因子的有理数运算。144 个校准、480 个留出配置的零开销输出与 `entry-fast` 一致；留出平均选点耗时再降低 7.26%，注入计时后平均响应改善 0.0141 ms。新模式显式启用，保留原实现作对照。[推演优化与消融](dynamic-cpu-entry-replay.md)
- **高压力离线最优仍有未收敛区间。** 最宽的 12 个配置加深到 2,048 节点后，平均区间宽度由 1,876.04 ms 缩至 1,099.30 ms，尚未证实精确最优。[资源下界](dynamic-cpu-oracle-resources.md)略有收紧但计算更慢，[等价状态合并](dynamic-cpu-oracle-dominance.md)在这 12 个配置中未出现可合并状态。
- **部分误差来自未来信息不可见。** 一个三请求构造中，仅改变尚未到达的 C 的时间，两场景对 B 的可见历史相同，离线最优却要求不同动作。立即提交一次边界的确定性策略，至少一个场景的平均响应差距不小于 3.0601 ms；随机选择也存在 1.8826 ms 的最坏期望差距下界。[完整反例与适用条件](dynamic-cpu-unseen-arrival.md)

上述百分比属于本机 CPU 选点时间，毫秒结果属于事件模拟的预填充响应。既有结果不能直接解释为真实服务或 GPU 推理的提速。

## 先做不下载数据的验收

从仓库根目录运行，使用 Python 3.12 或 3.13。

~~~sh
python scripts/check_dynamic_cpu_delivery.py
~~~

该入口核对七份冻结输入的原始字节哈希，运行原手算与快路验收，审计 400 个必要搬运下界配置，再检查两种离线搜索模式。每种模式均比较 300 个三请求配置及 18 个五请求配置的穷举最优。另对 240 个精确时钟配置检查四种离线模式及三档节点预算，覆盖时间字符串、驻留对象、共享、降速和额度释放。新的固定边界推演也检查 840 个兼容配置和 240 个构造配置。最后重建 100 组未来到达干预，并逐项匹配归档的逐动作结果与反例。输出保存到 `outputs/dynamic-cpu-checks/`，不下载原始轨迹。

## 公开轨迹与计时复现

先按[数据说明](../data/README.md)准备百炼轨迹，再运行各报告内的命令。需要重测本机选点成本时，从[重复性实验](dynamic-cpu-repeatability.md)开始；需要复算窗口审计时，运行[搬运下界对照](dynamic-cpu-transfer-bound.md)。已有完整结果随 `docs/evidence/` 提交，无需为查看报告重跑计时。换机器时计时数值会变化，零开销选点与确定性响应应保持一致。

CSV 已明确设置为 LF 检出，避免 Windows 换行转换破坏冻结哈希。原始公开轨迹继续按上游大小和 SHA-256 验证。

模拟器另修复了到达时间的输入表示问题，统一转为有理数后排序，保证数值字符串与 JSON 数值可以混用、同时到达保持轨迹顺序。原有归档输入的排序不变。该项回归检查已包含在手算验收中，[精确时钟与离线区间检查](dynamic-cpu-exact-clock.md)记录补充覆盖。
