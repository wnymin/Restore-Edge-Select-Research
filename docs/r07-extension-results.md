# R07 扩展结果：冻结 `entry-replay` 的泛化边界

**结论：`entry-replay` 仍可作为冻结的主干对照，但“逼近离线最优”不是对模型和资源配比都成立的性质。** 原 4B 在新的轨迹窗口中继续拿到大部分可省时间；仅加快续算，或让 27B 结构载荷的检查点重新能进预取额度，均出现跨源窗的实质选点缺口。不能用 1× 或其他基线已最优的工况给泛化背书。

## 试了哪些变化

- 保留 `entry-replay` 的粗筛、固定后继、四步观察与单槽单搬运规则，零开销下与 `entry` 比对边界和完整响应序列。每个配置和自己的 `local-cost`、全轨迹离线界比较，不拿不同模型的原始延迟互相比名次。
- 18 个未参与既有判读的源窗，分别来自同一数据集的 Trace A、Trace B、Coder 三个文件。窗不重叠；三文件不是三个生产部署，同窗变体不算独立复现。主矩阵固定 128 MiB；只在 27B 另测 256 MiB 容量，不混入主矩阵。详见[预登记](archive/r07-process/r07-extension-preregistration.md)。
- 每个配置先算零开销完整轨迹，受预算限制时保留可证区间。含开销表现来自本机串行轮换六轮，比较每点配对差的中位数；P95 是逐窗请求响应 P95，不是合并所有请求后的 P95，也不是实际服务端到端延迟。区间跨预算、基线已经最优或当前执行器不支持都不能当成泛化通过。

| --- | ---: | ---: | ---: | --- |
| 4B 锚点 | 8 / 24 | 32,768 | 51,511,296 | 本仓库 4B 网格 |
| 只改 KV / 只改状态 / 只改续算 | 8 / 24，仅做因素干预 | 65,536 / 32,768 / 32,768 | 51,511,296 / 26,050,560 / 51,511,296 | 原样 / 原样 / 0.75× |

## 选点质量：有改善空间时才算接近率

留出 **738** 个配置，**713** 个认证了精确离线最优，冻结算法 **697** 个达到该最优。按基线分开看才有意义：**521** 个已证明基线最优，**193** 个有可证改善空间，另 **24** 个不能判断基线是否最优。1× 的 126 个配置均无改善空间。全部 738 点零开销 `entry` 和 `entry-replay` 的边界与完整响应序列一致。复核的 51,537 次选点中，39,360 次只有一个合法候选，1,427 次走隔离快路径，7,800 次粗筛后返回保底边界，2,950 次实际进入回放，共试跑 3,802 次。三类不兼容输入单独记录，不计入这些数。

下表只看 **原到达、自然共享**；每格汇总 18 个源窗（不是逐点接近率的平均）。接近率 =（基线均值 − 算法均值）÷（基线均值 − 离线最优均值）。有界但未认证时保留区间；不能证明分母为正时不报接近率。

| 模型 / 预取额度 | SSD 12×：接近率 | SSD 16×：接近率 | 解释 |
| --- | ---: | ---: | --- |
| 4B / 128 MiB | 100% | 99.996% | 16× 仍有一个约 0.142 ms 的绝对差窗 |
| 只改 KV / 128 MiB | 100% | 99.543% | 16× 单窗缺口 16.851 ms，均值掩盖局部联动限制 |
| 只改状态 / 128 MiB | 无空间 | 无空间 | 较小检查点使本批基线即可达到最优 |
| 只改续算 / 128 MiB | 99.991% | 95.256% | 16× 整组漏掉 4.698 ms；两个源窗分别漏 5.079 / 77.171 ms，且均超 5% 预算 |
| R06 合成 / 128 MiB | 无空间 | 无空间 | 不算支持跨模型泛化的强证据 |
| 合成层交替 / 128 MiB | 无空间 | 无空间 | 只有在扩展组合中，另有 Trace A 同速突发一窗出现可证差距 |
| 27B 架构载荷 / 128 MiB | 15/18 窗无空间；3 未认证 | 14/18 窗无空间；4 未认证 | 检查点约 146.8 MiB，连状态本身都进不了 128 MiB；不是算法胜利 |
| 27B 架构载荷 / 256 MiB | 99.928% | 97.191–98.748% | 16× 整组漏 6.354–14.482 ms；两个源窗可证漏掉至少 19.361 / 82.073 ms，且均超 5% 预算 |

27B 单列容量探针使平均可暂存非零候选由 0 变为 21，说明“硬件额度与模型载荷的相对关系”直接决定有没有可优化的竞争。保护个体等待、改粗筛、扩窗口或联合重选都不是本轮交付；它们可能改善选点，也可能引入均值或计算开销，不能从单点见证推出净收益。

## 反常点：什么复现了，什么没有

| 机制 | 扩展中的证据 | 判读 |
| --- | --- | --- |
| 四步以外的已到达请求影响当前选点 | 7 个配置，Trace B 的 470、475 两个新窗；只改当前一步最多省 0.396 ms | 机制复现，但未复现旧窗 16.693 ms 的量级；未证明扩大观察范围的净收益 |
| 固定后继限制当前选点 | 6 个配置，Trace B 的 471、473、474、475；其中 27B、256 MiB、16× 的 474 窗只改当前一步就省 82.073 ms | 局部缺陷跨窗、跨成本配置复现；原 12× 锚点的工况没有被这些结果替代。扩大联合搜索的运行开销未测试 |
| 粗筛过早返回 | 2 个配置，均为 Trace B 470；保持四步和固定后继只强制当前替代，整窗分别改善 5.079 / 4.733 ms | **新反常点**，不是剪枝失效；单源窗，暂不推为普遍缺陷 |
| 未来信息／未归因 | 扩展中 16 个配置有可证离线差；其中 Trace A 115 的合成层交替、16× 同速突发在 isolated 路径产生约 0.156 ms 缺口 | 原短轨迹的未来信息反例仍成立；不能把这个新窗的缺口或旧的未决项自动归给未来信息 |

原 4B 的同速突发与共享配对，在扩展窗的零开销离线缺口上都没有差异，不复现旧批次同速突发在 12×／16× 的异号效果。合成层交替在 16× 的同速突发比均匀增加 **0.00864 ms** 的组均缺口（一个窗），去共享没有改变该模型原到达组的缺口。27B 主矩阵的“模型 × 突发／共享”区间跨零且较宽，**证据不足**。这些结论只针对已测的离线差，不等于突发、共享对排队时间或搬运量没影响。

## 含选点时间：均值和 P95 仍会掩盖个体代价

738 个配置中，没有配置的六轮配对中位数比 `local-cost` 的均值慢超过 1 ms，或 P95 慢超过 10 ms。但 **91/738** 个配置（15/18 个源窗）有同一请求在至少四轮多等超过 10 ms；零开销下也有 **92/738** 个配置超过这条个体阈值。计时回放观察到的最大个体额外等待为 **36.263 ms**，位于 27B 架构载荷、256 MiB、16× 的条件。这些计数是实验配置数，不是实际服务中的发生概率。

在有重复超阈且零开销同样超阈的配置里，按源窗和模型保留单点因果见证，共复算出 **48** 条，覆盖三个文件的 **15** 个源窗。例如 Trace B 471 的 27B／256 MiB／12×：受影响请求本身未改边界，单独把后续请求的 `1024` 改回 `512`，其 **25.925 ms** 的额外等待归零，但整窗平均响应变慢 **118.281 ms**。这说明个体保护与总均值确实可能冲突，不宜用提高均值来豁免尾部。

原 4B／128 MiB／16×、原到达自然共享的 18 窗，计入决策时间后窗口均值和 P95 的配对差平均仍比基线低 **199.967 / 399.882 ms**；但 11/18 窗有反复超阈的个体。`entry-replay` 每窗累计决策时间平均约 **3.694 ms**，比同策略的 `entry` 少约 **1.104 ms**；这是本机回放中的实现差，不是 GPU 或真实服务速度。
