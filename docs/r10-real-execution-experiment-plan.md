# R10 | entry-replay 的真实执行与服务收益验证

2026-11-25 拟定，同日本地分线启动，2026-11-26（JST）完成本机范围验收，结果见[本地验收记录](r10-local-acceptance.md)。目标是在有限显存暂存额度下，测量冻结的 `entry-replay` 相对 `local-cost` 在真实模型执行中的净收益，并确认收益出现的条件。同一执行器中的选点对照是主实验。完整服务和远程 GPU 用于检验结论能否迁移。

## 1. 研究问题与现有条件

1. **真实模型能否执行原策略？** 用决策时可见的状态选边界，随后真实恢复注意力 KV、循环状态和卷积历史。检查暂存容量、对象共享、搬运就绪和消费时机是否符合冻结语义。
2. **原生 I/O 下有没有净收益？** 在相同请求流和候选上，只切换策略，比较到达至预填充完成时间。状态采集、搜索及发布、搬运和排队均走真实执行路径。若常规工况没有收益，估计观测到的效应范围，再用受控实验定位何时出现收益。
3. **迁移到更真实的服务后还成立吗？** 测量 decode 和合批引入的影响，再用一张远程 GPU 复核代表性工况。分别报告能归因给选点的收益与整套服务的表现。

| 环境 | 用途 | 执行约束 |
| --- | --- | --- |
| Windows 11、i9-13980HX、RTX 4060 Laptop 8 GB、32 GB RAM | 接口验收、成本校准、机制对照、主实验和首轮服务实验 | 主模型为已跑通的完整 Qwen3.5-4B Q4_K_M。以归档 llama.cpp b10923、`8a56aedd6`、Vulkan 为起点。实测权重、工作区、活动序列、暂存及主机缓冲的峰值后确定预算。从 512–2,560 token 的已有区间起步。内存池超预算时先缩短上下文或减少配置，按相同规则重跑配对。 |

已有两类可复用证据。真实状态夹具验证了同步暂存、序列移交和续算，CUDA 缓冲夹具验证了设备事件和容量翻转。现有 `/slots` 只能观察部分槽状态，不能提供排队请求候选、对象级暂存和预取发出时刻，用来同步轮询还会扰动延迟。完整 4B 用于主实验，16 层衍生权重的流式失败保留为历史诊断。立项时可复用的接口和锚点见[真实状态暂存](archive/gpu-studies/dynamic-gpu-model-stage-study.md)、[CUDA 夹具](archive/gpu-studies/dynamic-gpu-joint-staging.md)、[R07 本机调度](r07-live-scheduling-results.md)和[R09](r09-decision-time-budget-results.md)。

## 2. 共同控制与执行顺序

`GPU-01 → GPU-02 → GPU-03 → GPU-04 → GPU-05`。`DATA-01` 可随本机准备进行，`GPU-04` 依赖其冻结清单。`REMOTE-01` 使用通过本地验收的可移植实验包。`INT-01` 汇总通过、负结果与未覆盖项。

主实验固定请求 FIFO、单计算槽、单串行搬运、共享设备暂存池、原预取窗、首次入窗提交一次、候选与初始放置。两条策略共用对象标识、成本表、状态视图、同刻规则和真实执行器。`entry-replay` 冻结现有可见窗口和固定后继规则，额外搜索预算为 0 ms。`local-cost` 使用同一份独占搬运、必要复制和续算成本。全部重算与最长合法前缀作为参照，原版 `entry` 用短用例核对选择与实现开销。引擎原生缓存机制若进入服务对照，按系统配置差异报告。

所有真实计时臂相同检查点、请求及输出上限、固定种子和设备设置。到达用独立的开放环客户端驱动，按绝对偏移提交，避免上一请求变快导致下一请求被提前发送。记录计划和实际到达，公布漂移、错误、超时及重试。使用同一初始快照和预热规程，按实验块随机安排 AB/BA 或轮换多臂。检查点准备在计时前完成，单独计入准备时间、空间和 I/O 台账。接电并记录温度、频率、功耗模式和后台活动。运行前固定异常排除条件，按完整配对保留运行结果及排除理由。

主机用单调时钟记录接收、资格、快照、选点开始／发布、容量等待、预留、I/O 发出／就绪、消费、预填充完成和首 token。设备侧用事件记录复制与计算，并核对主机与设备的时间映射误差。两套时钟无法可靠对齐时，只比较同一时钟的区间。额外记录检查点和 KV 的逻辑字节、分配字节、实读量、设备占用、复制量、复用命中与各类回退。使用进程内事件缓冲，配对核验追踪对时序的扰动。

## 3. 实验逐项设计

### R10-GPU-01 真实执行接口与恢复正确性

从真实状态夹具和已有设备事件夹具各复用可工作的部分，优先接入同进程的 llama.cpp 接口或最小的内部执行钩子。实现一个真实动作通路，先跑单请求全重算／浅／深三臂，再加入前驱和后继。每个边界显式列出 KV 块、循环状态、卷积历史和放置。选点输入须包含已到达队列、候选依赖、预留额度、共享身份、在途搬运与计算进度。单独验证逻辑计费与实际设备分配、交接后消费者使用的缓冲、写时复制及释放顺序。整槽加载可用于路径和数值诊断。若同进程接口只支持整槽复制、强制同步或无法表示只读对象共享，则该路径只验收它确实覆盖的机制，主 A/B 保持待执行。

用全重算作数值参照，固定后续 token 历史，在 512、1,024、可装入的较深边界分别从 RAM、SSD 恢复。校验检查点完整性、前缀身份、各张量形状和实际消费深度。比较后续至少 8 个位置的 logits 误差、贪心输出与固定 token 的续算结果。浮点容差由同后端全重算、不同 batch 切分的重复控制先锁定。超出容差和 token 不一致逐例保留。加入缺 KV、错误检查点、容量等于／略低于对象并集、共享消费、在途接管、前驱先完成和同刻冲突夹具。每个短用例记录两策略可见快照，离线按同快照复算动作和平局，另核对实发动作。改动未来到达后，未来请求尚未可见前的相同快照须得到相同选择。

**验收与停止点**：状态正确、动作确实由在线决策驱动、无超额度和遗漏依赖、前后事件能核对、两臂执行语义一致。配对追踪开启／关闭，若扰动达到预定最小效果的量级，先缩减追踪或隔离诊断轮。若恢复钩子无法支持等价语义，交付最小失败例和可支持的范围，暂停 GPU-04 主 A/B。已有 HTTP 脚本可运行强制动作配对作为机制证据。起点见[状态夹具](archive/gpu-studies/dynamic-gpu-model-stage-study.md)和[本机调度脚本说明](r07-live-scheduling-results.md#复核)。

### R10-GPU-02 原生成本、资源预算与运行噪声

测出三个路径的独占与并行代价。RAM 路径测主机缓冲到显存，SSD 路径分开实盘读取、主机缓冲等待和上传，设备内复制单列。SSD 以对齐的无缓冲读或可核查的冷读机制为主，用系统或设备 I/O 计数核对实读字节。页缓存热读独立标注，SSD 经 RAM 中转时注明路径。每种路径先覆盖 8／16／32 MiB KV 和实际检查点尺寸，再测短／长两类后缀的单跑和与搬运重叠。用相同输入的无同行／有同行臂测 CPU 提交、传输完成和计算变化，验证异步操作是否真正重叠。独占成本输入两条策略，在校准时确定重叠模型，并在新的形状上报告绝对误差、排序错误及误差范围。

预热后每路径×尺寸先做至少 12 次配对测量，针对临界或高波动点追加至 30 次。用相同输入和策略的 A/A 配对估计自然抖动，保存每块均值绝对差。按真实对象分配和对齐后字节定暂存档：一个冷候选装不下、能装一个但不能装典型两对象并集、能装两对象。放不进预取额度的候选仍可在队首按需恢复，前提是执行预算能容纳其依赖。实际无法满足驻留空间的档位单列。显存峰值包含活动序列和工作区，RAM 峰值包含暂存源、页缓存和锁页缓冲。历史 65.125 MiB 单候选和 130.250 MiB 两候选并集作为定位起点，实测后重新定档。可复用[现有扫描入口](r08-model-capacity-results.md)和[分段测量口径](archive/gpu-studies/gpu-boundary-restore.md)。

**验收**：冻结模型和后端哈希、成本表、设备与主机内存上限、原生 I/O 验证记录、各档重复差和同策略噪声。若只能测页缓存热读，则仅在报告中给热路径结果，并保留真实 SSD 冷路径缺口。

### R10-DATA-01 负载构建、分割与预登记

构建三种输入。第一类是容量临界、同行延迟和非竞争负对照等合成任务，供资格验证与机制诊断。第二类以 Bailian 到达与前缀复用关系为骨架，使用可复算的词元或文本映射合成实际提示。先检查映射后的前缀共享、长度、候选有效和到达关系，公布截断、跳过和映射造成的偏差。百炼轨迹含模板后的输入哈希，实际提示按哈希前缀关系构造并重新分词核对，记录无法保持的前缀关系。该组标为轨迹驱动的重建负载。第三类准备有授权的多轮对话与 coding／agent 文本或任务回放，按完整会话或任务划分，固定历史、聊天模板、输出上限与到达方式。短正确性控制可强制后续 token，服务测试用实际解码。原始来源、合成部分和输出差异分别登记。

校准先取 4 个单独的运行块，覆盖单请求、常规到达及容量竞争。主留出目标为两类负载各至少 6 个源块，每块起步 64–128 个请求，按源文件、区间、会话与历史窗核对排重。旧反例只用于校准。确切块数和负载档位由先导耗时与方差确定，正式留出前冻结策略、输入哈希、运行顺序、主指标、最小收益、尾部预算和停机规则。每个源块多次重跑用来测量波动，多个配置共享同源块时按源块聚合。缺独立文本负载时仍可验收范围较窄的轨迹重建结果。数据准备见[原始轨迹清单](../data/README.md)。

### R10-GPU-03 强制动作的真机机制对照

对 2–4 个请求构造一个相同决策快照，将目标强制为浅／深，其他边界固定。分别改变暂存并集能否装下、对象是否共享、前驱剩余工作、SSD 是否正在占道。每组含单请求隔离或宽容量负对照，单次只动一个因素。先用短用例确认机制，再用新提示与种子复做。真实恢复耗时与续算耗时单列，比较目标、前驱、后继的完成时间与总和。另用原生路径与一个冻结的受控争用条件做同输入配对，记录瓶颈发生在读盘、上传、调度还是准入。在原生路径检测不到翻转时，保留负结果，并用实际参数判别缺少竞争、成本模型错估或设备执行语义不同。

建议选 6 个条件，每个条件至少 8 个独立提示块，各做随机顺序完整配对。条件数可根据资格实验缩减，需保留宽容量、紧容量和共享反事实。输出逐事件瀑布图与候选分差。小规模可实际运行全部边界组合，报告重复测量下的最优候选及差异范围。模拟离线最优、真机已测候选和全轨迹最优分别标注。

**验收**：事件证据能解释哪一段等待改变了排序，或说明预期机制为何没有显现。强制动作结果供归因和选择诊断，主策略收益由 GPU-04 判定。

### R10-GPU-04 真实模型闭环主实验

先运行 `entry-replay` 与 `local-cost` 在原生 I/O 的配对。主配置用混合 RAM KV／SSD 检查点、一个典型两候选并集装不下的暂存档，以及由仅用基线的先导定出的争用负载。低负载宽额度、RAM 主导、SSD 独立冷读和其余暂存档放入诊断子矩阵。负载扫描按低、近饱和、突发三种条件选锚点，分别标记实际到达率和队长。开启受控 I/O 限速或背景争用的组独立运行，报告实测有效速率、并行度和方式。若使用延迟注入，按软模拟 I/O 记录。可在各类选 2 个块补测全重算与最长合法前缀。主实验两臂每块先做 5 次完整配对，重跑数以封存清单为准。按 12 块 × 2 臂 × 5 轮计，主配置共 120 次块运行。先用 2 块估算时长和存储，诊断矩阵按代表点安排。

主指标为到达到预填充完成的均值，定义正收益为 `local-cost` 减 `entry-replay` 的时间。先取每块内配对差，再跨块汇总。公布每块差值、P50／P95、慢超预算比例与最大个体等待、失败率、实际快照和选点耗时、暂存峰值及总搬运量。主负载如果实际有流式首 token，同时报告 TTFT 作为外部核对。P99 仅在尾部样本量与独立覆盖足够时报告。异常挂起、OOM 或失败均进入可用性账，延迟分析另列可配对样本，并做失败按超时上限计入的敏感性对照。报告每源结果和去掉单一来源后的方向，独立性不足时使用描述区间。

**建议的主验收线**在正式留出前登记。原生混合路径的平均收益同时超过 5 ms、基线均值 3% 和先导 A/A 每块均值绝对差的第 90 百分位，两个预声明负载类别均呈正方向。P95 非劣界暂定为较大者 10 ms 或基线 P95 的 5%，错误率差与逐请求等待预算在先导后逐一锁定。样本足够时，按预登记的独立采样单位做聚类区间，要求平均收益下界越过最小收益线、P95 退化上界低于非劣线。样本不足时报告点估计与效应范围。先导可据任务尺度更新候选阈值并记录原因，留出后维持原判据。自然条件无收益、只在受控条件有收益、可用性失败和证据不足均可结项，分别给出适用域。原生证据薄弱时只投入能区分瓶颈的后续对照。

2026-11-26 增补诊断，保留在主留出之外。诊断锚点和五对补测分别见[原生校准](r10-native-cost.md#预填充诊断锚点复算)及[补测登记](../configs/r10-prefill-diagnostics-v1.json)。

### R10-GPU-05 完整服务与可持续负载

在通过接口资格的 4B 执行路径增加流式解码，先固定合批关闭，随后只启用已有连续合批，分别对照两策略。如果后端支持且仍有机制问题，再单列 chunked prefill。用固定开环请求流，选择短输出和带长输出同行两组，预设低负载、拐点附近和略超过拐点的请求率或固定窗口。两臂配置、SLO 和过载策略相同。先用 2 个代表性块×3 档作试跑，形成可复现实验后再扩至未参与调参的负载。服务若需改变原计算顺序、预取资格或可见状态，标记为规则迁移，逐项记录，不与 GPU-04 合并估计。

客户端 TTFT 从提交到收到首个可见 token，服务端首 token 与预填充完成独立记录。报告 ITL、TPOT、吞吐、队长、失败和全部请求为分母的 SLO 达标率。有效吞吐是在单位时间内同时满足预定 TTFT、解码间隔及成功条件的请求数，超时和拒绝单列。响应按固定采样与输出上限施行，记录实际输出长度和 SSE 合并粒度。没有 token 级时钟时，明确报告流式片段间隔。若未取得生产 SLO，用校准前声明的实验目标画负载曲线。验收需在至少两类留出负载上报告服务曲线、单请求尾部与回退情况。仅支持整槽强制动作的引擎可以复用历史对照诊断 decode 干扰，策略接管收益维持未覆盖。

本机完成[单槽服务留出](r10-native-service.md)。共享暂存的双序列正确性按规则迁移单独验证，连续合批策略性能未覆盖。

### R10-REMOTE-01 A100／V100 代表性复核
