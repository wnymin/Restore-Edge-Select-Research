# R10-GPU-03 | 原生强制边界机制先导

固定完整 Qwen3.5-4B、同一个原生对象目录和单计算槽 FIFO。每臂依次处理三条请求：前驱从头算 768 token，前驱的首个设备计算标记提交后才发布其余两条；目标序列 1,088 token，强制从 512 或 1,024 恢复；后继序列 576 token，固定从 512 恢复。每臂先做统一形状预热，日志记录管线调用，以便区分编译与调度间隔。两份目录共 5 个检查点均通过完整状态及 8 个续算位置校验。运行时只比较同块的浅／深两臂；目标选点前的候选状态结构相同，主机实际时钟差保留。

先导在共享／独立两个目录各试紧容量 82.25 MiB 和宽容量 160 MiB。共享条件仅改变后继前缀身份，其余长度、输入安排及两臂动作保持相同。每格各跑一对，用于事件定位。独立提示和新控制的复测见下文。正值表示 1,024 臂响应较快。

| 条件 | 前驱响应差（ms） | 目标响应差（ms） | 后继响应差（ms） | 三条和（ms） |
| --- | ---: | ---: | ---: | ---: |
| 共享，82.25 MiB | 30.46 | 276.81 | 272.67 | 579.93 |
| 共享，160 MiB | -28.25 | 201.71 | 196.29 | 369.74 |
| 独立，82.25 MiB | -10.15 | 213.35 | 182.36 | 385.56 |
| 独立，160 MiB | -6.65 | 341.04 | 348.15 | 682.53 |

共享紧档中，两臂都在前驱完成前搬齐目标对象。浅臂提前为后继预留同一套对象；深臂在目标释放暂存后才为后继预留，携带原地 KV，但另读一次后继的 SSD 检查点。该额外读在目标短后缀完成前已就绪，未拖到后继的关键路径。独立紧档不能在前驱运行时为后继同时预留；两臂均在目标完成前搬齐后继对象，深臂剩余余量约 38 ms。两种宽档的两臂均在前驱完成前预取完毕。四对都没有在计时段观测到新的 Vulkan 管线创建。宽档深臂仍获益，支持“减少续算”解释。固定动作的前驱仍观察到 6.65–30.46 ms 的绝对差；不能用每格一对运行估计因素交互大小。

四个工况的原始 ZIP 与对应 JSON 摘要，以及下文有无 700 ms 等待的两份原始 ZIP，均可从本节归档一次解出。成员名沿用各工况标识 `shared-tight`、`shared-wide`、`private-tight`、`private-wide`、`shared-soft0` 和 `shared-soft700`。[机制先导归档](evidence/r10-native-mechanism-pilot.zip)

另预登记一个受控工况：共用紧档输入和真实无缓冲 SSD 读；在主机确认读完后、提交设备上传前，在串行搬运通道中保留 700 ms。原生 SSD 时长、人工等待、设备上传分别记录。固定动作模型预测相较原生工况，目标仍因续算较短而快，但深臂的后继会在额外一次 SSD 读的人工等待上转慢，三条响应和的方向翻转。350 ms 仅为模拟中间点。该诊断的时间不能称为真实 SSD 变慢，且不进入留出成本或吞吐。[受控预测与输入哈希](evidence/r10-native-mechanism-soft-forecast.json)。

受控配对观测到了翻转。浅臂只执行一次人工等待（701.05 ms）；深臂执行两次（700.17、700.43 ms），其中后继在目标完成约 27 ms 前已读完 SSD，但其上传就绪仍比目标完成晚约 684 ms。深边界把目标响应缩短 291.16 ms，却让后继慢了 403.76 ms；两条响应和已多花 112.60 ms，加上固定前驱的实测抖动后，三条和多花 224.32 ms。前驱抖动较大，故以设备事件和目标、后继的反向变化解释翻转；这一对不用于估计翻转临界点。[受控配对逐事件摘要](evidence/r10-native-mechanism-shared-soft700-summary.json)。

同一二进制去掉延迟后，反序重复该对，深臂仍节省 611.37 ms，总和的符号与早期原生配对一致。两组的真实 SSD 就绪、人工等待和续算可在[逐事件图](evidence/r10-native-mechanism-wait.svg)上对照。[同版本原生对照摘要](evidence/r10-native-mechanism-shared-soft0-summary.json)。

第二套提示复现跨过串行通道等待后的符号翻转；目标继续从深边界得益，但后继响应变慢约 512 ms，超过目标节省。改变共享、前驱长度或发布时点，在这几对原生运行中均未独立造成翻转。SSD 在途是发布时控制器可见的状态，不能当作物理 SSD 结束时刻：完成可早于下一次控制器轮询。每个单元只有一对，不能估计因素效应大小或自然出现频率；也没有运行算法选点。[复测逐事件摘要](evidence/r10-native-mechanism-replications-summary.json) · [七对原始记录](evidence/r10-native-mechanism-replications.zip)。

用主实验冻结的成本表，在七对强制运行实际记录的 42 个快照上复算两种选择，隐藏未到达请求。42 个快照均无分歧；14 个目标快照都选 1,024 token，其中 12 个记录前驱计算活跃、2 个记录搬运在途。注入的 700 ms 改变执行路径时间，复算时没有把它当成策略事先知道的成本。真实的强制边界翻转仍是机制证据；在这些快照上，两个策略不会自行选出浅／深对照的不同动作。后继快照还继承了强制边界形成的状态，不能把 42 个快照当作独立部署样本。这组复算不读取主留出，也不改变正式判据。[动作及输入指纹](evidence/r10-native-controlled-choice-replay-v1.json) · [复算工具](../scripts/gpu/analysis/explain_r10_controlled_choices.py)。

进一步检查这 14 个目标快照：每个都有 0、512、1,024 三个合法候选。固定所有已观测时刻与状态，只乘算两策略看到的 SSD 路径成本和预填充耗时，RAM 与设备内复制成本不变。42 个组合中仅两格改选：SSD ×8／预填充 ×0.25，以及 SSD ×16／预填充 ×0.5。在这两格中，8 个快照上 `local-cost` 选全重算、`entry-replay` 选 1,024，另外 6 个快照上双方都选全重算。预填充按本机原成本时，扫过的 SSD 倍率从 ×0.9 到 ×16，双方在全部 14 个快照上都选 1,024。这表明这些已测状态里的不分歧由当前成本与快照共同决定。这里只扫描有限格点，不能当作连续阈值，也未让这些成本改变真实到达、预取就绪或后续快照，不能据此估计换硬件后的策略收益。[42 格敏感性结果](evidence/r10-native-controlled-cost-sensitivity-v1.json)。
