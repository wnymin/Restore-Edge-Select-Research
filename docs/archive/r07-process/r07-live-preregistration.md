## 本机固定矩阵与可观测性复查

主矩阵在接口烟测后锁定：4B、512 batch 的连续合批开/关共享同 8 个配对提示块；4B 与 16 层衍生配置分别用 256 batch 和各自 8 个新提示块留出。留出目标长度 1792，设计目标长度 1536。每服务进程先跑 1 个完整热身块（归档、不入统计）；请求内容用固定种子生成，配对内保持一致，模式与边界顺序随机。不同批次预算与留出提示变化同时发生，不用于单独归因 batch 效应；合批开/关按两个进程固定顺序运行，跨进程差异只作机制线索。

烟测确认整槽接口返回了精确长度，但未暴露共享 HBM 暂存、转移就绪及全队列视图。另在 4B／连续合批／512 batch，用 8 个新提示块随机配对七种动作：同行独跑、短/长两边界各自的只恢复、恢复并续算但取消 `/slots` 探针、恢复并续算且保留探针；均从同行首 token 后开始动作。这个补充用于分开「恢复本身」「后续计算」和「观察对时序的扰动」，不是冻结策略 A/B，也不标成 HBM 配额实测。观察者对照先登记，结果不用于改主矩阵。

随后核对聚合 `/metrics` 与 `/slots`：让两个槽持续解码，再依次向一个已忙槽提交两个新请求，比较 0/1/2 个待处理请求的可见信息，并等实际响应完成。仅凭全局排队数不能补出请求身份、顺序或候选依赖。该资格探针独立于主矩阵，不把探针延迟计作策略开销。

16 层留出的初次热身遇到 SSE 在第 58 个片段后无完整结束标记，保留原运行片段与服务日志。重新运行时仍用原定种子、预算和提示，不改变生成协议；仅让采集器为失败动作也写一条记录，避免丢失后续配对。延迟统计只取双边完成的提示块，失败另算分母，不能从完整子集推到该配置的可用性。

记录到 SSE 终止事件后，增加失败定位负对照：将 16 层留出八个原同行提示原样取出，在 4B 与 16 层的 256-batch 服务上单独流式生成 64 token，不发恢复或第二请求；收齐结束或原样记录终止错误。该诊断不修改原矩阵或把失败删掉。
