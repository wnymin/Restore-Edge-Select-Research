# 精确时钟与离线区间检查

模拟器对时钟使用有理数，但此前请求排序直接比较输入的 `arrival_ms`。当时间写为字符串 `"0"`、`"10"`、`"2"` 时会按字典序排成 0、10、2，破坏事件时钟的顺序；混用数值与字符串还会抛出类型错误。现统一转换为有理数后排序，数值相等时保留原轨迹顺序。手算验收新增四类表示对照，分别覆盖纯字符串、混合类型、分数和等值的不同写法，并比较逐请求基线、自适应与穷举结果。

## 离线下界的补充覆盖

既有的三请求构造与公开轨迹未覆盖所有精确时间、额度释放和初始驻留组合。本轮用固定种子 20261122 生成 240 个三至五请求配置，在可穷举规模上检查离线搜索的证书。输入交叉以下变化：

- 到达间隔包含 0、1/3、1、12、50 ms，部分轨迹先打乱输入顺序，再按数值与稳定同分规则恢复服务顺序。
- 预取窗口为 0、1、2、4 个后续请求，额度为 0、70、128、160、192 MiB，释放规则覆盖开始、结束及带分数延迟的定时释放。
- 请求使用单一或交替两组前缀，组内共享对象；部分对象初始驻留，RAM/SSD 成本分别变化，并加入计算与传输的有理数降速、共享状态复制成本。CSV 中的 `prefix_layout` 标明前缀布局。

每个配置先枚举全部合法边界序列得到精确最优，然后分别检查原下界、加权资源下界、状态合并及两者组合。每种模式使用 1、8、1,000 个节点预算。要求每个下界都不超过精确最优，每个上界都有完整方案回放支撑，增加节点后区间单调收紧，最终必须收敛到穷举值。合计保存 2,880 条检查记录，全部通过。

在 1,000 节点上限的每配置完整搜索中，原模式合计展开 1,778 个节点，状态合并模式为 1,620 个，合并 195 个被支配状态。此处统计搜索节点，未计时；它说明构造配置上存在可合并状态，不能改变高压力公开轨迹中未找到相同状态的结果。

该实验检查正确性和证书，不用随机配置的比例代表生产负载，也不把较少搜索节点直接解释为运行提速。[精确分数与逐配置检查](../../evidence/dynamic-cpu-exact-clock.csv) · [种子与输入版本](../../evidence/dynamic-cpu-exact-clock.json)

## 复现

~~~sh
python -m scripts.cpu.dynamic.study_offline_invariants --seed 20261122 --cases 240 --out outputs/offline-invariants/audit.csv
~~~

从仓库根目录运行即可，不需要公开轨迹。`python -m scripts.validation.check_dynamic_cpu_delivery` 也会重建这份结果并与归档逐项比较。若发现失败，脚本会把该配置完整写入相邻的 `.failure.json`，便于直接定位输入。
