# 保留选点结果的窗口搜索提速

前几轮的动态门控可以减少推演，但它有时会跳过影响后续请求的恢复边界。这轮以原有 `entry` 为对照，测试能否保持相同的恢复边界和事件结果，同时降低搜索开销。

## 两种实现

| 策略 | 与 `entry` 相比的改动 |
| --- | --- |
| `entry-fast` | 使用已构建的对象搬运与后缀续算表，避免选点和推演时重复换算。在队首只有这一条已到达请求、当前无在途搬运和额外预留、设备驻留等于初始状态时，按独占成本直接选点。 |
| `entry-progress` | 沿用上述优化，并在候选推演的推进过程中检查下界。如果已完成请求和剩余请求的乐观完成时间之和已经无法击败当前赢家，提前结束这一候选的推演。 |

孤立请求的窗口内只有它自己。所有候选都从同一时刻开始，无并发快慢变化，其完成时刻是相同的当前时间加上各自的搬运、复制和续算成本之和。原 `entry` 的逐请求回退也使用这个独占成本及同样的同分规则。

过程下界使用实算的已完成时间、FIFO 后缀计算，以及队首缺失对象的必要搬运。传输通道只有一条。队首仍需加载时，在途工作要先走完，若在途对象本身属于缺失集合则扣除重复计费。超过当前最好成绩，或等分但按边界长度也无法胜出时，才可终止。过程检查本身也有开销，因此单独比较它和只加缓存的版本。

两种实现都对单传输通道、固定且已知的搬运成本和普通窗口筛选启用。涉及分通道、主机分段留存、时变费率、预测误差或自定义观察的配置继续由原 `entry` 处理。

## 回放对照

先重放此前 1,344 个配置，逐项比较选点、每个请求的完成时刻、等待、搬运时间线、峰值容量等输出，搜索计数单独统计。再在第 79、80、81 窗运行三条轨迹、两类布局与间隔、两档预算、两种搬运压力作用范围和四档倍率，共 288 个配置。每组在固定时间线上计时三次，另做三次将实测决策耗时注入模拟时钟的对照，随机顺序的种子固定为 20261117。

历史的 1,344 个配置与新一批普通候选下的 288 个配置均逐项通过等价检查。下表统计新一批的 216 个受压配置。选点用时包含一个配置内全部请求的选点时间，净改善则是将开销注入模拟后相对旧 `entry` 的平均响应变化。

| 实现 | 选点用时 | 推演事件数 | 净改善 | 净改善大于零 |
| --- | ---: | ---: | ---: | ---: |
| `entry` | 9.45 ms | 54,766 | — | — |
| `entry-fast` | 8.29 ms | 54,766 | +0.117 ms | 152 / 216 |
| `entry-progress` | 9.22 ms | 53,065 | +0.039 ms | 142 / 216 |

普通候选下，`entry-fast` 的选点用时减少 **12.3%**，推演次数和事件数与 `entry` 一致。过程剪枝虽然少走了 1,701 个事件，但检查本身抵消了大部分时间收益。离线搜索在普通组的 288 个配置中认证了 136 个最优，剩余配置给区间。以上开销为本机 Python 计时，净改善也只对应这套 CPU 模拟。

再用第 82、83 窗的历史匹配检查点构造 96 个配置。每个请求允许全部匹配边界，最多 6 个候选。两种实现再次逐请求等价。原 `entry` 的选点时间为 8.68 ms，`entry-fast` 为 7.27 ms，下降 **16.3%**。注入时间后平均响应改善 0.183 ms，96 对中 66 对较快。过程剪枝减少了 956 个推演事件，但选点时间为 8.38 ms，高于只加缓存和孤立请求快路的版本。[加密候选逐配置结果](../../evidence/dynamic-cpu-entry-dense.csv) · [加密候选汇总](../../evidence/dynamic-cpu-entry-dense-summary.csv) · [参数](../../evidence/dynamic-cpu-entry-dense.json)

两批结果支持在对应单通道模型中使用 `entry-fast`。其收益来自执行同一策略时减少算术和状态采集开销，原有窗口搜索的可见范围与优化目标继续限定它能识别哪些改选。过程剪枝保留为开销对照。

后续在另一批 192 个配置中进行了[十二轮平衡顺序计时与兼容性复查](dynamic-cpu-repeatability.md)。

## 复现

~~~sh
python scripts/check_fixture.py
python -m scripts.cpu.dynamic.study_dynamic_cpu_compact --entry --nodes 32 --repeats 3 --seed 20261117 --out outputs/dynamic-cpu-entry.csv
python -m scripts.cpu.dynamic.study_dynamic_cpu_compact --entry-dense --nodes 32 --repeats 3 --seed 20261117 --out outputs/dynamic-cpu-entry-dense.csv
~~~

可以通过 `--trace-dir` 指定已下载的百炼文件。普通回放入口也支持 `--policies next4 entry entry-fast entry-progress`。验证时需保证四种策略共享同一组请求、对象放置和成本。
