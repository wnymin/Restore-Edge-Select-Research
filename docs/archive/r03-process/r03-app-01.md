## 1. 任务边界

本任务使用第一阶段固定语义：精确检查点恢复、Qwen3.5-4B CPU 元数据模拟、固定请求顺序、单计算槽、串行传输、共享 HBM 预取额度、首次入窗只选一次。研究对象仍是恢复边界选择，不扩展到淘汰、活动 KV 分配或服务调度器重写。

本轮区分三类证据：

1. **机制配对**：同一输入只改变一个因素，固定边界对照，测量收益符号是否改变；用于 D 的局部敏感性和反例发现。
2. **闭环留出**：已有动态策略与成本压力留出，用于说明策略级净成本和适用域；没有同输入单因素省略时，不把它归因给某一个因素的 L。
3. **信息下界**：相同决策前可见状态、不同未来到达的构造，用于证明在线信息限制；这不是生产频率估计。

### 2.2 未到达信息下界

复用 `dynamic-cpu-unseen-arrival.csv` 的 100 组配置。只有 1 组构造配置出现正的最坏遗憾下界，但该组已经证明：相同决策前可见历史不能同时适配两个不同的未来到达场景。

### 3.2 关于 L 的重要限制

本轮没有把“动态策略在压力留出上获得 105–733 ms 改善”写成 F03、F08、F10 或 F11 任一因素的单独 L。那样会混淆多个因素和策略整体效果。按照 MET-01，只有同一输入、同一快照、同一候选、同一成本和同一执行器下的因素保留／省略闭环，才能填写单因素 L。

因此，本交付中的“L 不可评估”是有明确理由的，不是遗漏填写：当前证据没有完成因素级闭环消融，不能把政策级成绩拆分归因。

### 2.4 因素级同输入闭环消融

为补充因素级 L，本轮在 144 个固定合成配置上运行统一的 `snapshot-score` 在线策略：完整版本使用 `projected_cost`，消融版本只把一个决策时特征族置为中性，其余输入、候选、执行器、成本和到达序列完全不变。L 定义为消融策略相对完整策略的平均响应增加；这是**该 CPU 合成域和该策略族内的闭环 L**，不是生产性能损失。

复现命令：

```powershell
python -m scripts.validation.study_r03_factor_ablations --out docs/evidence/r03-factor-ablations.json
```

| 消融因素 | 配置数 | 动作变化 | 动作变化率 | 平均 L（ms） | 最大配置 L（ms） | 最大单请求退化（ms） |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| F08 运行计算余量／覆盖窗口 | 144 | 53 | 36.81% | 1.3012 | 8.0 | 16.0 |
| F09 在途残余／有效就绪延迟 | 144 | 0 | 0% | 0 | 0 | 0 |
| F10 可覆盖搬运量／消费窗口 | 144 | 53 | 36.81% | 1.3012 | 8.0 | 16.0 |
| F11 搬运／复制／重算成本 | 144 | 100 | 69.44% | 9.0766 | 42.0 | 84.0 |
| F13 同行竞争代理 | 144 | 51 | 35.42% | 1.2502 | 8.0 | 16.0 |

F09 在本合成域没有活动在途残余，因此零损失只能说明“当前域内没有可消融的该信号”，不能证明真实服务中可忽略。F08 与 F10 在当前实现中共享覆盖窗口字段，结果不能进一步拆成两个独立贡献；这正是因素拆分的识别边界。F11 的成本信息在本域影响最大。完整逐配置结果见 `docs/evidence/r03-factor-ablations.json`，汇总见 `docs/evidence/r03-factor-ablations-summary.json`。

该实验使 F08、F09、F10、F11、F13 在声明的 CPU 合成子域获得因素级 L 证据；不能替代 GPU 状态误差、公开轨迹留出或真实服务验证。
