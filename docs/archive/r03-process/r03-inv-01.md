- **任务**：R03-INV-01
- **盘点版本**：v1.0
- **盘点日期**：2026-11-19
- **方法依赖**：`R03-MET-01/v1.0`

本盘点只覆盖当前仓库中可审计的来源，不宣称穷尽真实服务的所有因素。`known` 表示来源中已明确出现；`unknown` 表示该来源明确保留但尚无可用测量或决策前证据；`forbidden_online` 表示只能用于离线评价，禁止作为当前在线输入。Q/O/D/L 的最终评级不在本任务中预先填写。

## 3. 去重与拆分规则

- “共享身份”和“净新增预留”拆成 F04/F03：前者决定对象是否相同及引用关系，后者决定计费后的容量结果；低共享翻转率不能消除任一因素。
- “就绪状态”“在途身份”“搬运次序／同刻规则”拆成 F06/F07：对象是否已可用与对象按什么顺序到达是不同机制，已有反例显示顺序变化可改变动作。
- “运行计算余量”“在途残余”“可覆盖搬运量”拆成 F08/F09/F10：计算资源窗口、传输剩余时间和二者重叠量具有不同单位与可见性。
- “候选成本差”和“成本误差”拆成 F11/F12：前者是策略输入，后者是不确定性和校准问题。
- “同行竞争”和“同行代理”合并为 F13 的因素族，但 APP 阶段必须分别报告真实状态与粗粒度代理，不能用代理结果代替真实状态结论。
- F15/F16 不作为当前在线策略因素评分：F15 是禁止输入的信息约束，F16 是尚未扩展的执行模型；二者仍保留在盘点中，避免被误认为遗漏。

## 4. 当前盘点边界与待补证

1. F01–F07 是合法性、容量或执行器约束，不能以平均响应损失预算直接省略。
2. F08–F14 是需要由 APP 任务填充 Q/O/D/L 的动态或评估因素；当前盘点只登记证据范围，不替代实验评级。
3. F09、F12 的 GPU 活动残余和有效就绪延迟仍有未知；不得把事后 GPU 时间戳回填为在线可用信号。
4. F13 的代理信号只能先做筛查，需与逐对象状态和净开销分开评估。
5. F15 的未来／事后信息只能做离线真值或误差解释；F16 需要另立扩展范围后再评价。
6. 当前没有因素获得“在全适用域内可忽略”批准。任何省略都必须引用 `R03-MET-01/v1.0` 的同输入消融、适用域和留出证据。
