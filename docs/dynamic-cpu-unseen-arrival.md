# 尚未到达的请求如何限制在线选点

在请求第一次进入预取窗口时，在线策略可以使用此前历史、已到达请求和当前资源状态，随后只选择一次边界。本轮固定这些可见输入，仅更改尚未到达的请求 C 的到达时间，检查这份信息是否足以选中整条轨迹的离线最优边界。

## 相同快照，不同的离线最优

使用归档 Vulkan 续算和搬运成本，构造三请求 A、B、C，分别在 0 ms、1 ms 和较晚时刻到达。B、C 共享前缀，B 的候选为 0、576、1,152 token。RAM 与 SSD 耗时同时放大 12 倍，预取预算为 70 MiB。两场景只把 C 的到达时刻从 1,200 ms 改到 1,500 ms。程序逐项核对 B 选点时的候选状态、计算余量、就绪与预留字节、传输队列和额度全部相同。

每个场景穷举所有完整边界序列。下表是先固定 B 的动作，再允许未来请求使用最有利的后续方案时，相对该场景离线最优的平均响应差距。数值越大表示损失越多。

| B 的边界 | C 在 1,200 ms 到达 | C 在 1,500 ms 到达 |
| ---: | ---: | ---: |
| 0 | 121.6613 ms | 87.9986 ms |
| 576 | 0 ms | 3.0601 ms |
| 1,152 | 4.8928 ms | 0 ms |

前一场景的离线最优均值为 1,008.4643 ms，完整边界序列为 0、576、576。后一场景最优均值为 942.1269 ms，序列为 0、1,152、1,152。比较的是各场景相对自己的最优差距，两种不同到达时刻的原始响应均值不直接作为策略收益比较。

## 无法由这份快照消除的差距

令 $J_s(c)$ 为场景 $s$ 中固定 B 为 $c$ 后，穷举后续动作得到的最小平均响应，$O_s$ 为完全离线最优。记录 $R_s(c)=J_s(c)-O_s$。两种场景对 B 都提供相同的可见历史，因此确定性策略只能给出相同动作。它在两个场景中的最坏差距至少为：

$$
\min_c\max_s R_s(c)=3.060135\text{ ms}.
$$

这里已经允许后续请求使用知道未来的最优延续，这比普通在线策略更有利，所以该下界也约束按同一可见状态立即作出一次选择的在线策略。

允许 B 随机化也无法把最坏期望差距变为零。把两个场景下的动作差距看作二维点，寻找动作概率混合后两个期望差距的较大值的最小值。穷举单个动作及两动作混合的平衡点，最小值为 **1.882647 ms**，由约 61.52% 选择 576、38.48% 选择 1,152 达到。算法使用有理数，反例 JSON 同时记录精确分数。

这项结论依赖首次入窗立即提交边界、相同可见历史以及这里的固定执行器。新增关于未来请求的信号、允许延迟提交、改变资源预算或优化目标，都需要另行比较。它解释了一类误差来自信息尚不可见，不能仅通过更准确地拟合当前队列消除。

## 搜索范围

对两种搬运作用范围、五档倍率、五档预算、是否共享前缀，共 100 组固定配置，分别枚举六个 C 到达时刻。每个配置内先检查可见快照一致，再穷举完整边界序列。本批只有上述一组配置出现正的最坏差距下界。1 倍和无预取预算对照都没有这样的下界。这些配置是机制构造，出现比例只描述这一组网格。
