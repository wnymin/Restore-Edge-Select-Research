# R02 独立分工与最终交付

2026-11-19 修订。原计划在中途安排了案例交换，并把两线复核与分线完成绑在一起。现在每人根据固定仓库版本完成自己的研究、复算和交付。两份最终成果提交后，由本方在 `R02-INT-01` 汇总并复算，按证据登记阶段验收。

## 共同起点

以 `9c20261` 为已知参照版本。两人各自从仓库取得原执行器、GPU 归档、CPU 开发样例及复算入口。各自运行通用夹具验收和本线相关回归，可独立重跑相同的参照命令。正式留出由负责该产出的人在评估前自行冻结，记录输入版本、种子、成本档和判定规则。各方可以独立处理本线缺失的样例和脚本，按现有仓库格式提交。入口见 [CPU 开发参照](r02-cpu-reference.md) 和 [GPU 报告](r02-gpu-observation.md)。

## 独立分工

| 任务 | 主责 | 分线最终产出和自验 |
| --- | --- | --- |
| `R02-CPU-01` | 协作者 | 原执行器完整求值、三种表示的对照、冻结留出、充分判据或可复现反例。逐请求验动作、精确平局及完成向量。保真后测判定、续算及回退的净成本。成本档使用仓库已有 CPU 配置或自行冻结的合成档。 |
| `R02-GPU-01` | 本方 | 三组 GPU 留出、探针开关及事件可见性诊断，连同观测与真值、缺失与拒判、采集开销及适用边界复算。提交独立的策略取舍结论。遇到硬件缺口，独立完成归档审计并注明新实测缺口。 |
| `R02-INT-01` | 本方 | 提交前可独立维护已有证据和复算入口。两线最终交付后，统一运行可移植复算命令，核对结论与证据范围，更新验收台账。 |

双方各自持有固定的输入、参照、验收条件和可写文件。CPU 新脚本、输入、证据及分线报告归协作者维护。GPU 新脚本、证据和分线报告归本方维护。若双方都需要动公共入口，各自先在本线目录提供入口或小型适配，汇总时处理公共改动。GPU 结果和 CPU 判据的对照在阶段末进行。排期无中途案例交换、参数会签或互跑新结果的节点。

## 最终交付

每线各交一次可复算成果。成果归入 `main` 的分线文件，汇总人维护公共索引。交付时记录提交号或文件路径、基线版本、冻结输入、命令、验收结果和未覆盖事项。可复现的反例或实测否定结果按同样方式交付。任何一线先完成即可登记为已交付。另一线尚在进行时，台账分别登记两线状态。

汇总时根据 `R02-case/v1` 对照机制和适用域，直接复算两份最终成果。归档 GPU 复算可在 CPU 环境执行。需要复采的硬件结论保留设备条件。只有满足原 R02 验收门槛时才登记阶段验收通过。入口见 [最终复算与汇总](r02-cross-review.md)。
