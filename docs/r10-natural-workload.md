# R10-ANA-01｜自然负载特征与恢复边界一致性的解释

**在 R10 已测的自然来源负载及本机单槽 FIFO 配置下，`local-cost` 与 `entry-replay` 的恢复边界选择完全一致，前瞻选点未显示额外收益。** 该结论覆盖百炼轨迹重建与 OASST 真实文本加合成到达。RTX 4060 Laptop 上运行 Qwen3.5-4B Q4_K_M，预填充 4,800 个逐请求配对、单槽服务 1,824 个可比较的逐请求配对，均无边界分歧。预填充平均响应差为 10.09 ms（0.62%），低于 144.65 ms 的预登记门槛；两策略在可比较服务请求上均有 808 个达标。实验按预登记口径检验增益，端到端性能等价尚未检验。[预填充验收](r10-local-acceptance.md#r10-gpu-04-primary) · [正式服务留出](r10-native-service.md)

R10 中，任务并发和暂存竞争都曾发生。恢复边界仍保持一致，原因有两层。首先，约七成决策只有全重算，其余决策中的多边界机会又高度集中在少数输入类型。其次，在冻结的单槽 FIFO 成本模型下，换用更浅边界能省掉的窗口等待，最多只抵消额外续算代价的 **29.7%（预填充）和 27.1%（服务）**。这两个比例来自同一快照的逐候选推演。[逐项证据](evidence/r10-natural-workload.json) · [本机验收](r10-local-acceptance.md)

## 单槽 FIFO 下的改选条件

设决策时刻为 $t$，窗口包含队首 $h$ 到 $v-1$，目标请求为 $i$。$v$ 由已到达请求确定，至多纳入目标之后 4 条请求。固定其他请求的恢复边界。令 $C_j(c)$ 表示目标选边界 $c$ 时，推演窗口内请求 $j$ 的完成时刻，取 $C_{h-1}(c)=t$。令 $P_j(c)$ 为估算的名义续算时间。已在执行的队首可以统一取 $P_h=0$，其剩余执行时间计入下式。定义

$$
W_j(c)=C_j(c)-C_{j-1}(c)-P_j(c).
$$

$W_j(c)$ 是该完成间隔中超出名义续算的残差，归集暂存、串行搬运、设备复制及其等待。已启动队首的公共部分在两方案相减时抵消。设 $b$ 为串行基线选出的最深边界，$a<b$ 为任一替代边界。记 $S=P_i(a)-P_i(b)>0$，并定义浅边界节省的加权残差 $B$。

$$
B(a,b)=\sum_{j=h}^{v-1}(v-j)\,[W_j(b)-W_j(a)].
$$

窗口目标 $J$ 为请求响应时间之和。同一快照下到达时刻相同，目标差等于完成时刻之和的差。把相邻完成间隔相加，每项会在其后的 $v-j$ 个完成时刻出现，得到

$$
J(a)-J(b)=(v-i)S-B(a,b).
$$

**浅边界严格胜出的充要条件是 $B(a,b)>(v-i)S$。** 并列时沿用深边界。$v-i$ 是目标与可见后继之和。压缩到达间隔可能增加预取冲突，也可能增加需要共同承担目标额外续算的请求数。相近的前缀如果带来就绪或共用预留，可以降低新增搬运。独立前缀如果同时争用暂存，替代边界有时能省去其他请求的等待。实际方向取决于这些变化能否让 $B$ 越过同一快照的阈值。$B$ 通过固定后继选点的逐候选推演求得，$S$ 来自冻结预填充成本。

## 续算开销与模型规模

R10 真机校准使用 RTX 4060 Laptop 上的 Qwen3.5-4B Q4_K_M。选点用到的计算量是**两个边界之间的预填充时间差** $S$。若只有这项差值增加，状态、窗口权重和候选间等待差相同，深边界更难被替换。实际执行中，续算变慢还会增加积压、改变预取可覆盖时间和窗口内的请求数，因此用闭环对照复核这一方向。[R10 本机成本](r10-native-cost.md)

## 代码 Agent 与正常搬运成本

在工具调用后暂停的分支，可能同时命中仍驻留的共享浅点和已降到 SSD 的私有深点。代码 Agent 的工具循环、近邻分布、跨分支重叠及原始时序回放由 R11 核验。公开的 64-token 块标识只确定前缀几何，检查点周期与物理驻留仍需独立观测。[R11 实验](r11-coding-agent-recovery.md)

若浅边界的前缀 KV 已在 GPU，深边界只加载缺失 KV 和自己的循环、卷积状态，新增搬运量为 $D=C_{\mathrm{state}}+k(q-p)$。按 R07 的 Qwen3.5-27B 无填充载荷，$C_{\mathrm{state}}=146.8125$ MiB，$k=64$ KiB/token。两点差 128 token 时需取回 154.8125 MiB。沿用 HiState §3.1 的带宽估算，SSD 5 GB/s 时读约 32.47 ms，主机到 GPU 64 GB/s 时复制约 2.54 ms，串行且未覆盖时合计约 35.00 ms。续算差若为 10 ms，未覆盖的 SSD 读盘时间就是续算差的约 3.25 倍。128 token 和 10 ms 是量级对照；热端能否复用、磁盘真实速率、目标卡上的续算差及可覆盖的搬运时间均需同一部署实测。[R07 载荷推导](r07-extension-results.md#试了哪些变化) · [HiState v1 §3.1、图 5](https://arxiv.org/html/2610.41508v1#S3.SS1)

本机已有未注入 I/O 延迟的物理配对。Qwen3.5-4B 的 1,024-token 状态驻留在目标槽，1,152-token 状态首次从文件读回。第一批留出中，深恢复调用平均 79.22 ms，服务端预填充少 60.92 ms，目标从 662.59 ms 增至 714.05 ms；换种子后深恢复仍慢 84.72 ms。恢复调用包含文件读、解析、同步及接口等环节，归档另有裸搬运标定。两批基于预置状态的小样本证实正常路径可以出现反转，还需在代理全量请求中测出现频率。[实测及重复](archive/gpu-studies/gpu-boundary-restore.md) · [原始配对](evidence/gpu-boundary-resident-trials.csv) · [换种子配对](evidence/local-cost-gpu-close.csv)
