## R07 已归档的真实服务对照

- **目标与同行。** 85 个完整配对中，深恢复均缩短目标首 token 时间。4B 关闭连续合批时，同伴最大可见片段间隔在有同行和有后继两组分别增加 10.29 和 13.27，超过 10 ms 的配对分别有 4/8 和 5/8。
- **恢复阶段和端到端。** 4B 观察者对照下，深恢复在仅恢复时使同行最大间隔多 11.89，在继续预填充且无探针时使同行最大间隔少 54.36。排除只观测到 63 个有内容或 token ID 的 SSE 片段的提示后，差值仍为 +12.00 与 −52.84。
- **探针。** 两次同步探针合计中位 189.35，同深度配对下目标首 token 多等 187.05–197.51。
- **16 层失败。** 单跑同伴提示时 16 层仍有 5/8 失败，4B 为 0/8。服务格式错误的根因仍需服务侧证据。
- **接口。** 待处理数 0→1→2 可观测，槽位快照始终只显示同两个活动任务。排队身份和候选、共享暂存的依赖及就绪事件缺失。真实策略闭环仍需要调度器内部日志。

运行复核时，原 R07 服务校验唯一差异是队列接口 JSON 的换行哈希。Git 保存 LF，将其还原成原始采集的 CRLF 后，SHA-256 精确匹配归档记录。随本次提交的校验器将该规则用于队列 JSON，处理后可完整复算原汇总。

将本目录的 docs 和 scripts 按原路径合入仓库，在根目录运行以下命令。新脚本读取公开归档中的诊断、离线证书和计时，不依赖原始轨迹或 GPU。

```powershell
python -m scripts.validation.check_r08_published_witnesses

```

R07 到达分线的全量复核仍待归档溯源对齐。check_r07_extension 先遇到前置 JSON 的换行差异，复原换行后发现 study_r07_extension.py 与 r07-extension-matrix.json 的当前版本也与归档哈希不同，LF 和 CRLF 均无法匹配。需要对应版本或可核验的历史提交，再运行同平均到达率的分层对照。新留出封存、冻结候选后的独立盲验属于后续交付。
