## R01 双人分工：动态感知的恢复边界选择

以下保留 R01 原有 A1–A3／B1–B3 分工与证据；已验收工作不重复排期。

目标：在能拉开策略差距的成本配置下，解释同一配置内哪些请求与负载状态会改变选点收益，建模并验证利用这些信息的在线决策。动态状态是否比静态硬件规格更有解释力，作为待检验的假设。

| 组别 | 负责的问题 | 工作量安排 | 主要交付物 |
| --- | --- | --- | --- |
| A：需要 GPU 验证 | 动态因素能否在真实服务内改变选点？哪些量可在决策前观测，并据此做低开销决策？ | A1 物理配对与成本拆分；A2 状态建模及留出验证；A3 低开销规则与实测对照。每项约占组内三分之一，可用 CPU 分析实测。 | 真实配对与配置、可复算分析、在线信号与规则、实测边界及成本范围。 |
| B：只需 CPU 验证 | 在固定执行器内，动态状态通过哪些机制影响选择？何时值得付出推演成本？ | B1 配对干预及标注；B2 状态模型与在线策略；B3 留出回放及离线最优对照。每项约占组内三分之一。 | CPU 复现脚本、动态策略与例证、留出表和适用边界。 |

## B 组：只需 CPU 验证的工作说明

首轮 B1 合成干预已完成：[动态 CPU 配对结果与复现](dynamic-cpu-interventions.md)。144 个配置、864 条单点干预。B 组 B1–B3 已于 2026-11-18 完成验收，详见 [CPU 结项记录](dynamic-cpu-completion.md)；后续仅保留一般化保证、真实误差覆盖和跨组交叉验证。

本节可独立作为协作者的工作依据。使用现有模拟器、归档的 Vulkan 续算及传输成本、合成轨迹与公开轨迹；无需 GPU、模型权重、真实推理服务或 A 组新数据。先读 [主对照](trace-oracle.md)、[模拟规则](phase1.md)和[复现入口](experiment-index.md)。

1. **B1：定位效果来自哪里。** 从已归档的 SSD 11/12 倍、16 倍及 RAM/SSD 同时受压配置中，挑选确有策略差距的配置；另取基线已最优的低成本配置作阴性对照。固定成本、初始对象放置、候选和服务规则，只改变到达间隔、共享关系或初始占用；每类先做最小合成轨迹，再从归档回放筛选匹配案例。记录可见队列、剩余额度、对象就绪／在途、可重叠时间、单请求成本差。对同一决策快照改选一次，后续沿固定基线决策，分别报告目标和后续请求完成时间变化。保存有翻转和无翻转的案例、参数与种子。
2. **B2：建立状态模型并实现决策。** 用选点时可见的特征，估计沿用 local-cost、直接改选或启动现有窗口推演的收益。先做可解释的门控，比较仅用静态成本的版本及移除动态特征后的版本。离线/全轨迹标签仅用于训练、分析或评价，不进入在线特征；模型参数只在校准集选择。新增策略用独立模块或脚本实现，复用现有事件语义，并保留原有策略用于对照。
3. **B3：冻结策略后验收。** 在留出的轨迹窗口及整组硬件成本组合上比较 local-cost、固定启用窗口推演、仅按硬件档位选策略和新策略。固定共同输入；分别报告不计开销的平均响应、实际选点耗时、含耗时净增益、P95/单请求损失及离线最优接近率。最优未证实时给区间，基线已最优时标明无可降空间。不设固定接近率门槛；不能稳定超过简单策略时，交付限制与失败案例。运行 python scripts/check_fixture.py，并提供从仓库根目录可执行的命令、输入版本、数据分组和随机种子。

B1 可复用 [单次改选反例脚本](../scripts/cpu/replay/study_tail_witness.py)和[状态采集入口](../scripts/cpu/replay/study_load_routing.py)；B2 先比较已有 adaptive / adaptive-screened 的筛选，再决定需要新增哪些特征。完整公开轨迹回放按[数据说明](../data/README.md)准备；合成对照和归档分析可直接开始。

B 组新增材料放在 scripts/、src/restore_edge_select/ 和 docs/evidence/，实验报告单独放 docs/，文件名优先用 dynamic-cpu 或 dynamic_cpu 前缀；涉及模拟器公共接口时由 B 组集中修改。

### B 组验收状态（2026-11-18）

B1、B2、B3 均已完成并验收：

- **B1：已完成。** 已完成动态状态配对干预、翻转与无翻转案例、公开轨迹匹配及目标／后续请求影响记录。
- **B2：已完成。** 已冻结只使用决策时可见信息的动态门控，并与静态门控、硬件分档和原有 `entry` 路径对照；新增 `entry-replay` 仅优化固定边界推演，不改变边界选择结果。
- **B3：已完成。** 已完成 480 个留出配置及离线最优对照，报告零开销响应、选点耗时、含开销净收益、P95、单请求损失和离线最优接近率；未认证精确最优的配置保留区间。

结论是：动态状态确实能改变恢复边界收益，但在计入本机选点开销后，尚无证据表明动态策略稳定优于简单 `entry` 基线。因此 B 组的失败案例和适用边界属于交付结果，不构成未完成项。B 组结项不代表 A 组 GPU 验证或整个项目完成。
## A 组：需要 GPU 验证的研究任务

后续以[统一报告的研究方向](dynamic-gpu-lookahead-report.md#5-后续方向与验收条件)为准。A 组优先用归档或受控 GPU 对照区分候选可行性、目标关键路径和请求间代价；只有现有证据无法区分算法预测时才补实验。下面的 A1–A3 记录已有验证路径，新的接口或执行方式不作为两组汇合条件。

1. **A1：实测动态变量是否改变相对收益。** 以现有 RTX 4060 Laptop 双槽作为起点，固定提示词、候选与模型，配对改变同行是否活跃、启动时差、同行待处理工作量。在换硬件前优先找到接近恢复回本点的边界和方向稳定的对照。记录真实槽缓存 token、冷读量、恢复接口与服务端阶段耗时、目标与同行首 token 响应及共同完工时间。条件允许时用独立传输微基准校验重叠与争用；无法拆分的时间保持未归因。
2. **A2：校准可提前观测的信号。** 对比只使用独占成本的规则与加入同行状态的规则；服务结束后的实际重叠、响应与恢复计时仅用于解释。将校准和留出按种子及工况切分，衡量预测方向、响应差和跨工况误差。等待、传输与续算只有在实际被分别测量时才据此向模拟器提供参数范围。
3. **A3：冻结并验证低开销规则。** 与固定驻留、固定深恢复及独占成本策略做配对比较；同时报告目标、同行、两项响应之和、完工时刻和决策开销。若收益来自牺牲目标请求，明确适用的优化目标和代价。小样本的实测最优只指已测候选的配对参照，不能称为全轨迹离线最优。整槽恢复与 CPU 模拟的细粒度预取有不同执行语义，不把二者的结果当成同一实验。

A 组新增通用分析、报告和精简证据优先使用 dynamic-gpu 或 dynamic_gpu 前缀；机器专用测量脚本按[协作约定](../CONTRIBUTING.md)留在本机。发现本机无法形成稳定翻转时，保留反例；远程 GPU 只复核最能区分机制的用例，不作为 B 组前置条件。

首轮实测见[同行进度配对](dynamic-gpu-peer-progress.md)，机制复测见[浅驻留延迟提交对照](dynamic-gpu-delay-control.md)，选点前信号的跨工作量留出见 [A2 规则与结果](dynamic-gpu-a2-signals.md)，实时分派见 [A3](dynamic-gpu-a3-live.md)。系统候选见[同槽提前恢复](dynamic-gpu-early-restore-plan.md)；汇总证据见[GPU 机制附录](dynamic-gpu-lookahead-appendices.md#round-gpu-findings)。

## 并行边界与汇合

两组立即并行：A 从归档双槽配对和本机开始，B 从归档 CPU 配置和合成反例开始。B 不等待新校准，A 不等待新算法；任一组的成果都可独立验收。两组只在汇合时交换机制案例及证据：至少注明成本配置来源、目标函数、边界、决策前状态、基线与改选效果、计时语义及可复现入口。由 B 将有意义的实测范围作为补充敏感性配置，由 A 选择可在双槽环境表达的模拟反例复测，均为已有交付后的交叉验证。
