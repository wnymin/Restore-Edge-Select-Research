# 恢复选点的安全条件与在线信息边界

本轮得到两个结论。第一，在固定 FIFO 下，如果每个候选的就绪时间和续算时间不受其他请求选点影响，那么逐请求最小化实际完成时刻就是全局最优；只看独占搬运加续算仍可能选错。第二，即使暂存只占到续算开始，改选也可能给其他请求增加超过自身收益的等待。看不到未来的到达时间时，在线策略不能确保每次选对，但在一个两请求模型里，可以用最早可能到达时刻给出精确的安全检查。

## 无耦合时的贪心最优

请求按固定顺序一次执行一个。每个请求 $i$ 的候选集合固定，候选 $b$ 有绝对就绪时间 $R_{i,b}$（不早于请求到达）和续算时间 $C_{i,b}$，两者都不受任何请求的选点影响。给定前一请求的完成时刻 $t$，选择使 $\max(t,R_{i,b})+C_{i,b}$ 最小的候选。

**证明。** 第一项请求的贪心完成时刻不晚于任意比较策略。若第 $i-1$ 项同样成立，就用比较策略给第 $i$ 项所选的候选：对它而言，前一项更早完成只可能让它更早或同一时刻完成；贪心还可以选一个更快的候选。归纳得到每项完成时刻都不晚，因此也最小化响应和与共同完工。若一个候选的就绪和续算均不差于另一个，后者可直接排除。这是充分条件：若存在容量、队列或共享耦合，则需另证；固定 FIFO 本身不够。

## 两请求何时发生整体翻转

目标在时刻 0 选点，候选 $b$ 的续算开始和完成时刻分别为 $S_b$ 和 $T_b$，对象占用容量至 $H_b$（交接释放时 $H_b=S_b$，完成释放时 $H_b=T_b$）。同行有固定边界，最早在 $a$ 申请预取，搬运耗时 $L$，续算耗时 $p$。目标搬运在 $a$ 前已结束；两者只因容量竞争，同行在目标之后续算。两种候选和同行对象单独均可入池。令 $W_b$ 为同行准入等待：可共存时为零，否则为 $(H_b-a)_+$。其完成时刻是 $\max(T_b,a+L+W_b)+p$。以下用 $(x)_+=\max(0,x)$。

给定 $G=T_{浅}-T_{深}$，再令 $Q_b=(a+L+W_b-T_b)_+$，即同行搬运实际暴露在目标完成后的时间。选择深边界对两项响应和的改善是：

$$
2G + Q_{浅} - Q_{深}。
$$

目标提早会为同行提前腾出计算机会，所以公式中有两份 $G$；若同行来不及就绪，$Q_b$ 抵消其中一部分。若深边界使目标更快且两条路径都能与同行共存，同行不可能更晚。若两条都不能共存，但深边界不晚释放，则同样安全。只有深边界拦住同行时，**准入等待增加还不足以推出选浅更好**：整体严格偏好浅当且仅当额外暴露时间 $Q_{深}-Q_{浅}$ 大于 $2G$。

## 有限未来信息能保证什么

容量取 3，目标浅／深占用 1／2，各在时刻 1／2 就绪，计算资源都要等到时刻 6。浅／深续算需要 4／2 个时间单位，且**都在时刻 6 交接释放**。同行对象占用 2，搬运需要 8，续算需要 1。两条轨迹在时刻 0 的可见状态相同，均有且仅有一个未来同行，连其大小和工作量相同；只改变它的到达时刻。

| 同行到达 | 浅：两项完成时刻 | 深：两项完成时刻 | 响应和最优 |
| --- | --- | --- | --- |
| 2 | 10、11 | 8、15 | 浅，少 2 |
| 10 | 10、19 | 8、19 | 深，少 2 |

目标始终偏好深。任意确定性在线规则面对相同快照都选同一边界，最坏多花 2；若随机以概率 $q$ 选深，早到和晚到分别产生 $2q$ 与 $2(1-q)$ 的期望损失，因此至少一条固定轨迹上期望损失不低于 1。代价用响应和（固定在单条轨迹内的到达时刻相消），平均响应的界再除以请求数。这给出信息不足的下界，不依赖计时噪声，也不依赖暂存保留到续算结束。它不适用于允许推迟选点、改选或提前知道同行到达的策略。

**安全检查。** 若只有深边界会挡住同行，且 $G>0$，知道同行搬运时间与一个最早可能到达时刻 $a_0$ 即可检验深边界对所有 $a \ge a_0$ 是否都不差。记同行在深路径相对浅路径的延迟为 $D(a)$。当 $a<H_{深}$，深路径的同行完成固定，浅路径的同行完成随到达单调不减，因此 $D(a)$ 不增；当 $a \ge H_{深}$，两者都能立即准入且深路径目标更早，故 $D(a) \le 0$；足够晚时二者完成相同。所以最坏同行延迟恰为 $\max(D(a_0),0)$。深边界对全部可能到达都安全，当且仅当该值不超过 $G$。如果不通过这个检查，晚到仍偏好深，此时到达信息才有可能改变决策。这条检查假定只有一个未来同行及固定装入／续算时间；共享复用、多个在途对象和抢占不在证明范围内。

## 多看一个请求什么时候还不够

两请求判据只看到了第一个同行的代价。即使更远的请求既不占暂存也不争传输，延迟仍可沿 FIFO 向后传。设某同行在深路径已经比浅路径多等 $d$，其浅路径完成时刻为 $F$，下一个请求在两条路径都于 $R$ 就绪，续算量也相同。下一个请求的延迟恰好是 $(d-(R-F)_+)_+$：如果它在队首空出来前就就绪，前面的延迟会完整传递；只有实际空闲才吸收延迟。对于这段状态不变的后缀，可用浅路径中的空闲间隔逐项扣除延迟；只知道后面有几项请求时，用该项数乘当前延迟是安全上界。这个上界不适用于后继的恢复时刻本身也发生变化的情况。

仍用容量 3、交接时刻 6、同行时刻 2 到达，将深续算改成 1、同行搬运改成 6。前两项浅／深分别完成于 $(10,11)$ 和 $(7,13)$，响应和偏好深 1 个时间单位。加入一个在时刻 3 到达的驻留请求，续算耗时 1，不占暂存；它在两条路径分别于 12 和 14 完成。现在响应和反而偏好浅 1 个单位。**一个直接竞争者已足以改变后面多个请求的响应；只把直接争额度者纳入代价仍会低估影响。**

## 可复算范围和 GPU 证据边界

用 [枚举脚本](../scripts/cpu/replay/study_boundary_window.py) 在 44,280 个合成实例上比较最长、独占静态成本、目标关键路径、已知同行时间的判定与直接求两条时间线的离线最优。策略统一在同分时选浅（最长基线固定选深）。容量为 3 时，每种释放规则有 7,380 个实例，其中 4,239 个目标严格偏好深；整体反向在交接释放下有 63 个，在完成释放下有 406 个。在这两个切片，静态成本误选分别为 1,274 和 1,149，目标关键路径分别为 63 和 406；已知同行判定与离线最优的损失都是零。它使用到达信息，是模型内的校验对照，不是实用在线策略的成绩。仅给最早到达时刻时，在容量为 3、目标严格偏深的 405 组参数中，交接释放能安全选深 368 组，完成释放能安全选深 256 组。网格的取值不是实际负载分布，这些比例不用于估计线上发生频率。

~~~sh
python -m scripts.cpu.replay.study_boundary_window
~~~

在[项目 Phase 1 夹具](phase1.md)中，把 SSD 搬运时间设为三倍，只改 C 的到达时刻。B 在 1 ms 的候选观测完全相同。若固定 C 在 1,152 token 恢复，160 MiB 下把 C 从 2 ms 推迟到 40 ms，B 选深对响应和的效果从增加 2.50 ms 变成减少 4.25 ms；在两条轨迹上，B 自己都快 4.25 ms。额度提高到 192 MiB 后，两者都能预取，早到时选深使响应和减少 8.50 ms。若允许联合选择 C 的边界，**原夹具的翻转消失**：160 MiB 早到时离线最优让 B 选深，让 C 改浅；晚到时让 C 改为重算。固定同行动作得到的翻转不能直接推出全局最优的首个动作相反。

进一步构造**双方都能自由选边界**的反例：保留原模型的精确检查点，用 128 token KV 块，将 B 的浅边界移到 768、C 的浅边界移到 1,024，两者仍都可以重算或选 1,152。B 选浅时，C 的深对象可以一起预取（73.125 + 85.125 = 158.25 MiB）；B 选深时，连 C 的浅对象也不能同时纳入 160 MiB（85.125 + 81.125 = 166.25 MiB）。穷举全部 9 个边界组合，逐个 B 动作都按最好的 C 选择计算：

| 共享额度 | C 到达时刻 | 唯一离线最优 B／C 边界 | B 选深对响应和的改善 |
| --- | ---: | --- | ---: |
| 160 MiB | 2 ms | 768／1,152 | −2.22 ms |
| 160 MiB | 40 ms | 1,152／重算 | +2.89 ms |
| 171 MiB | 2 ms | 1,152／1,152 | +5.78 ms |
| 171 MiB | 40 ms | 1,152／重算 | +2.89 ms |

在每档容量内，早晚两条轨迹在 B 决策时的候选快照仍完全相同。160 MiB 下即使允许 C 事后采取最优动作，确定性规则在至少一条轨迹上仍要多付 $20/9$ ms 的响应和；B 选重算在两条轨迹都更差。放宽到 171 MiB 后翻转消失。这是主模拟器语义下的存在性结果，参数用于区分机制，不代表本机实测代价或轨迹频率。

~~~sh
python -m scripts.cpu.replay.study_boundary_window_phase1
~~~

已有 [GPU 设备事件](dynamic-gpu-staging-study.md)支持“准入等待只有越过消费窗口才进入关键路径”，但该夹具先提交同行，考察的是同行占用如何影响目标；这里的在线下界用的是目标先占用、未来同行受影响，不能把现成 GPU 数据当成该下界的实测。若补测，只需区分目标收益仍为正、而同行延迟是否超过它：固定边界和搬运量，只交换同行的两个到达时刻，并用能同时容纳两对象的额度作对照。不需要改造推理服务接口才得出上述算法结论。
