# 搬运下界与搜索开销的对照

本轮以 `entry-fast` 为起点，检验是否能用决策时可见的对象状态进一步排除候选。新模式 `entry-transfer` 沿用相同窗口、候选、评分和同分规则。

## 必要搬运给出的下界

在某次选点的时刻 $t$，把已就绪对象和当前活跃前缀 KV 当作此后永久可用，并忽略预取容量与其他排队搬运。某请求仍缺对象时，这些对象的总独占搬运时间就是它最早可加载完成的下界。正在传输的工作不能被抢占，其剩余工作也要算入；如果它本身属于所需对象，则只算一次。重叠降速按当前系数还原为剩余独占工作。

对窗口内各请求，先取 FIFO 前一请求的完成下界与自身对象就绪下界的较大值，再加必要续算。把各请求的完成下界相加，与原有纯计算下界取较大值。如果它已无法按原同分规则击败当前赢家，可以跳过该候选。这个判断只排除有下界依据的方案。

审计模式 `entry-transfer-audit` 对本可排除的候选也完整推演，检查每个新增下界都不超过实算完成时刻之和。400 个三请求构造配置及 144 个校准、480 个留出配置全部通过审计和逐请求结果对照。构造配置还单独与穷举最优核对。

## 实测代价

首次实现提前计算所有对象下界，即使纯计算下界已足以排除候选也付出成本。改为首次需要时才构造下界后，冻结实现，再验证原留出窗口。每配置先预热，两种实现以正反顺序各出现三次，分别测量固定轨迹选点时间及注入选点耗时后的响应。

| 数据组 | 校准配置 | 留出配置 |
| --- | ---: | ---: |
| 配置数 | 144 | 480 |
| 新增下界检查 | 574 | 2,621 |
| 新增排除候选 | 10 | 16 |
| 原推演事件数 | 20,972 | 74,969 |
| 新推演事件数 | 20,862 | 74,813 |
| 原选点总时间的配置均值 | 5.574 ms | 5.278 ms |
| 新选点总时间的配置均值 | 5.746 ms | 5.640 ms |
| 注入时间后的平均响应改善 | −0.0060 ms | −0.0240 ms |

更紧的下界只省下少量事件，计算依赖集合与有理数的成本超过了这部分收益。保留 `entry-fast` 作为当前实现参照，`entry-transfer` 作为已完成审计的实验对照。下界能说明哪些推演无用，是否值得算它还需要成本对照。

## 离线区间加深

此前部分整轨迹离线最优区间过宽。按绝对区间宽度选出最宽的 12 个配置，复现 32 节点的原区间，再将搜索上限依次提高至 256、2,048 节点。每个阶段都重放搜索提供的完整边界序列，验证其上界可实现，并核对上下界单调收紧。

这些配置全部属于 32 倍的高成本组。2,048 节点后，所有区间都收窄，但仍未认证精确最优。搜索尚未找到比现有 `entry` 更快的完整序列，不能据此认定它已是全局最优。结果同时保留边界序列、搜索节点和耗时，供后续改进下界或继续搜索使用。[分阶段离线区间](evidence/dynamic-cpu-oracle-refinement.csv)

## 复现

~~~sh
python scripts/check_fixture.py
python scripts/study_transfer_bounds.py --out outputs/transfer-bounds/calibration.csv
python scripts/study_transfer_bounds.py --holdout --out outputs/transfer-bounds/holdout.csv
python scripts/refine_dynamic_cpu_oracle.py --top 12 --nodes 32 256 2048 --out outputs/transfer-bounds/oracle-refinement.csv
~~~

可用 `--trace-dir` 指定已校验的百炼目录。`entry-transfer` 沿用固定单通道成本的快路条件，不满足条件时回退原 `entry`。审计模式要求零开销回放，避免把额外验证当成策略的正常决策时间。
