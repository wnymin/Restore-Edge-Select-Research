# R07：`entry-replay` 泛化性研究

**登记日期：2026-11-23。状态：设计中；尚未启动 R07 实验，未打开 R07 留出集。** 本阶段先检验既有算法，不开发新门控，不用留出结果调整主干算法。

## 研究问题与冻结范围

**RQ：在精确恢复与单槽执行规则不变时，冻结的 `entry-replay` 能否在不同到达强度和突发程度下，继续拿到大部分可省的响应时间，且不引入明显的净开销或尾部代价？** 如果不能，区分过早返回保底点、观察窗口太短、只改一个恢复点的限制，以及在线无法预知未来到达。

- **冻结主干与已有对照。** 源码锚点为提交 `ee75cc9a4b0bff43610a7d174f1d6041e5070665`。保持现有 `entry-replay` 的粗筛、单请求保底、计算下界、改选门槛、同分规则、固定后继边界和 `queue_horizon=4`。保留 `local-cost` 为收益分母的基线、`entry` 为同规则实现对照。现有算法、配置和历史证据不重新调参；新增实验以独立输入变换和诊断脚本实现。执行前记录源码及输入哈希、命令、环境和参数；本页登记不是实验矩阵已经冻结。
- **只改变到达。** 固定模型与成本、缓存放置、候选边界、FIFO 与同刻顺序、单计算槽、串行搬运、显存共享预取额度、首次入窗选一次。执行器的**预取窗口**与策略的**向后观察上限**是两回事；主实验两个都不改。比较不同固定成本或预算档时，只作分层，不在同一配对里改成本或预算。
- **不在本轮主张的范围。** 多传输通道、多计算槽、并行批处理、持久驻留和真实服务性能不纳入。前缀共享程度作为到达实验之后的候选扩展；若承接，须先登记独立配对口径，不能将共享和突发一起改变。

## 实验设计

| 实验 | 如何构造配对 | 区分什么 |
| --- | --- | --- |
| 原样锚点 | 不变换到达时间；先用手算轨迹和已有归档输入核对主干与 `entry` 在零开销下的边界和完成序列。 | 把回放工具错误和算法本身的问题分开。 |
| 改到达强度 | 固定请求列表和先后次序，保持首个到达时刻，均匀缩放到达间隔。草案用 `1/2`、`1`、`2` 倍间隔作紧凑、原样和疏松组。 | 均匀变密时，单步决策是否留下更多可省时间。 |
| 改突发程度 | 对等长的相邻间隔组重新分配组内间隔，保留组总时长、首末到达时刻和请求顺序。草案用相邻两段间隔，分别构造等分组和 `1:7` 集中组；零总时长组保持不变。原样作为额外对照。 | **平均到达率相同**时，成批到达会不会使现有观察上限失效。以间隔结构及每次决策时可见请求数验证干预确实改变了所测条件。 |

- **先做可辨别的短轨迹。** 纳入无竞争负对照、暂存容量临界、有正在搬运的请求，以及拥堵时已有超过四个后续请求的场景；确保部分场景确有可省空间。使用相同执行器穷举全部边界组合，核对精确离线最优。原有 R01/R06 构造仅作锚点或机制参考，不算新留出证据。
- **再做独立轨迹留出。** 在设计集确认干预强度和离线计算开销后，冻结原始窗口 ID、变换、随机种子、分层、样本量和搜索预算，随后才打开留出。优先用新的源窗口；同一源窗口的全部变体都归入同一拆分，不能把同一批请求的不同到达变体当成独立样本。若只使用一条轨迹，结论只覆盖该轨迹及这些生成方式。候选留出窗口须核对以往 R01–R06 的使用记录。
- **选择有信息的成本分层。** 用此前无改善空间的低压配置作负对照，用此前确有改选收益的 11×–16× 配置作主要锚点；32× 只在设计集评估预算后单列压力组，不把倍率解释为物理设备规格。分层后仍可能出现无改善空间的点，单独报告。

## 如何归因，不把离线上界当在线能力

发现明显损失时，在首次出现差异的快照保存对象、在途、预留、已选边界和可见请求，对每个合法候选做配对回放。诊断对照只解释失败，不代替冻结主干结果：

| 诊断对照 | 支持的解释 |
| --- | --- |
| 同一可见窗口、固定后继边界，绕过粗筛并枚举全部当前候选；另对照开启与关闭剪枝 | 若只有绕过粗筛才恢复收益，说明提前返回遮住了改选机会。若安全剪枝与穷举不同，先排查下界或实现一致性，不能归为策略权衡。 |
| 只扩大策略观察范围到更多已到达请求，执行器预取窗口不变 | 若当前动作翻转并获得收益，说明短观察窗口遗漏了影响。 |
| 用同一已到达集合，允许少量后继共同选点，并用小实例穷举 | 若扩大观察范围仍不够、联合改选才有收益，说明固定后继选点是限制。 |
| 配对两个决策前完全相同、仅未来到达不同的续段 | 若两个续段的最佳首步相反，记录为在线信息限制，不把能看到未来的离线优势直接记为 `entry-replay` 的缺陷。未能归因的缺口单独列出。 |

## 判读和验收

- **选点质量与实现开销分开。** 零开销下报告 `local-cost` 的可省空间、`entry-replay` 的绝对剩余差距和[离线最优接近率](trace-oracle.md#怎样读接近率)。短轨迹给精确值；长轨迹有搜索预算时给可行上界和可证下界，并记录认证率和区间宽度。若离线最优为 $[L,U]$、算法响应为 $A$，剩余差距为 $[A-U,A-L]$；须用相同输入和成本，并把可行算法结果纳入上界。确信基线已经最优时标“无可降空间”，区间太宽时标“证据不足”。
- **闭环表现单独报。** 同机配对重复、轮换运行顺序，报告选点 CPU 时间和注入决策时间后的平均响应、P95、逐请求退化；计时不确定性按源窗口聚类，不把配置变体当独立样本。零开销离线最优不直接拿来给含开销结果计算接近率。CPU 模拟／本机计时不等于真实服务端到端提速。
- **留出前写下最小有意义差距与损失预算。** 草案以每预设分层的平均绝对差距 **1 ms**、未拿到的空间 **5%** 作为均值判读起点：两者同时超过且在至少两个独立源窗口复现，才作为优先追踪的大缺口；尾部和含开销净退化另设预算，不被均值抵消。设计集结束后要说明阈值依据，冻结正式预算、分母分层、离线停止规则和重复次数，再打开留出。本草案的数值不是已经冻结的验收结论。
- **三类结果都可交付。** ① **可复现缺陷**：离线界能确认有实质缺口、留出中复现，并在同一快照上找到可在线获得的改进来源；② **有限泛化证据**：在有可省空间、离线界足够紧的独立留出上，冻结主干的剩余差距和含开销／尾部代价在预先声明的损失预算内；③ **证据不足**：如离线区间太宽、只见无改善空间、窗口不独立或计时噪声太大，明确缺什么，不把未发现反例当作通过。研究验收看证据是否充分，不强求得到正结果或新算法。
