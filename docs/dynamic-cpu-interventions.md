# CPU 动态状态配对干预：首轮合成证据

2026-11-17。对应 [B1 工作目标](work-plan.md)：固定成本与执行语义，检验到达状态是否改变单次改选收益。

## 实验设计

复用三请求手算轨迹和 Qwen3.5-4B 对象规格。交叉共享／不共享、SSD 带宽耗时倍率 1/4/16、预取额度 0/70/160/192 MiB、C 到达时刻 1/2/15/29/35/60 ms，共 144 个配置。A 在 0 ms、B 在 1 ms 到达，无额外争用降速。共享组使 C 使用 B 的输入、候选和对象；两组固定同一显存复制模型。1 倍来自手算成本，不是本机实测成本。

每配置先运行 local-cost，分别对 B、C 枚举 0/576/1152 边界，仅修改目标请求一个边界，其余边界固定为基线，共 864 条记录，包含 288 条不改选对照。采集目标提交前的快照时，前序决策固定为基线。三请求穷举仅用于事后评价。完全枚举，不使用随机种子。

从实验仓库根目录运行，无需 GPU、网络或公开轨迹：

~~~sh
python -m scripts.cpu.replay.study_dynamic_cpu --out outputs/dynamic-cpu-interventions.json
python scripts/check_fixture.py
~~~

脚本同时生成同名 CSV。[逐次记录](evidence/dynamic-cpu-interventions.csv)保存收益、目标和后续完成时刻变化、基线与最优均值，以及选点前的容量、缺失量、计算余量、在途和积压信号。JSON 保存完整候选快照。

## 结果

864 条记录中，115 条改善均值，461 条恶化，288 条不变。固定共享、成本、额度、目标及改选边界，仅扫描 C 到达时刻，有 13 组同时出现正负收益。这是构造配置计数，不代表生产发生概率。

最小翻转例：不共享、SSD 1 倍、70 MiB，C 从基线 1152 改为 576 token。

| C 到达 ms | C 完成时刻变化 ms | 三请求均值改善 ms |
| ---: | ---: | ---: |
| 1 / 2 / 15 | −0.75 | +0.25 |
| 29 | +2.25 | −0.75 |
| 35 / 60 | +3.25 | −1.0833 |

A、B 完成时刻不变。70 MiB 容得下浅边界约 67.125 MiB 的依赖，容不下深边界约 85.125 MiB 的依赖。早到时浅边界可预取，以续算换掉深边界的按需搬运；晚到时覆盖搬运的机会缩小或消失。到达 1 和 29 ms 时，浅候选的 prefetch_fits 都为真，仅判断“放得下”也不足以决定收益。

零预取额度的 216 条干预没有正收益，是本轮阴性对照，不能推广为任意无预取场景下基线必然全局最优。

## 验收及剩余工作

每条干预检查完成时刻差之和等于均值收益的负三倍、结果不优于穷举最优、沿用基线时逐请求差为零。已有手算验收通过：36 个组合、24 个快速路径用例及动态重叠控制。
