# CPU 研究：识别共享机会与控制选点成本

本研究在固定请求顺序、候选边界和缓存布局下，评估混合模型的在线恢复边界选择。主指标为请求从到达到模拟预填充完成的时间。所有结果使用百炼轨迹与 CPU 事件模拟。归档的硬件读数用于设定成本参数。人为放慢搬运的实验用于观察策略行为。

**结论**：当前常规成本证据支持保留 `local-cost`。在搬运受压条件下，识别能共享或接力的对象，能让直接估计保住队列推演的大部分收益。跨层回退和同层回退用于说明风险边界。

## 策略与强基线

逐请求基线 `local-cost` 按独占时的搬运与续算成本选择边界。`next4` 使用已到达请求的队列视野。`entry` 用已有入口下界减少推演，并在每个配对配置中验证与 `next4` 的零开销选点和完成时间一致。

| 策略 | 决策 |
| --- | --- |
| `mixed-estimate` | 候选可立即预取，主路径的增量搬运足以抵消复用省下的计算时，使用队列快照估计。候选跨层时，还要求触发候选估计快于静态边界。 |
| `mixed-projected-entry` | 用同一压力筛选触发完整候选推演，用于区分估计与推演的效果。 |
| `mixed-reuse-estimate` | 额外识别已驻留或已预留的可共享对象。在增量搬运为零、有可观测共享信号且预估有收益时，也允许直接估计。 |
| `reuse-cross-tier-fallback` | 如果估计胜出的是需要新增搬运、可预取的另一层非零候选，则保留静态边界。 |
| `reuse-cross-tier-guard` | 对同一类跨层改选只试算静态候选和估计胜出者。只有队列目标改善且视野内没有请求预计变慢时才改选。 |
| `reuse-prefetch-fallback` | 在跨层回退上，额外保护同层、可按需加载但超出预取预算的深边界，避免为预取含新增 SSD 搬运的浅边界而退回。 |

规则使用决策时的对象层级、预取预算、队列工作和搬运估计。局部预测约束与完整运行的 P95 是不同指标。

## 留出结果与适用区间

每个压力档有 108 个配对配置，来自 Coder、Trace A 和 Trace B 各三个窗口。每窗前 256 条构造历史缓存，接下来的 96 条按长度筛选后回放。交叉检查点放置、到达间隔与预取预算。同一批窗口的多种配置用于配对，不作为独立生产样本。

| 留出窗口与条件 | 路径压力 | 全量 `entry` | 旧直接估计 | 共享直接估计 |
| --- | ---: | ---: | ---: | ---: |
| 84–86，两路径受压 | 16 倍 | 541.44 | 359.84 | 495.33 |
| 84–86，两路径受压 | 32 倍 | 1537.24 | 990.79 | 1371.81 |
| 87–89，仅 SSD，4K 续算表 | 16 倍 | 574.28 | 327.92 | 457.97 |
| 87–89，仅 SSD，4K 续算表 | 32 倍 | 529.67 | 374.57 | 485.52 |

表内为相对 `local-cost` 的零开销平均响应改善，单位 ms。共享触发保留全量推演约 80%–92% 的平均收益，候选推演事件为零。两组常规与 8 倍档的零开销结果与静态一致。87–89 组采用 3,584 token 上限与 SSD 计算降速减半的控制设定。84–86 组采用 6,656 token 上限与归档并发成本配置。

在成本已知的 90–95 窗，跨层回退与选择性检查的 864 个配对配置的零开销均值、P95 均相同。93–95 窗的仅 SSD 32 倍压力组，两个保护策略比共享直接估计平均少改善 53.06 ms。选择性检查推进了额外的 2,594 个预测事件。

在 96–98 窗，关闭并发降速并固定实际 SSD 时长，把所有策略所见的估计乘以 0.5、1 或 2。低估时，部分条件下收益消失。估计正确或偏高时，跨层检查在部分条件下保留了直接回退放弃的收益。每行基线都使用同一份估计。不能从不同误差下的相对收益直接推断绝对耗时变化。99–101 的 432 个新配对配置里，同层回退没有改变零开销均值和 P95。

三请求[穷举对照](evidence/cpu-oracle-grid.csv)补充了可解释的上限。固定相同候选，改变到达、SSD 搬运成本与预取预算后，`local-cost` 在 22/48 个构造条件中高于穷举最优，最大平均差距 8 ms。构造对照用于验证机制。

## 三个可复现的反例

- **共享候选漏选。** Trace A 77 窗中，请求 258 的 512-token 候选有 65.125 MiB 依赖已被前一个请求预留，增量搬运估计为零。旧压力条件错过了这次估计。固定其他边界、只改这一边界时，平均响应改善 165.78 ms。[逐请求证据](evidence/cpu-estimate-witness-77.json)
- **跨层尾部退化。** Coder 89 窗只改了一次 512→1,024 token，从 RAM 转到 SSD。均值快 1.78 ms，P95 慢 9.03 ms。固定两组边界并仅关闭 SSD 搬运造成的计算降速，P95 转为快 0.72 ms。两种跨层保护均挡住了这次改选。[逐请求证据](evidence/cpu-reuse-tail-witness-89.json)
- **成本估高后的同层误选。** Coder 96 窗在估计 SSD 耗时为实际两倍时，将一个不能提前预取但可以按需恢复的 3,072-token SSD 边界改成可提前预取的 512-token SSD 边界。只改这一步时窗口均值慢 361.03 ms，四次改选共同作用后均值慢 76.47 ms。同层回退挡住该反例，但留出验证没有额外收益。[逐请求证据](evidence/cpu-reuse-stale-witness-96.json)

统一建议是将共享直接估计作为低开销候选，跨层回退作为保守对照，继续用 `local-cost` 作默认基线。各条件的尾部、预测事件与计时数据见[复现与归档](cpu-policy-reproduce.md)。
