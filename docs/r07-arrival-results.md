# R07 到达条件验证：阶段结果

本页只归档到达分线，不是 R07 结项或跨模型验收。更广的模型与负载验证见[扩展结果](r07-extension-results.md)、[扩展设计](r07-entry-replay-generalization.md)和[反常点登记](archive/r07-process/r07-anomaly-register.md)。

**结论：在本轮单槽 CPU 模型和 Trace B 留出内，`entry-replay` 的平均响应泛化较强，没有发现分层层面的明显均值退化；但不具备逐请求无退化保证。** SSD 16× 下有可重复的逐请求额外等待，也有一个源窗的局部选点缺陷。保持现有主干；不建议仅凭这批结果在所有工况增加门控，或把均值接近最优当作尾部安全证据。

## 证据范围

按[研究设计](r07-entry-replay-generalization.md)和[留出前预登记](archive/r07-process/r07-preregistration.md)执行。主干选点、阈值、观察上限和执行器均未修改。先运行 60 个可精确穷举的短轨迹点和 42 个设计点；再运行 Trace B 450–461 的 12 个新源窗，每窗交叉 3 个 SSD 成本档、7 个到达变体，共 **252 配置、23,604 个请求实例**。变体间共享源请求，实例数不是独立样本数。计时采用 6 轮配对，共 1,512 轮，每轮 3 个策略，时长只在模拟器中注入。

所有 252 个留出点的离线搜索均找到可重放上界并认证为精确最优（最多消耗 655 个节点，预算 1,024）。`entry` 与 `entry-replay` 的零开销边界、完成序列在 252 点全部一致；其中 `entry-replay` 在 **237/252** 点达到离线最优。均值以配置等权；计时差值按源窗口聚类。精确离线最优的数值不是统计置信区间。

## 结果一：均值稳健，但要区分无可降空间与真正泛化

下表每行汇总该成本档的七个到达分层，给出分层均值的最小和最大值；“最坏逐请求”是六轮中的单次值。正的“节省”表示 `entry-replay` 优于 `local-cost`。

| SSD 倍率 | 零开销：拿到理论可省空间 | 零开销：仍距最优均值 | 计入开销：平均响应节省 | 计入开销：P95 节省 | 反复多等 >10 ms 的配置 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 1× | 无可降空间，84/84 点基线已最优 | 0 ms | 0.020–0.031 ms | 0.020–0.034 ms | 0/84 |
| 12× | 99.550–99.952% | 0.051–0.409 ms | 90.415–244.004 ms | 154.421–428.770 ms | 0/84 |
| 16× | 99.348–99.983% | 0.014–1.391 ms | 82.830–211.803 ms | 143.587–373.153 ms | 64/84，来自 10/12 源窗 |

- 12× 与 16× 的 **14/14 分层**有正的可省空间且通过预登记的均值判据；21 个分层的闭环均值与 P95 都没有越过退化预算。相对同规则的 `entry`，12×–16× 下合计的每配置 CPU 选点时间减少约 **0.87–1.11 ms**，不是 GPU 端到端测速。
- 到达干预确实改变了压力。例如 16× 打分时的平均最大可见队列由原样 **69.3** 变为密集 **80.8**、疏松 **51.9**，按相同平均到达率构造的较低负载配对由均匀 **16.0** 变为突发 **19.6**。这组同速的突发使 16× 的均值离线差增加 **0.336 ms**，但在 12× 反而减少 **0.358 ms**；原跨度的两间隔配对未改变离线差。不能据此说突发一定致退化。
- 16× 最大单配置零开销差 **16.693 ms**，是该配置可省空间的 **5.54%**。出现在源窗 460 的五个变体，仍只是**一个源窗**，未达到两个独立源窗的分层大缺口判据。不能用汇总结果掩盖该局部缺陷，也不能把五个变体当五次独立复现。

## 结果二：窗口和固定后继确实会漏选，尾部代价不是单纯计时噪声

- **可见窗口限制。** 16×、源窗 460 原样在同一决策快照中，四步试跑选 `512`；把观察范围扩到更多已到达请求（不改执行器预取窗口），改选 `1024`。只强制这一决策，后续继续用原算法，窗口平均响应下降 **16.693 ms**。同源窗 5 个到达变体呈现相同类型。这个信号是在线可见的，不需要预知未来。
- **后继联动限制。** 12×、源窗 458 原样在四步以及全可见的固定后继试跑中都选 `1024`；让最先两个有多个候选的已到达后继参与联合试跑，当前点翻到 `512`。单次强制改为 `512` 的闭环平均改善 **1.853 ms**。同源窗 5 个变体有该诊断信号。剩余 5 个有离线差的留出配置，首次偏离离线计划时的这些快照对照未定位原因；不强归因。15 个差异配置的首次分歧均进入试跑，四步穷举与原剪枝结果一致；未观察到粗筛或剪枝在这批首个分歧上误选，不是普遍正确性证明。
- **未来信息限制。** 短轨迹的最大离线差为 **8.571 ms**。在这类短轨迹中，只改变决策之后未到达请求的时刻、保持已见状态不变，可以让最优首步从 `1152` 翻到 `0`，而在线动作不变。这样的差距不能全部归因于算法；短轨迹反例也不是线上发生率。
- **逐请求尾部。** 16× 有 **64/84** 个配置出现同一请求在至少四轮多等 10 ms 以上，最坏 **12.245 ms**；65/84 在不计选点耗时时也出现过超过 10 ms 的个体退化。源窗 457 的密集例中，受影响请求自己以及更早序号请求的选点都没有变；将随后第一个改选点从 `1024` 强制还原到 `512`，该请求的 **12.062 ms** 零开销额外等待归零，但整窗平均响应相对原算法增加 **119.617 ms**。这是当前均值目标允许的跨请求代价，不能因为整体 P95 改善就把它视为噪声。16× 原样已有 9/12 窗反复超阈，较低负载的突发配对从均匀 9/12 增至 10/12；不能把整体尾部现象归因于突发。

**适用域：** 仅 Qwen3.5-4B、单槽、单搬运通道、128 MiB、split、Trace B 与所测到达变换。1× 只说明本批简单策略已经足够。共享强度、32×、跨轨迹、其他模型及真实 GPU 服务均未由本轮验证。后续在 R07 内先验证这些现象能否跨模型和独立源窗复现；个体保护需求单独记录，不据此修改冻结主干，也不直接扩大窗口或联合搜索后宣称净收益。
