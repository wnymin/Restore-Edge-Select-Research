# 离线搜索的双资源下界

在最宽的 12 个离线区间上，单纯把搜索上限从 32 增至 2,048 个节点，使平均区间宽度从 1,876.04 ms 降为 1,099.30 ms，但仍未认证精确最优。这轮检验能否利用计算槽与传输通道同时只能处理有限工作，进一步收紧下界。

## 工作量的分摊

一个缓存对象可能被多个请求共享。若把整份搬运时间分别算给每个请求，就可能高估实际必须完成的工作。这里先统计每个对象在所有合法候选中最多被多少个不同请求使用，把该对象的搬运时间按这个数量等分。某个完整计划选中的各份费用之和就不会超过真正需要的总搬运工作。当前已就绪、活跃可接管或已在传输的对象按免费处理，进一步放松约束。

对某个已固定或尚未决定的请求，记候选的续算为 $C$，分摊的缺失搬运为 $D$。给定 $0<\lambda<1$，取其合法候选中最小的 $\lambda C+(1-\lambda)D$。累加到任一请求时，得到完成这些请求所需的加权工作下界。因为一个计算槽和一个传输通道即使同时工作，每毫秒也至多完成一单位加权工作，这个累加量可以约束完成时刻。

实现使用 $\lambda=1/4,1/2,3/4$，与原有请求就绪和 FIFO 计算下界取较大值。原搜索默认路径保持原配置，新下界通过 `resource_floor=True` 显式启用。

## 对照结果

300 个可穷举的构造配置上，单节点下界均不超过精确最优，完成搜索后与穷举最优一致。12 个宽区间配置的结果如下，时间为这一组搜索在本机的总和。

| 2,048 节点对照 | 原下界 | 双资源下界 |
| --- | ---: | ---: |
| 平均区间宽度 | 1,099.30 ms | 1,096.74 ms |
| 总搜索时间 | 71.49 s | 167.08 s |
| 认证精确最优的配置 | 0 / 12 | 0 / 12 |

双资源约束略微提高了部分下界，但对象共享使费用分摊偏乐观，额外有理数运算显著增加了时间。在这一组配置中，原下界仍适合作为参照。结果保留区间，不能把未找到更好完整计划当成已认证最优。
