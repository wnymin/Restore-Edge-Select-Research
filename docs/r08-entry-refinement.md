# R08-CPU-04：`entry-refinement` 候选与公开自验

`entry-refinement` 是独立、默认关闭的、只改变首次入窗恢复边界的 CPU 模拟候选。启用时仍先取得冻结 `entry-replay` 的动作；无信号、预算不够、预测收益不足或尾部守门拦截时回退该动作。它不改变请求顺序、精确恢复依赖、缓存放置、预取窗口、搬运和释放规则，也不把回放中的后继动作写回执行器。禁用时不运行候选逻辑。

## 方法与消融

- 只有当前请求在计算中的前驱之后，且存在尚未就绪、能单独暂存的候选，并有其他可暂存的已到达请求或已占用的暂存额度，才试跑。该信号说明共享资源可能发生竞争，不保证动作有收益。
- 依次试跑三段：发现原粗筛提前返回时，穷举同四后继视野；再试至多 24 个已到达后继的串行基准延续；最后在这个范围内只放开最先两个带可暂存候选的后继。每阶段为当前动作使用相同分支集。首次通过收益和尾部条件就停止，只提交当前动作。
- 每个决定最多新增 40 次固定续演；阶段全部候选放不下就回退，不从部分枚举选胜者。每次回放的范围上界为当前请求与 24 个后继，另含仍在执行且已提交选择的前驱。预测门槛是每个参与对比的未完成请求平均节省大于 1 ms；这**不是**实时净收益证书。
- 尾部守门分别用匹配的联动续演和串行续演。在同快照中，如果同一请求在两种续演下都比冻结动作与 `local-cost` 串行参照慢超过 10 ms，则不提交该动作。未触发守门不保证实际整窗不退化；取舍与失配仍需完整闭环观察。

| 消融标签 | 去掉的内容 |
| --- | --- |
| `short-only` | 扩大视野与后继联动均关，仅触发同视野的粗筛复核与尾部守门。 |
| `without-short` | 略过同视野复核，保留扩视野、联动和尾部守门。 |
| `without-joint` | 不放开后继动作，其余不变。 |
| `without-guard` | 不做尾部守门，其余不变。不作为默认或替换候选。 |

候选只使用模拟器已经观测到的到达状态、依赖对象、就绪状态、容量和已知当前速率。模拟器回放入口拒绝超出已到达范围或不合法的候选。没有把轨迹编号、模型名、压力倍率、离线动作或未来到达用于触发。实验结论仅适用于固定顺序、已知平稳成本、单计算槽与串行搬运，不是产品服务的 TTFT、TPOT 或吞吐结果。

## 已核对的反例与开销

以下是同一批六轮配对的结果，耗时差取窗内配对中位数；负值表示比冻结 `entry-replay` 更快。这里的“零开销省”直接比较全窗均值并核对离线区间，不把强制动作诊断当算法成绩。

| 公开回归点 | 零开销均值节省 | 含开销均值差／P95 差 | 消融和尾部 |
| --- | ---: | ---: | --- |
| B481／4B／12×／176 MiB | 13.251 ms，闭合原缺口 | −13.777／−16.379 ms | 仅四后继不改善；去联动仍改善，说明扩已到达视野已足够。冻结策略重复超阈的请求从 71 个降为 0。 |
| B482／27B 载荷／16×／384 MiB | 252.670 ms，闭合原缺口 | −220.172／−368.550 ms | 去联动即丢失收益。两条策略仍有同一请求重复超阈，不能称为修复尾部。 |
| B470／仅改变续算／16× 与 27B 载荷／12× | 0／0 ms，均**未修复** | 均值 +2.871／+7.001 ms | 守门关掉时分别收回 5.079／4.733 ms；这是消融，不作为主候选，也不能据此宣称计入开销、其他窗或真实服务安全。 |
| B481／27B 载荷／16×／176→180 MiB | 两点均为 0 | 两点均未达到 1 ms 的绝对退化门槛 | 保留“能暂存不代表能靠改选提速”的负对照；只按原对照的标签解释，不外推容量阈值。 |
| B481／27B 载荷／16×／384 MiB 正对照 | 无新增离线差 | +1.730 ms 均值退化 | 原本已最优；即使动作不变，试跑成本也使绝对门槛未过。 |
| B481／27B 载荷／16×／512 MiB 尾部见证 | 没有改选 | +6.720 ms 均值退化 | 原均值—尾部取舍仍在；不把运行本候选当成消除个体等待。 |

已知 R08 的 11 个实质均值缺口都通过离线缺口口径（B481 7 个配置、B482 4 个；只有两个独立源窗），六轮均值中位数也均比冻结策略快。另有 `R07-A01` B457 回归点新增一名重复超阈请求。**这两组事实不能互相抵销。** 144 个设计点无零开销改选收益，其中 45 个含开销均值比冻结策略慢超过 1 ms，41 个属于原已认证最优／近最优工况；4 个配置新增重复超阈请求。即使不等待新留出，已有足够证据拒绝默认替换。

决策开销统计以每窗六轮中位数再跨窗汇总，不能解释成请求级生产分布。以设计点为例，候选选点 P50/P95 的跨窗中位数为 0.00165/8.120 ms；零开销下 57.6% 的多候选决策有试跑，所有试跑最终不改选。这里的“触发而未改选”是开销诊断，不等于对所有决策真值进行反事实检查后的误触发率。

## 完整历史矩阵：不通过非劣门槛

2026-11-24 完成全部 1,309 个配置的自验：72 个微用例、144 个设计点、25 个归档反例／对照，以及下面 1,068 个历史矩阵配置。四套用例的成员、六种计时顺序、合法动作、容量、额外回放上限和冻结策略序列已核对。零开销下，历史矩阵没有新造离线差的已认证最优点；失败主要在计入决策与实际执行影响之后。

| 历史矩阵 | 原已认证最优／近最优 | 含开销均值退化 >1 ms（原好工况） | 含开销 P95 退化 >1 ms（原好工况） | 新增重复超阈的配置 |
| --- | ---: | ---: | ---: | ---: |
| 代理／归档成本主矩阵（864 点） | 771 | 147 | 166 | 15 |
| 实测预填充与搬运参数（168 点） | 163 | 36 | 44 | 3 |
| 拆分成本对照（36 点） | 35 | 19 | 21 | 2 |
| 合计（1,068 点） | 969 | 202 | 231 | 20 |

“原好工况”包括已认证最优，以及可省空间为正且最差接近率至少 95% 的配置。按配对净节省留存率中位数计算，497 个原好配置低于 99%；原净节省为正才进入比例，接近零的分母使比例不稳定，因此不以它单独判退。均值、P95 列可能重叠，不相加。全历史矩阵仅 16 点的配对均值改善超过 1 ms，均在归档成本主矩阵；实测成本分线没有这种收益。这些是配置，不是独立流量样本。

- **最坏退化**：B482／27B 架构载荷／12×／384 MiB 原本已认证最优。候选零开销动作未改，但计入决策后的配对中位数为均值 **+51.670 ms**、窗内 P95 **+93.852 ms**。历史矩阵还有 20 个配置出现新的重复超 10 ms 个体损失；其中 B486／16 层／仅实测搬运成本／128 MiB 有 32 个新超阈请求。
- **决策开销**：历史矩阵候选决策 P50／P95 的跨窗中位数为 **0.00120／2.395 ms**，最大单次实测决策时间为 **53.660 ms**。相比冻结策略，六轮配对下每窗决策总耗时差的跨窗中位数为 **+30.249 ms**；这是决策总和，不是响应差，也不从已注入开销的响应里再减一次。历史零开销路径触发 9,167 次（占 17,578 次多候选决定的 **52.2%**），仅改选 21 次，**99.8%** 的触发不改选或被拒。额外回放的实测最大次数与上限见汇总；尚无可靠证据可以把试跑成本从回退路径排除。

**我方结论：不替换 `entry-replay`，也不宣称存在可部署的子域。** 历史回归的两类收益不足以抵销必要门槛失败；B470 守门未解、个体退化及独立盲验未覆盖的限制都保留。后续如果重做候选，优先验证能否在回放前用低成本证据排除无收益工况，不为已知窗口硬编码例外。

## 自验、复现和交接

候选参数在 [`configs/r08-entry-refinement.json`](../configs/r08-entry-refinement.json)，实现为 [`entry_refinement.py`](../src/restore_edge_select/entry_refinement.py) 与 [`simulator.py`](../src/restore_edge_select/simulator.py) 的 opt-in 接口。旧归档验证从固定 Git 树核对当时的模拟器文件哈希；当前默认策略另逐窗用实际动作与完成时刻的序列哈希对齐。旧归档文件本身不改。

从实验仓库根目录、准备好固定公开原始轨迹后执行。命令要求新输出路径，不覆盖旧归档：

```powershell
python -m scripts.validation.check_r08_refinement --reproduce --results outputs/r08-refinement-reproduce.jsonl.gz --out outputs/r08-refinement-summary.json
```

`all` 包含 72 个微用例、144 个原设计点、25 个归档反例或对照、完整 864 个修正后的 R08 历史主矩阵与 204 个实测成本／成本拆分点。它不是盲验：历史窗口在当前阶段全部属于已公开信息。实验脚本分别记录每个窗、每个请求的解、均值、P95、决策时间，以及预算、回退和额外回放计数。时间部分先预热，再用三策略的六种顺序逐一配对，以模拟器的实际均值差计入决策期间的阻塞（包括状态获取、试跑与失败回退）。不同成本倍率或计时轮不能当作独立源窗。原始 27B 不是 GPU 实测；实测成本矩阵也只测试把测量参数带回模拟器。
