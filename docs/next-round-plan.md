# R02 双人分工：固定容量下的后续状态判据

制定日期：2026-11-18。承接[动态因素评估](dynamic-factor-priority.md)和[统一报告第 5 节](dynamic-gpu-lookahead-report.md#research-next)。按现有资源安排：你负责本机 RTX 4060 的观测验证与报告整合，协作者负责 CPU 判据与复现。两条线可以独立开工、独立交付。[B1–B3](dynamic-cpu-completion.md)不重做，前轮 A 组材料作为已有证据复用。

## 研究问题与范围

**固定每次比较的容量、放置、可见请求和后继边界后，两个候选经历不同准入历史，哪些状态必须保留，才可复用后续推演并保持原选点？** 附带两个验收问题：省下的求值是否抵得过判定成本？会影响判定的活动状态能否在 GPU 选点前观测？

- 主实验用 Qwen3.5-4B 和原 CPU 执行器，先做 3–4 个已见请求、开始计算时释放、固定后继边界的快照。容量可跨配对扫描，但同一候选对内不变；保持固定 FIFO、单计算槽、串行不可抢占传输、首次入窗选一次及原同刻规则。首个目标是覆盖**释放后重试与共享或在途状态相遇**的子域，不做任意请求数的最小充分状态证明。
- 单次参照是同快照、同已见请求集、同成本和同固定后继计划的完整求值。主目标是平均模拟响应；P95 和最大单请求退化另列。精确简化须保留获胜动作、原平局和选中方案的逐请求完成向量。可在单次通过后做相同首次入窗规则的闭环回放，但不把固定后继证明说成全轨迹最优或误差下的多步安全。
- P0 对象身份、预留与重试、队列和事件规则不可被近似代替；P1 余量与成本差用于判断后续工作能否抵消。P2 只做针对性观测；P3 仅作为 GPU 粗代理对照。暂不研究容量未知、定时释放的一般解、第二通道、连续批处理、未来到达预测或近似恢复。

**`R02-CPU-01`。** 复用 [§3.4 的状态等价判据](dynamic-gpu-lookahead-report.md)、[释放重试](evidence/dynamic-lookahead-dynamic-release-7884.json)和[同汇总不同顺序](evidence/dynamic-lookahead-transfer-order-7820.json)。以原执行器为参照，对比完整对象状态、保留未来相关对象及逐对象搬运前缀的表示、仅汇总字节与成本的表示。交付有适用条件的充分判据或最小反例，以及脚本、冻结输入和逐请求核对表。保真后才测命中率、回退原因及净开销，不另写执行器。

**`R02-GPU-01`。** 复用[多对象暂存 GPU 夹具](dynamic-gpu-joint-staging.md)，对照紧额度短窗口、同额度长窗口与同短窗口宽额度，每组交错浅／深。先用归档冻结方案，再以新种子复测。交付观测字段、时间基准、采集方法和开销，以及留出的配对差、误判、拒判、覆盖和缺失项。对照独占成本、粗活动标志与可见状态区间；只有就绪延迟可读时，不声称验证了活动残余。

**`R02-INT-01`。** 按案例 ID 交换并复算精简证据，分别登记 CPU 保证、GPU 机制及未覆盖工况。交付验收摘要和证据入口，明确现有策略是否保留；新 GPU 实测缺失时据实列出，不阻塞 CPU 验收。

**CPU 对照怎么做。** 在同一执行阶段、同一剩余请求及固定后继计划下比较续算状态。若允许时间平移，只在子域没有未来外部事件且执行规则时间平移不变时使用；候选已完成请求的分数差单独保留，不能并入共同后续抵消。配对至少覆盖容量刚低于、等于和高于新增预留需求，释放与完成／就绪同刻及其两侧，共享 KV／共享检查点、有无初始在途、预取无法通过但可队首按需恢复。包含无竞争阴性对照，以及容量 × 余量、共享 × 释放各一组。某种状态不能正确表示时给出冲突的两条轨迹或明确排除条件。

**GPU 对照怎么做。** 主要核对“等准入不一定等暴露等待”：分别报告释放、就绪、消费窗口和目标／同行完成差。每组输出所有有效配对及噪声近似平局，不硬判胜负；缺失或通知未到不能写成“仍在活动”。若采用时间区间，冻结误差定义和共同时间基准；报告覆盖的是哪一个量，不把经验极值当确定保证。同一设备合成夹具的完成时刻和不等于真实服务 TTFT。GPU 不可用时用归档完成可观测性审计，新增硬件覆盖标为未验收，不阻塞 CPU。

## 验收与停止条件

1. **先验保真。** 声称适用的子域内不接受动作、平局或逐请求完成向量差异。条件不满足时回退同一可见窗口的完整求值，不能为了省时直接改回 `local-cost` 并继续声称动作等价。常规无可降空间用 `local-cost` 作实际策略基线；受压均值用 `entry` 作策略对照，完整求值用于核对正确性，两者不混作同一个参照。
2. **再验净成本。** 同机重复计时，比较完整求值与状态提取＋构键／判定＋剩余求值＋回退；报告中位数、P95、回退率和闭环净收益，同时报告零开销平均响应、P95、最大单请求退化。若只少算事件、净耗时无稳定下降，不替换现有策略。若保真失败，缩小适用域或以最小反例结项，不用平均损失掩盖错误。
3. **单列 GPU 证据边界。** 有留出配对且观测覆盖支持时，仅提升相应量的证据等级；无法区分状态或区间跨平局时记为不确定，不强制改选。不以 GPU 有正收益为结项条件，不承诺全局最优、真实服务加速或多步保护；如另报离线最优，未认证时给区间。

提交前从实验仓库根目录运行 `python scripts/check_fixture.py`，并在交付中提供新实验的配置版本、复现命令、冻结清单和失败案例。本轮至少产出一项可复现的 CPU 充分条件或反例，以及一份 GPU 可观测性结论或证据缺口记录；任一结果都可以否定继续加复杂度的必要性。
