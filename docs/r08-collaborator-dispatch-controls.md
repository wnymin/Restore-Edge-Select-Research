# R08 SSD 预取普遍延后的跨窗口负对照

复放 R08 已公开的 12 个修正后源窗，配置统一为 27B 架构载荷、16× 搬运成本和 512 MiB。每臂保持冻结策略的恢复边界。固定 960 ms 与相对 80% 两臂适用于所有 SSD 预取，从前驱到队首起算。相对臂按前驱选定边界对应的模型续算成本乘 0.8。另做一个只对基线与冻结策略分歧位置施加 80% 延后的诊断对照。该对照使用完整基线序列提供位置。

| 规则 | 平均响应改善窗数 | 全窗额外等待均不超过 10 ms 的窗数 | 12 窗等权平均收益（ms） | 最大单请求损失（ms） |
| --- | ---: | ---: | ---: | ---: |
| 冻结策略 | 10 | 3 | +585.820 | 36.105 |
| 全量 960 ms | 0 | 1 | −638.578 | 3976.558 |
| 全量 80% | 0 | 1 | −556.685 | 3165.075 |
| 只延后选点分歧位置，80% | 1 | 2 | −319.811 | 1608.533 |

两条全量规则都在 11 个窗口降低基线平均响应表现，在 Coder 99 持平。只延后分歧位置也仅在原 B481 有正均值收益，该窗最坏额外等待仍达 10.163 ms。这里排除了把 B481 单笔搬运的回测结果直接推广到所有 SSD 预取的做法，也表明选点分歧本身不足以作为触发。延后会留下更多需求读等待，是否值得做需要同时估计前驱可避免的重叠损失与后继将新增的等待。

所有窗口的原选点、精确均值与归档匹配。空干预复现完整搬运日志，实验检查暂存容量。数据来自已公开窗口和模拟器，计算开销按零计。运行以下命令输出逐窗 JSONL。

```powershell
python -m scripts.validation.audit_r08_dispatch_controls
```
