# GPU A3：实时选点与共同初始缓存状态

接续 [A2 跨工作量留出](dynamic-gpu-a2-signals.md)。验证冻结的同行待完成规则实际分派请求时的效果，以及与固定深恢复相比是否减少不必要的恢复。仅在优化两项响应和时启动动态规则；目标响应和共同完工仍独立评价。

RTX 4060、Vulkan、Qwen3.5-4B Q4_K_M、llama.cpp b10923，双槽连续批处理。目标总输入 2,560 token。固定浅驻留、固定深冷恢复、动态选择均从目标槽内已经驻留 1,024 token 开始；深选择用同一目标槽原位恢复至 1,152 token。同行已有 512 token 驻留。采用新种子 7313，五个提示词块内随机交错 12 个组合：无同行，及 1,792/75、2,816/425、3,328/1,450 三个同行总长／提前时差工况，各交叉三条策略；预热块排除。深路径使用不同的未读文件别名并核对状态文件和卷读量。

动态分支在目标选点时查看同行客户端 Future 是否已完成，直接用 [A2 冻结规则](evidence/dynamic-gpu-a2-rules.json)给出的两类收益符号分派；不读后续阶段。校准得到的独占成本策略在这两个边界上等价于固定浅驻留，合用一个基线。计时从选点前到目标返回一个 token，包含实际判定、恢复及续算；另以同一单调时钟量选点快照和分支开销。同行响应从其自己提交计，共同完工以同行提交为起点（无同行用目标起点）。配对参照是各固定路径在独立重复中的实际结果。

20 个配对块、60 条有效测量中，所有块的三条策略均返回同一约束首 token，选点前同行标志也一致。下表相对固定浅驻留，正值为更快：

| 策略 | 实际深恢复 | 目标收益 ms | 同行收益 ms | 响应和收益 ms | 共同完工收益 ms | 最大目标损失 ms |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| 固定深恢复 | 20/20 | −9.50 | +90.47 | +80.98 | −9.43 | 152.88 |
| 冻结动态规则 | 10/20 | −5.77 | +82.83 | +77.05 | −5.70 | 85.04 |

**动态规则减少了恢复次数，保留了多数响应和收益；对固定深恢复没有测出更低的响应和。** 标志为真的两个工况都改选，响应和分别改善 164.86、172.72 ms，各 5/5。无同行和同行已完成时都保留浅驻留。已完成工况中，同行在目标选点前已经结束，后续策略不能因果改变其耗时；该工况的同行响应均值差属于独立重复波动。动态规则的总响应和比固定深恢复多 3.92 ms，目标和共同完工约少 3.7 ms；两条策略在同样执行深恢复的一个工况，响应和均值仍差约 27 ms，不能把总体的小差值认定为稳定策略优势。

动态选点耗时中位数 **13.85 µs**、最大 **24.40 µs**，含读取客户端状态和分支，不含任何引擎遥测 RPC。低开销本身没有消除目标代价：相对浅驻留，目标仍平均慢 5.77 ms，整组也晚 5.70 ms。相对每块固定浅/深两次实测中较快的参照，动态的响应和平均晚 21.78 ms；该参照是带重复噪声的实测最小值，不是全轨迹离线最优。

现场选择与 A2 结论一致：若明确只优化响应和，可用待完成标志减少不必要的深恢复，并接受部分目标变慢；目标延迟和共同完工优先时仍推荐浅驻留。下一项针对真实恢复关键路径，做[同槽提前恢复](dynamic-gpu-early-restore-plan.md)，检验能否减少目标和整组等待，而不是换目标函数。
